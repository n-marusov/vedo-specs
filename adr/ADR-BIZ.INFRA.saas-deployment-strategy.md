# ADR-BIZ.INFRA.saas-deployment-strategy

**Дата:** 2025-03-15  
**Статус:** Принято

## Контекст

VEDO Core — многопользовательский редактор онтологий. Целевая аудитория включает стартапы (чувствительны к цене), крупные корпорации (требуют контроля данных), финтех/банки (регуляторика 152-ФЗ), госсектор (сертификация ФСТЭК).

MVP должен выйти быстро, ресурсы DevOps ограничены (3 инженера).

## Требование-источник
- [deployment-model.md](requirements/REQ-CON.INFRA.deployment-model.md)
- [deployment-tiers-reference-architecture.md](requirements/REQ-CON.INFRA.deployment-tiers.md)

## Решение

Принять поэтапную стратегию развёртывания: MVP — SaaS мультитенант в облаке (Yandex Cloud / AWS), Enterprise P2 — on-premise через Helm-чарты для Kubernetes, Scale P3 — приватное облако и гибридная модель.

SaaS-first для MVP обеспечивает быстрый выход на рынок при ограниченных DevOps-ресурсах (3 инженера). On-premise добавляется позже без переписывания архитектуры, что позволяет не пропустить корпоративные тендеры. Единая кодовая база для всех моделей снижает стоимость поддержки и исключает расхождение поведения.

Начать с облачного мультитенантного SaaS. Архитектуру проектировать с учётом будущего on-premise: Helm-чарты, конфигурируемые профили развёртывания, отсутствие привязки к cloud-only сервисам.

**Уточнение по deployment tiers (v1.0):**
- Коммерческие профили SaaS фиксируются через `Standard` (99.9%), `High` (99.95%) и `Premium` (99.99%).
- `Standard` — базовый профиль MVP/Community; `High` — целевой профиль production для бизнес-клиентов; `Premium` — профиль enterprise-критичности с multi-region active-standby.
- Поддерживаемый путь апгрейда: `Standard -> High -> Premium`; прямой `Standard -> Premium` допускается как миграционный проект с плановым простоем.
- Даунгрейд tier не поддерживается в рамках штатного процесса эксплуатации.

## Рассмотренные альтернативы

| Альтернатива | Рассмотрена для | Причина отклонения |
|--------------|-----------------|-------------------|
| Только SaaS | MVP | Корпоративные клиенты не будут покупать |
| Только on-premise | MVP | Затянет релиз на 6+ месяцев |
| 4 модели сразу | MVP | Слишком дорого для 3 DevOps |

## Последствия

- **Положительные последствия:** Быстрый выход на рынок, единая кодовая база, низкий порог входа
- **Отрицательные последствия:** On-premise отложен, Enterprise-тендеры могут быть пропущены
- **Смягчение:** Архитектура позволяет добавить on-premise без переписывания
