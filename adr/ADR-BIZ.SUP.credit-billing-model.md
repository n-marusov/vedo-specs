# ADR-BIZ.SUP.credit-billing-model — Модель биллинга AI Credits

**Статус:** ПРЕДЛОЖЕНО
**Дата:** 2026-07-15

## Контекст

VEDO Hub внедряет AI Assistant (M2) с функциями:
- NL→OWL генерация (F14)
- NL-режим запросов (F10.1, F10.2)
- AI-подсказки по связям (F14.3)

Эти функции используют LLM-провайдеров с разными тарифами:

| Провайдер | Модель | Цена input (за 1M) | Цена output (за 1M) |
|-----------|--------|-------------------|---------------------|
| OpenAI | GPT-4o | $5.00 | $15.00 |
| OpenAI | GPT-4 | $30.00 | $60.00 |
| OpenAI | GPT-4o-mini | $0.15 | $0.60 |
| Anthropic | Claude 3 Opus | $15.00 | $75.00 |
| Anthropic | Claude 3 Sonnet | $3.00 | $15.00 |
| Anthropic | Claude 3 Haiku | $0.25 | $1.25 |
| Google | Gemini 1.5 Pro | $2.50 | $10.00 |
| Google | Gemini 1.5 Flash | $0.075 | $0.30 |
| Local (on-premise) | Llama 3 / Qwen | $0 | $0 |

**Проблемы:**

1. **Непредсказуемые счета:** Без лимитов пользователи могут получить неожиданные счета (аналогично OpenAI cost overruns)
2. **Разные тарифы:** Пользователи не понимают, сколько стоит запрос к разным моделям
3. **Администрирование:** Организациям нужен контроль над расходами на AI
4. **Прозрачность:** Пользователи должны видеть стоимость до выполнения запроса
5. **Гибкость:** Разные организации имеют разные бюджеты на AI

**Требуется** единая модель биллинга, которая:
1. Разделяет платформу и AI Assistant (модульность)
2. Обеспечивает предсказуемость расходов через AI Credits
3. Учитывает разных LLM-провайдеров и их тарифы
4. Даёт администратору контроль над бюджетом
5. Предоставляет прозрачность пользователям

## Решение

Внедрить **AI Credits Billing System** — компонент для управления биллингом AI Assistant, состоящий из следующих элементов:

### 1. AI Credits — универсальная валюта

**1 Credit = $1 USD**

AI Credits — это универсальная валюта VEDO AI Assistant. Все AI-запросы расходуют Credits на основе фактического использования токенов и тарифов выбранного провайдера.

```
Расход (в Credits) = input_tokens × цена_input(провайдер, модель) 
                    + output_tokens × цена_output(провайдер, модель)
```

### 2. Включённые Credits по тарифным планам

| План платформы | Включённые AI Credits |
|:---|:---|
| **Community** | $0 (AI-функции недоступны для приватных) |
| **Pro** | $10/мес |
| **Team** | $19/мес |
| **Enterprise** | $39/мес (или кастомно) |

### 3. Общий пул Credits для организации

Все Credits организации находятся в общем пуле. Администратор может:
- Пополнять пул (от $10)
- Устанавливать лимиты на пользователей и группы
- Включить автоматическое пополнение

### 4. Модель превышения лимита

| Сценарий | Поведение |
|---|---|
| **Credits > 0** | AI-функции работают, Credits списываются |
| **Credits = 0** | AI-функции блокируются до пополнения |
| **Автопополнение** | При балансе < 20% автоматически пополняется |

### 5. Тарифы провайдеров — конфигурируемые

Администратор может настраивать тарифы провайдеров через конфигурацию. Система поддерживает автоматическую синхронизацию с API провайдеров.

### 6. Прозрачность для пользователей

Перед выполнением AI-запроса пользователь видит ориентировочную стоимость в Credits.

**Поток запроса AI-функции:**

```
1. Пользователь отправляет NL-запрос (NL→OWL / NL-запрос)
2. API Gateway получает запрос с ontology_id
3. LLM Policy Router определяет провайдера и модель
4. AI Credits Billing System:
   a. Проверяет баланс Credits организации
   b. Рассчитывает ориентировочную стоимость запроса
   c. Если баланс > 0: продолжает выполнение
   d. Если баланс ≤ 0: возвращает ошибку "Insufficient Credits"
5. LLM Adapter выполняет запрос к провайдеру
6. Cost Calculator рассчитывает фактическую стоимость
7. Balance Manager списывает Credits с баланса организации
8. Usage Dashboard обновляется
9. Ответ возвращается пользователю
```

**Поток пополнения Credits:**

```
1. Администратор заходит в настройки организации
2. Выбирает "Пополнить AI Credits"
3. Вводит сумму (от $10)
4. Подтверждает платеж (через платежную систему)
5. Balance Manager зачисляет Credits в общий пул
6. Транзакция логируется в audit
7. Если AI-функции были заблокированы — разблокируются
```

**Структура данных:**

**Таблица `tenant_credits`:**
```sql
CREATE TABLE tenant_credits (
    tenant_id UUID PRIMARY KEY,
    balance DECIMAL(10, 2) NOT NULL DEFAULT 0,
    included_credits DECIMAL(10, 2) NOT NULL,
    last_month_usage DECIMAL(10, 2),
    updated_at TIMESTAMP,
    auto_top_up_enabled BOOLEAN DEFAULT FALSE,
    auto_top_up_threshold DECIMAL(10, 2),
    auto_top_up_amount DECIMAL(10, 2)
);
```

**Таблица `credit_transactions`:**
```sql
CREATE TABLE credit_transactions (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    amount DECIMAL(10, 2) NOT NULL,
    type VARCHAR(20) NOT NULL, -- 'top_up', 'consumption', 'included_credits'
    provider VARCHAR(50),
    model VARCHAR(50),
    input_tokens INTEGER,
    output_tokens INTEGER,
    request_id UUID,
    user_id UUID,
    timestamp TIMESTAMP NOT NULL,
    description TEXT
);
```

**Таблица `provider_rates`:**
```sql
CREATE TABLE provider_rates (
    id UUID PRIMARY KEY,
    provider VARCHAR(50) NOT NULL,
    model VARCHAR(50) NOT NULL,
    input_price_per_1m DECIMAL(10, 6) NOT NULL,
    output_price_per_1m DECIMAL(10, 6) NOT NULL,
    cache_discount DECIMAL(3, 2) DEFAULT 0.5,
    updated_at TIMESTAMP,
    source VARCHAR(20) -- 'manual' or 'api_sync'
);
```

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Фиксированная абонентская плата за AI | Непредсказуемость затрат и несправедливость для пользователей с разным уровнем использования |
| Hard-limit без возможности доплаты | Pre-paid модель с доплатой даёт лучший UX — блокировка без восстановления ухудшает опыт |
| Постоплата (счёт в конце месяца) | Риск неожиданных больших счетов (OpenAI cost overruns) |
| Единый тариф для всех моделей | Разные тарифы провайдеров: GPT-4 vs GPT-4o-mini имеют разницу в 200 раз |
| Кэширование токенов без скидки | Скидка 50% по аналогии с GitHub Copilot — справедливое ценообразование |

## Последствия

**Положительные последствия:**

1. **Предсказуемость:** Пользователи видят стоимость до выполнения запроса.
2. **Контроль:** Администратор может устанавливать лимиты и пополнять баланс.
3. **Гибкость:** Разные модели с разными тарифами — пользователь выбирает баланс «качество/цена».
4. **Прозрачность:** Дашборд показывает расход по пользователям, провайдерам, моделям.
5. **Модульность:** Платформа и AI Assistant разделены — можно использовать платформу без AI.
6. **Масштабируемость:** Общий пул Credits для организации упрощает администрирование.
7. **Интеграция:** Поддержка нескольких провайдеров с разными тарифами.

**Отрицательные последствия:**

1. **Сложность:** Дополнительный компонент биллинга требует разработки и поддержки.
2. **Задержка:** Каждый AI-запрос требует проверки баланса (дополнительный hop).
3. **Фрагментация:** Разные провайдеры имеют разные API для получения usage.
4. **Зависимость:** При недоступности биллинговой системы AI-функции недоступны.
5. **Когнитивная нагрузка:** Пользователи должны понимать стоимость разных моделей.

**Меры снижения рисков:**

1. **Кэширование:** Кэшировать баланс организации (TTL 60 сек) для снижения задержки.
2. **Плавная деградация:** При недоступности биллинговой системы — использовать кэшированный баланс.
3. **Документация:** Подробное руководство по стоимости моделей.
4. **Уведомления:** Предупреждения при низком балансе для предотвращения блокировки.
5. **Мониторинг:** Дашборд здоровья биллинговой системы.

**Риски:**

1. **Неактуальные тарифы:** Если тарифы провайдера изменились, а система не обновилась — неверный расчёт.
   - **Смягчение:** Автоматическая синхронизация ежедневно + ручное обновление.
2. **Ошибочное списание:** Если система неверно рассчитала стоимость запроса.
   - **Смягчение:** Аудит всех транзакций, возможность ручной корректировки.
3. **Злоупотребление:** Пользователи могут намеренно генерировать дорогие запросы.
   - **Смягчение:** Лимиты на пользователей, уведомления администратора.
4. **Local LLM:** Для on-premise local LLM стоимость = $0, но это может обесценить Credits.
   - **Смягчение:** Local LLM доступна только в on-premise, где биллинг не применяется.
