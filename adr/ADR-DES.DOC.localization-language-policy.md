# ADR-DES.DOC.localization-language-policy

**Дата:** 2026-05-12  
**Статус:** Принято

## Контекст

VEDO Core ведётся русскоязычной командой и ориентирован на клиентов, для которых русскоязычные артефакты, документация, runbooks и материалы для заказчиков являются базовым требованием. Одновременно пользовательский интерфейс должен поддерживать многоязычность, чтобы продукт мог поставляться SaaS, on-premise и корпоративным клиентам в разных юрисдикциях.

## Требование-источник
- [localization-language-policy.md](requirements/REQ-NFR.DOC.localization-language-policy.md)

## Решение

Принять языковую политику: human-артефакты, документация, runbooks и материалы для заказчиков — на русском; UI — с i18n для многоязычных поставок; технические идентификаторы, API, error codes — на английском для точности и совместимости.

Русский язык по умолчанию соответствует языковой среде команды и заказчиков, а i18n-архитектура UI позволяет поставлять продукт корпоративным клиентам в разных юрисдикциях без переписывания компонентов; разделение контента и кода исключает конфликт между точностью технических терминов и доступностью пользовательского интерфейса.

UI-строки вынести в файлы переводов; русский обязателен для MVP, английский — как второй язык или запасной вариант; переключение языка не сбрасывает контекст (онтологию, ветку, фильтры, выбранный объект).

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Документация на английском по умолчанию | Не соответствует текущей пользовательской и заказческой среде проекта |
| Только русский UI без i18n | Ограничивает корпоративные и международные поставки |
| Переводить технические identifiers/API/code | Ломает точность, совместимость и трассируемость |

## Последствия

**Положительные последствия:**
- Human layer становится понятным для основной команды и заказчиков.
- UI готовится к многоязычным поставкам без переписывания компонентов.
- Локализация становится архитектурным требованием, а не задачей позднего этапа.

**Отрицательные последствия:**
- Нужно поддерживать переводческие ресурсы и правила исключений.
- Code traceability warnings возможны до реализации UI/i18n markers.

**Меры снижения рисков:**
- Зафиксировать исключения для технических терминов в `constraints.localization.global`.
- Проверять пользовательские строки через UI review и i18n tests.
- Не локализовать API identifiers, protocol names и code blocks.
