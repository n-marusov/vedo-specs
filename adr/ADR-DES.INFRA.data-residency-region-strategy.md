# ADR-DES.INFRA.data-residency-region-strategy

**Дата:** 2026-05-10  
**Статус:** Принято

## Контекст

VEDO Core должен поддерживать клиентов в разных юрисдикциях: РФ, ЕС, США и потенциально другие регионы. Ограничения по географии развёртывания связаны не с архитектурой кода, а с требованиями data residency, 152-ФЗ, GDPR, HIPAA, SOC 2 и политиками заказчика.

- [deployment-geography.md](requirements/REQ-CON.INFRA.deployment-geography.md)
- [deployment-tiers-reference-architecture.md](requirements/REQ-CON.INFRA.deployment-tiers.md)

## Решение

Принять стратегию «один код, разные регионы» — выбор региона является конфигурацией развёртывания, а не fork продукта.

Один код остаётся переносимым между регионами без расхождения поведения и дополнительной стоимости разработки. РФ развёртывание покрывает MVP и 152-ФЗ, а ЕС и США добавляются без архитектурного форка. Запрет cross-region sync ПДн и логов гарантирует соблюдение GDPR, 152-ФЗ и data residency заказчика.

Хранить region, data_residency и compliance flags как конфигурацию развёртывания. Для РФ рекомендовать Yandex Cloud, для ЕС — AWS eu-central-1, для США — AWS us-east-1. Явно запрещать синхронизацию ПДн и логов между регионами; обезличенные TBox модели могут синхронизироваться по согласованию.

**Уточнение по deployment tiers (v1.0):**
- `Standard` и `High` размещаются в одном регионе (single-region), различаясь только уровнем отказоустойчивости внутри региона.
- `Premium` использует multi-region active-standby, но соблюдает residency: ПДн и аудиторские логи не выходят за разрешённый юридический периметр.
- Cross-region репликация разрешается только для данных и контуров, явно допустимых политикой резидентности и договором с заказчиком.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Один глобальный SaaS-регион | Не покрывает 152-ФЗ и GDPR data residency |
| Отдельные code forks под каждый регион | Увеличивает стоимость разработки и риск расхождения поведения |
| Свободная трансграничная синхронизация всех данных | Нарушает GDPR, 152-ФЗ и требования резиденции данных заказчика |
| Поддерживать только РФ на MVP и не планировать ЕС/США | Ограничивает корпоративный и международный рынок |
| Поддерживать любой новый регион без legal review | Риск нарушения локального законодательства |

## Последствия

**Положительные последствия:**
- Один код остаётся переносимым между регионами.
- РФ развёртывание покрывает MVP и российские требования data residency.
- ЕС и США могут быть добавлены без архитектурного форка.
- Cross-region sync rules снижают риск нарушения privacy laws.
- Новый регион имеет понятный процесс введения в курс дела до 6 недель.

**Отрицательные последствия:**
- Потребуются region-specific configuration profiles.
- Необходимо поддерживать разные cloud provider integrations и KMS.
- Мультирегиональное развёртывание не может свободно синхронизировать ПДн и логи.
- Для США корпоративным клиентам может потребоваться SOC 2 Type II, что добавляет стоимость.

**Меры снижения рисков:**
- Хранить region, data_residency и compliance flags как конфигурацию развёртывания.
- Поддерживать готовые конфигурации для Yandex Cloud РФ, AWS Frankfurt EU и AWS us-east-1 USA.
- Для каждого нового региона выполнять legal review, provider selection, configuration, testing и documentation.
- Явно запрещать cross-region sync ПДн и логов.
- Разрешать только обезличенную TBox синхронизацию по согласованию.
