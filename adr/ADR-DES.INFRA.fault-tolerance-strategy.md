# ADR-DES.INFRA.fault-tolerance-strategy

**Дата:** 2025-03-15  
**Статус:** Принято

## Контекст

VEDO Core — микросервисная архитектура. Отказ любого сервиса не должен приводить к полной недоступности. Необходим graceful degradation.

## Требование-источник
- [fault-scenarios.md](requirements/REQ-NFR.INFRA.fault-scenarios.md)

## Решение

Принять матрицу отказов сервисов с режимами деградации (read-only для Ontology Service, no commits для Versioning Service) и политику Circuit Breaker с фиксированными порогами failure_threshold и timeout.

Graceful degradation позволяет пользователям продолжать работу при частичных отказах, а не получать HTTP 503. Circuit breaker предотвращает каскадные отказы, изолируя проблемные сервисы. Emergency kill switch через `vedo-cli emergency readonly` с целевым временем срабатывания ≤ 60 секунд даёт оператору экстренный контроль без физического отключения инфраструктуры.

Настроить circuit breaker для Versioning Service (3, 60s), Ontology Service (3, 30s). В UI реализовать отображение текущего режима деградации. Read-only mode активировать через `vedo-cli emergency readonly`; физическое отключение оставить как L3 запасной вариант.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|---------------------|
| Всегда HTTP 503 | Пользователи не могут работать |
| Без circuit breaker | Cascading failures |
| Скрывать ошибки | Потеря доверия |

## Последствия

- **Положительные последствия:** Пользователи продолжают работу при частичных отказах, circuit breaker предотвращает каскадные отказы
- **Отрицательные последствия:** UI-логика для режимов деградации, тестирование сценариев отказа сложнее
