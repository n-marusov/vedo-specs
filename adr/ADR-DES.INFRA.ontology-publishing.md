# ADR-DES.INFRA.ontology-publishing

**Дата:** 2026-05-13
**Статус:** Принято

## Контекст

VEDO Core позволяет инженерам знаний работать с онтологиями внутри организации. Однако возникает потребность делиться опубликованными онтологиями с внешними партнёрами и клиентами без создания аккаунта и раскрытия внутренних данных.

Требования к публикации:
- Read-only просмотр опубликованных онтологий без авторизации
- 2D/3D навигация по структуре онтологии
- Полнотекстовый поиск по элементам
- Интеграция с внешними системами НЕ планируется
- Файловый экспорт НЕ планируется

## Требование-источник
- [ontology-publishing.md](requirements/REQ-CON.STACK.ontology-publishing.md)

## Решение

Ввести VEDO Publisher Service и отдельный read-only инстанс Neo4j для публичных снэпшотов онтологий.

Изолированная архитектура гарантирует, что внешние пользователи видят только опубликованные данные без доступа к рабочей онтологии, служебным блокировкам и комментариям; Public Browse API с allowlisted endpoints (metadata, node details, graph neighborhood, full-text search) и rate limiting защищает публичный периметр, а выделенный Publisher Service обеспечивает асинхронное создание снэпшотов без нагрузки на production-кластер.

Publisher Service создаёт снэпшот и импортирует данные в изолированный read-only Neo4j; Browse UI обращается только к Public Browse API; публичный Neo4j не содержит служебных данных, не доступен напрямую из браузера и не принимает запросы из внешней сети.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Использовать основной Neo4j с read-only доступом | Раскрывает структуру организации, блокировки, комментарии |
| Дать Browse UI прямой доступ к Public Neo4j | Браузер не должен знать credentials/протокол БД и не должен выполнять произвольные запросы |
| Файловый экспорт (Turtle/RDF/XML) | Не запрошено пользователями, усложняет архитектуру |
| SPARQL endpoint для внешних систем | Не планируется интеграция с внешними системами |
| CDN/S3 для хранения файлов | Не планируется файловый экспорт |

## Последствия

**Положительные последствия:**
- Чёткое разделение между internal editing и external consumption
- Внешние пользователи видят только опубликованные данные без доступа к рабочей онтологии
- Browse UI позволяет партнёрам просматривать онтологию без создания аккаунта
- Отдельный read-only Neo4j гарантирует изоляцию данных, а Public Browse API ограничивает поверхность чтения

**Отрицательные последствия:**
- Новый сервис и отдельный инстанс Neo4j добавляют operational complexity
- Public Browse API становится публичным периметром и требует security hardening
- Snapshot creation может быть ресурсоёмким для крупных онтологий (асинхронное выполнение смягчает)

**Меры снижения рисков:**
- Snapshot создаётся асинхронно через background job с уведомлением
- Публичный Neo4j полностью изолирован и не имеет служебных данных
- Public Browse API использует отдельные read-only credentials, allowlisted queries, pagination, depth limits и rate limiting
