# ADR-DES.INTEGRATION.mcp-server-query-adoption

**Дата:** 2026-05-24  
**Статус:** ПРИНЯТО

## Контекст

Современные AI-ассистенты (Claude Desktop, Cursor, ChatGPT) поддерживают Model Context Protocol (MCP) для интеграции с внешними инструментами. Пользователи VEDO Core хотят задавать вопросы о своей онтологии на естественном языке через любимый AI-клиент, не открывая VEDO GUI.

Без MCP-сервера каждый внешний LLM-клиент должен был бы самостоятельно знать SPARQL/CYPHER, структуру онтологии и адрес endpoint'ов VEDO, что создаёт высокий порог интеграции.

## Требование-источник
- [vision.md](vision.md) — F10.3

## Решение

VEDO предоставляет MCP-сервер, реализующий Model Context Protocol, с инструментами для запросов к графу знаний.

MCP-сервер публикует три инструмента:
- `query-sparql` — принимает NL-запрос, преобразует его в SPARQL, выполняет SELECT/ASK, возвращает результат
- `query-cypher` — принимает NL-запрос, преобразует его в CYPHER, выполняет MATCH/RETURN, возвращает результат
- `introspect-ontology` — возвращает схему текущей онтологии (классы, свойства, метки узлов, типы связей) для контекста LLM

LLM-клиент (Claude Desktop, Cursor и др.) через MCP вызывает эти инструменты; MCP-сервер обрабатывает NL-запрос на стороне VEDO и возвращает результат. MCP-сервер не требует opt-in — данные онтологии не покидают периметр VEDO.

## Рассмотренные альтернативы

- **Не делать MCP-сервер, только REST API** — LLM-клиенты должны самостоятельно писать SPARQL/CYPHER, что сводит на нет преимущество NL-запросов
- **Сделать только NL-кнопку в GUI** — не покрывает внешние AI-клиенты, которые пользователи уже используют для других задач
- **Сделать отдельный LLM-прокси-сервис** — MCP уже является стандартом; собственный проприетарный протокол увеличивает стоимость интеграции

## Последствия

**Положительные последствия:**
- LLM-клиенты получают стандартизированный доступ к графу знаний через MCP
- NL-запросы обрабатываются на стороне VEDO — данные онтологии не покидают периметр
- MCP-сервер не требует opt-in (в отличие от GUI NL-режима, где данные уходят LLM-провайдеру)
- Единый инструментарий для всех MCP-совместимых AI-ассистентов

**Отрицательные последствия:**
- Требуется поддержка MCP-протокола и его версионирование
- NL-запросы через MCP требуют NL→SPARQL/CYPHER конвертера на стороне VEDO
- Нужна документация по подключению MCP-клиентов

**Меры снижения рисков:**
- Использовать официальную MCP SDK для реализации сервера
- Покрыть инструменты теми же ограничениями безопасности (read-only, LIMIT, timeout, rate limiting, query complexity, аудит)
- Документировать MCP-интеграцию для популярных клиентов (Claude Desktop, Cursor)
