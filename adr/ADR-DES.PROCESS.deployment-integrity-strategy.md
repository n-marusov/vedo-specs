# ADR-DES.PROCESS.deployment-integrity-strategy

**Дата:** 2026-05-13  
**Статус:** Принято

## Контекст

Инцидент Knight Capital показал риск частичного выката: один узел может остаться на старой версии и активировать dead code. Для VEDO Core это угрожает integrity production-данных, миграциям, API-совместимости и восстановлению после инцидентов.

## Требование-источник
- [ci-cd-procedures.md](requirements/REQ-FUN.PROCESS.ci-cd-procedures.md)

## Решение

Каждый production deployment должен проходить автоматическую проверку целостности: CI/CD фиксирует expected artifact digest, 100% узлов возвращают фактический digest до переключения трафика, smoke test проходит на каждом узле, любое расхождение блокирует релиз, откат выполняется автоматически за ≤ 5 минут.

Автоматическая верификация digest на каждом узле исключает silent partial rollout — ни один узел не может остаться на старой версии без блокировки релиза, а автоматический откат за ≤ 5 минут минимизирует время инцидента. Feature flags с owner и expiry ≤ 90 дней предотвращают накопление dead code, а ежеквартальное измерение dead code ratio ≤ 5% делает эту метрику управляемой.

Deployment evidence формируется автоматически CI/CD и хранится append-only в WORM/Object Lock storage; stale feature flags получают cleanup issue вместо немедленного удаления.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Проверять только успешность Helm rollout | Не доказывает, что все узлы получили правильный artifact digest |
| Evidence post-factum вручную | Не гарантирует полноту и достоверность |
| Не блокировать stale feature flags | Накапливает dead code и создаёт риск повторения Knight Capital класса инцидентов |
| Проверять выборку узлов | Неприемлемо: достаточно одного stale узла для катастрофического поведения |

## Последствия

**Положительные последствия:**
- Исключается silent partial rollout.
- Любой инцидент имеет точное evidence, что было развёрнуто и где.
- Feature flags и dead code становятся управляемой частью жизненного цикла.

**Отрицательные последствия:**
- CI/CD становится строже и может чаще блокировать релизы.
- Требуется инфраструктура immutable evidence storage.

**Меры снижения рисков:**
- Evidence формируется автоматически и не требует ручного труда.
- Stale flags получают cleanup issue вместо немедленного удаления.
