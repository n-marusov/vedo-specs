# ADR-DES.PROCESS.merge-request-strategy

**Дата:** 2026-05-16
**Статус:** Принято

## Контекст

При параллельной работе нескольких инженеров над одной онтологией в разных ветках возникает необходимость контролируемого слияния изменений с целевой веткой (например, `main`). Прямой merge без проверки может привести к внесению ошибочных или некачественных изменений в основную ветку.

## Требование-источник

- [collaboration-quality-metrics.md](requirements/REQ-FUN.INTEGRATION.collaboration-quality-metrics.md)
- [branching-model.md](requirements/branching-model.md)

## Решение

Ввести процесс Merge Request как обязательный механизм внесения изменений в защищённые ветки (`main`, `release/*`).

Merge Request включает:
1. Ветка-источник (source branch) с изменениями
2. Ветка-назначения (target branch), обычно `main`
3. Semantic Diff — визуальное сравнение двух версий онтологии (добавленные/удалённые/изменённые классы, свойства, индивиды)
4. Обсуждение (комментарии к Merge Request)
5. Статусы: `draft` → `open` → `approved` → `merged` / `closed`
6. Проверка отсутствия конфликтов перед слиянием

Назначенный Maintainer ревьюит Semantic Diff, оставляет комментарии, утверждает или отклоняет Merge Request. При конфликте с целевой веткой автор Merge Request обязан разрешить конфликт через UI Semantic Diff до повторного запроса ревью.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Прямой push в `main` | Нет контроля качества изменений, невозможно ревью |
| Синхронные блокировки | Противоречит pure Git модели, не решает задачу ревью |

## Последствия

**Положительные:**
- Каждое изменение в `main` проходит ревью
- История Merge Request'ов даёт аудит принятых изменений
- Semantic Diff понятен инженеру знаний (не требует понимания сериализации)

**Отрицательные:**
- Добавляет шаг в процесс внесения изменений
- Требуется UI для управления Merge Request'ами

**Меры снижения рисков:**
- Для hotfix-сценариев возможен fast-track с упрощённым ревью
- Автоматическая проверка на conflicts перед мержем
