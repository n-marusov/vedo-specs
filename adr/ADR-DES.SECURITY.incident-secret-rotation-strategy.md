# ADR-DES.SECURITY.incident-secret-rotation-strategy

**Дата:** 2026-05-17  
**Статус:** Принято

## Контекст

После security-инцидентов критично быстро и полно ротировать секреты. Частичная/медленная ротация оставляет окно повторной компрометации.

## Требование-источник

- [incident-secret-rotation.md](requirements/REQ-NFR.SECURITY.incident-secret-rotation.md)

## Решение

Утвердить mandatory rotation SLA по категориям секретов (4/8/24 часа), с 100% охватом затронутых секретов и автоматическим отзывом старых значений.

## Рассмотренные альтернативы

- Ротация по запросу владельца сервиса — отклонено (непредсказуемо, высокий риск пропусков).
- Единый срок для всех секретов — отклонено (не учитывает критичность).

## Последствия

- **Плюсы:** минимизация dwell-time у скомпрометированных credentials.
- **Минусы:** риск кратковременной нестабильности интеграций при массовой ротации.
- **Смягчение:** обязательный post-rotation smoke suite.
