# ADR-DES.SECURITY.nl-query-opt-in-mandate

**Дата:** 2026-05-24  
**Статус:** ПРИНЯТО

## Контекст

NL-режим в GUI Query Builder (кнопка «Микрофон») отправляет NL-запрос пользователя и контекст онтологии (классы, свойства, метки узлов) внешнему LLM-провайдеру для генерации SPARQL или CYPHER.

Онтологии VEDO Core могут содержать конфиденциальные бизнес-данные клиентов (нефтегазовая, фармацевтическая, финансовая отрасли). Передача этих данных внешнему LLM-провайдеру без явного согласия пользователя создаёт риск утечки интеллектуальной собственности и нарушения NDA.

MCP-сервер обрабатывает NL-запросы на стороне VEDO, без отправки данных внешнему провайдеру, поэтому для MCP opt-in не требуется.

## Требование-источник
- [vision.md](vision.md) — F10.6

## Решение

Ввести обязательный opt-in для NL-режима в GUI Query Builder. MCP-сервер не требует opt-in.

**Правила:**
- Перед первым NL-запросом в сессии пользователь видит диалог с предупреждением: «Ваш запрос и структура онтологии будут отправлены LLM-провайдеру (указать имя). Данные могут быть использованы провайдером для обучения моделей. Нажмите «Разрешить» для продолжения или «Отмена» для возврата в редактор».
- Согласие действует на одну сессию (до закрытия вкладки или истечения токена сессии).
- Пользователь может отозвать согласие в любой момент через настройки сессии.
- Факт opt-in (или отказа) фиксируется в audit-логе вместе с timestamp, user_id и provider_name.
- При отказе от opt-in NL-режим недоступен; пользователь может использовать визуальный конструктор или текстовый редактор.
- MCP-сервер не показывает opt-in: обработка NL-запроса выполняется на стороне VEDO, данные не покидают периметр.
- Организации могут настроить allowlist/blocklist LLM-провайдеров на уровне tenant.

## Рассмотренные альтернативы

- **Не делать opt-in** — риск утечки данных онтологии внешнему LLM-провайдеру без ведома пользователя; нарушение принципа privacy-by-design
- **Всегда блокировать NL-запросы** — пользователи теряют возможность NL-генерации запросов, снижается ценность функции
- **Анонимизировать контекст перед отправкой** — невозможно анонимизировать структуру онтологии (классы, свойства) без потери полезного контекста для LLM
- **Только on-premise LLM без opt-in** — ограничивает пользователей SaaS, которые хотят использовать внешние LLM; можно добавить как опцию post-MVP

## Последствия

**Положительные последствия:**
- Пользователь явно контролирует передачу данных онтологии LLM-провайдеру
- Соответствие принципу privacy-by-design и GDPR/152-ФЗ
- MCP-сервер не требует opt-in, что упрощает интеграцию внешних AI-клиентов
- Audit-лог фиксирует все факты opt-in для compliance

**Отрицательные последствия:**
- Дополнительный шаг в UX NL-режима (диалог opt-in)
- Пользователь может случайно отклонить opt-in и не понять, почему NL-режим недоступен
- Сессионное согласие требует повторного opt-in при каждом входе

**Меры снижения рисков:**
- Чёткий и понятный текст предупреждения с указанием имени провайдера
- Возможность сохранить согласие на более длительный срок (с настройкой tenant)
- Разрешить администраторам tenant предварительно утверждать провайдеров, чтобы снизить число диалогов opt-in для пользователей
