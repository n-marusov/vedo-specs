# ADR-DES.UI.ai-suggestion-ux-strategy — Стратегия UX AI-подсказок связей

**Статус:** ПРЕДЛОЖЕНО
**Дата:** 2026-07-15

## Контекст

VEDO Hub внедряет AI-подсказки связей (F14.3) — функция, которая предлагает пользователю возможные связи между классами, свойствами и другими сущностями онтологии на основе анализа структуры и common patterns.

**Проблемы UX:**

1. **Confirmation fatigue:** Слишком много подсказок → пользователь перестаёт их анализировать и принимает бездумно (аналогично GitHub Copilot).
2. **Низкое качество:** Подсказки с низкой уверенностью отвлекают и снижают доверие к системе.
3. **Информационная перегрузка:** Пользователь не понимает, каким подсказкам можно доверять.
4. **Отсутствие контекста:** Пользователь не видит обоснования подсказки.
5. **Сложность применения:** Применение подсказки требует много действий.
6. **Конфиденциальность:** Для Internal/Private онтологий подсказки должны генерироваться только локальной LLM.

**Целевые UX-принципы:**

1. **Качество над количеством:** Показывать только лучшие подсказки (≤ 5, confidence ≥ 70%).
2. **Прозрачность:** Пользователь видит уверенность и обоснование каждой подсказки.
3. **Контроль:** Пользователь явно подтверждает применение (не автоматически).
4. **Контекст:** Подсказки связаны с текущей сущностью и онтологией.
5. **Производительность:** Подсказки генерируются быстро (≤ 7 сек p95).
6. **Безопасность:** Конфиденциальность данных соблюдается.

### 2. Поток генерации подсказок

```
1. Пользователь открывает сущность (класс/свойство) в редакторе
2. UI отправляет запрос к Suggestion Engine:
   {
     "entity_id": "http://example.org/class/Car",
     "entity_type": "class",
     "ontology_id": "ontology-123",
     "context": {
       "open_tabs": ["Car", "Engine", "Wheel"],
       "recent_changes": ["Added Driver class"]
     }
   }
3. Suggestion Engine проверяет кэш (Redis, TTL = 5 мин)
4. Если кэш отсутствует или устарел:
   a. Запрашивает структуру онтологии из Ontology Service
   b. LLM Policy Router определяет провайдера (Public → external/local, Internal/Private → local)
   c. Генерирует подсказки через LLM (с учётом confidence)
   d. Фильтрует подсказки по confidence ≥ 70%
   e. Ранжирует по убыванию confidence
   f. Сохраняет в кэш (Redis, TTL = 5 мин)
   g. Сохраняет историю в PostgreSQL
5. Возвращает пользователю максимум 5 подсказок
6. UI отображает подсказки с индикаторами уверенности
```

### 3. Типы подсказок и их представление

| Тип | OWL-конструкция | Отображение в UI |
|-----|----------------|------------------|
| **subClassOf** | `rdfs:subClassOf` | «Класс X → подкласс Y» |
| **ObjectProperty** | `owl:ObjectProperty` | «Свойство 'имеет' связывает X и Y» |
| **DatatypeProperty** | `owl:DatatypeProperty` | «Атрибут 'год' типа integer для X» |
| **EquivalentClass** | `owl:equivalentClass` | «Класс X эквивалентен Y» |
| **DisjointClass** | `owl:disjointWith` | «Класс X и Y — непересекающиеся» |

**Отображение каждой подсказки:**

```
┌─────────────────────────────────────────────────────────────────┐
│  🔗 [Тип связи]  ●●●●● 92%  (высокая уверенность)              │
│                                                                 │
│  "Класс 'ЛегковойАвтомобиль' может быть подклассом 'Автомобиль'" │
│                                                                 │
│  [Применить]  [Отклонить]  [Почему?]                           │
│                                                                 │
│  Обоснование: "В онтологии уже есть класс 'Автомобиль'.         │
│  'ЛегковойАвтомобиль' является специализацией, что соответствует │
│  иерархической структуре."                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 4. Управление состоянием подсказок

**Состояния подсказки:**

| Состояние | Описание | Действия пользователя |
|-----------|----------|----------------------|
| **Pending** | Предложена, ожидает реакции | Apply / Reject / Ignore |
| **Accepted** | Принята пользователем | Связь создана, коммит создан |
| **Rejected** | Отклонена пользователем | Больше не показывается для сущности |
| **Applied Manually** | Пользователь создал связь вручную | Подсказка больше не нужна |

**Хранение состояния:**

```sql
CREATE TABLE suggestion_history (
    id UUID PRIMARY KEY,
    entity_id VARCHAR(255) NOT NULL,
    entity_type VARCHAR(50) NOT NULL,
    ontology_id UUID NOT NULL,
    suggestion_type VARCHAR(50) NOT NULL,
    details JSONB NOT NULL, -- { target_entity, property_type, ... }
    confidence DECIMAL(5, 2) NOT NULL,
    status VARCHAR(20) NOT NULL, -- pending/accepted/rejected/applied_manually
    user_id UUID,
    timestamp TIMESTAMP NOT NULL,
    accepted_at TIMESTAMP,
    rejected_at TIMESTAMP,
    applied_manually_at TIMESTAMP,
    llm_provider VARCHAR(50),
    trace_id VARCHAR(255)
);
```

### 5. Кэширование подсказок

**Redis схема:**

```
Key: suggestion:{ontology_id}:{entity_id}:{entity_type}
Value: JSON array of suggestions (max 10)
TTL: 5 минут (или сброс при изменении онтологии)
```

**Инвалидация кэша:**
- При изменении структуры онтологии (добавление/удаление класса/свойства)
- При применении подсказки (состояние меняется)
- По истечении TTL (5 минут)

### 6. Конфигурация

```yaml
ai_suggestions:
  max_suggestions: 5
  max_suggestions_on_show_more: 10
  confidence_threshold: 0.7  # 70%
  cache_ttl: 300  # 5 минут в секундах
  rate_limit:
    per_user_per_minute: 20
    per_entity_per_hour: 10
  recalc_triggers:
    - class_created
    - class_deleted
    - property_created
    - property_deleted
    - class_hierarchy_changed
  analytics:
    enabled: true
    collect_anonymously: true
```

### 7. Конфиденциальность и безопасность

| Уровень онтологии | LLM-провайдер для подсказок |
|-------------------|-----------------------------|
| **Public** | Внешний (OpenAI/Anthropic) или локальный (по выбору) |
| **Internal** | Только локальный (если админ не разрешил внешний) |
| **Private** | Только локальный (если админ не разрешил внешний) |

**Аудит:**
- Каждая генерация подсказок логируется с указанием провайдера
- Каждое применение/отклонение логируется с указанием пользователя
- Данные онтологии не сохраняются в логах

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Автоматическое применение подсказок | Риск нежелательных изменений — пользователь должен контролировать изменения |
| Показывать все подсказки без фильтрации | Confirmation fatigue (GitHub Copilot research: >5 рекомендаций снижают качество решений) |
| Не показывать confidence | Отсутствие прозрачности — пользователь не может оценить надёжность предложения |
| Генерировать подсказки только при запросе | Увеличение когнитивной нагрузки — подсказки должны быть проактивными |
| Не сохранять историю | Невозможность отследить принятые/отклонённые подсказки и предотвратить повторные предложения |
| Одинаковые подсказки для всех типов сущностей | Разные типы сущностей требуют разных типов подсказок (subClassOf релевантен для классов, но не для свойств) |

## Последствия

**Положительные последствия:**

1. **Улучшение UX:** Пользователь видит только качественные подсказки (≤ 5, confidence ≥ 70%).
2. **Прозрачность:** Confidence score и обоснование помогают принимать решения.
3. **Контроль:** Пользователь явно подтверждает применение — никаких автоматических изменений.
4. **Производительность:** Кэширование (Redis, TTL 5 мин) снижает нагрузку на LLM и ускоряет отклик.
5. **Безопасность:** LLM Policy Router обеспечивает соблюдение конфиденциальности данных.
6. **Аналитика:** Данные об использовании (acceptance rate, confidence correlation) помогают улучшать качество подсказок.

**Отрицательные последствия:**

1. **Сложность:** Дополнительный компонент (Suggestion Engine) требует разработки и поддержки.
2. **Задержка:** Генерация подсказок добавляет время открытия сущности (≤ 7 сек p95).
3. **Зависимость:** При недоступности LLM подсказки недоступны.
4. **Стоимость:** Генерация подсказок расходует AI Credits.
5. **Когнитивная нагрузка:** Пользователь должен оценивать подсказки (хотя и меньше, чем без фильтрации).

**Меры снижения рисков:**

1. **Асинхронная загрузка:** Подсказки загружаются после открытия сущности — не блокируют интерфейс.
2. **Индикатор загрузки:** Пользователь видит, что подсказки генерируются.
3. **Кэширование:** Снижение нагрузки на LLM и ускорение отклика (Redis, TTL 5 мин).
4. **Graceful degradation:** При недоступности LLM подсказки не отображаются, но редактор работает.
5. **Документация:** Объяснение, как работают подсказки и confidence score.

**Риски:**

1. **Низкое качество подсказок:** Если LLM генерирует плохие подсказки, пользователь перестаёт им доверять.
   - **Смягчение:** Аналитика acceptance rate, итеративное улучшение промптов на основе данных.
2. **Confidence inflation:** LLM может завышать confidence.
   - **Смягчение:** Калибровка confidence на основе исторических данных (корреляция confidence vs acceptance).
3. **Производительность:** Генерация подсказок может быть медленной для больших онтологий.
   - **Смягчение:** Кэширование, ограничение сложности запросов к LLM.
4. **Конфиденциальность:** Для Internal/Private онтологий подсказки не должны использовать внешний LLM.
   - **Смягчение:** LLM Policy Router обеспечивает соблюдение политик; audit-лог фиксирует использованного провайдера.
