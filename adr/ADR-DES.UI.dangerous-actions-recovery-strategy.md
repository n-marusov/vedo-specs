# ADR-DES.UI.dangerous-actions-recovery-strategy

**Дата:** 2026-05-10  
**Статус:** Принято

## Контекст

Удаление класса, перемещение в иерархии, массовый импорт и массовое редактирование могут изменить или удалить значимые фрагменты онтологии. Ошибка пользователя без понятного подтверждения и восстановления является Showstopper, если нет обходного пути.

## Требование-источник
- [dangerous-actions-recovery.md](requirements/REQ-USR.UI.dangerous-actions-recovery.md)

## Решение

Моделировать каждое опасное действие как Command с обязательным dry-run preview и обратимым исполнением через единый Dangerous Action Flow.

Единый паттерн Command + Impact Preview + Reversible Operation даёт пользователю прозрачную картину последствий до подтверждения, гарантирует возможность отката через undo token или rollback reference и исключает случайные необратимые изменения онтологии без привязки к конкретному UI-компоненту.

Реализовать Command как объект с dry-run точка доступа, transactional boundary на серверной части и привязкой к Versioning Service для массовых операций; UI вызывает единый flow: preview → confirm → execute → undo.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Прямые API-вызовы из UI | Нельзя единообразно показать последствия и восстановление |
| Простое подтверждение `Вы уверены?` | Не даёт архитектурной связи с impact analysis и rollback |
| Rollback только через ручную поддержку админа | Не подходит для частых операций моделирования |

## Последствия

**Положительные последствия:**
- Опасные операции становятся единообразными и тестируемыми.
- Серверная часть получает явную модель command/dry-run/execute.
- Versioning Service становится естественной точкой rollback для массовых изменений.

**Отрицательные последствия:**
- Нужно проектировать dry-run для разных доменных операций.
- Не все действия обратимы без дополнительной истории изменений.

**Меры снижения рисков:**
- Ограничить паттерн только операциями с риском потери/массового изменения данных.
- Для irreversible actions требовать explicit acknowledgement и создавать backup/commit до применения.
