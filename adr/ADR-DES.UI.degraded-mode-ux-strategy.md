# ADR-DES.UI.degraded-mode-ux-strategy

**Дата:** 2026-05-17  
**Статус:** Принято

## Контекст

Полная недоступность системы во время деградации наносит больший ущерб, чем контролируемый read-only режим. Нужна единая UX-политика деградации.

## Требование-источник

- [degraded-mode-availability.md](requirements/REQ-USR.UI.degraded-mode-ux.md)

## Решение

Ввести обязательный degraded mode: сохранение read-only операций с измеримым SLO, блокировка write-path с детерминированным кодом ошибки и обязательным UI-баннером.

## Рассмотренные альтернативы

- Полный shutdown при перегрузке — отклонено (излишний downtime).
- Частичная деградация без стандартизованной API/UI семантики — отклонено (хаос для пользователей и интеграторов).

## Последствия

- **Плюсы:** контролируемое снижение функциональности, сохранение доступа к критичному read-flow.
- **Минусы:** усложнение state-машины приложения.
- **Смягчение:** единые error codes и автотесты режимов деградации.
