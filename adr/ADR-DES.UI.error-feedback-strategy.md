# ADR-DES.UI.error-feedback-strategy

**Дата:** 2026-05-10  
**Статус:** Принято

## Контекст

Пользователи VEDO Core включают инженеров знаний, ИТ-архитекторов, бизнес-пользователей и аналитиков. Технические ошибки вида `Invalid IRI`, `Error 403`, `domain is null` без привязки к объекту или полю увеличивают time-to-learn и создают Major UX-дефекты.

## Требование-источник
- [error-feedback.md](requirements/REQ-NFR.UI.error-feedback.md)

## Решение

Ввести единый структурированный error contract между серверной частью и клиентской частью с Error Presentation Layer для отображения.

Унифицированный contract со stable error_code, severity, field_path, message_key и recovery_hint_key позволяет клиентской части мапить технические ошибки на локализованные пользовательские сообщения, выбирать корректный renderer (inline, toast, modal, import report row) и агрегировать UX-значимые коды ошибок для observability — исключая raw текст серверной части в интерфейсе пользователя.

Серверная часть возвращает error_code, severity, field_path, message_key и recovery_hint_key; клиентская часть мапит message_key на локализованное сообщение; Error Presentation Layer выбирает renderer в зависимости от контекста ошибки.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Показывать raw ошибки серверной части | Смешивает техническую диагностику и пользовательский язык |
| Мапить ошибки отдельно в каждом компоненте | Дублирование, непоследовательность и сложная локализация |
| Только HTTP status без доменных кодов | Нельзя привязать ошибку к полю/узлу/операции |

## Последствия

**Положительные последствия:**
- Ошибки становятся частью API contract.
- Клиентская часть получает единый слой локализации и presentation.
- Observability может агрегировать UX-significant error codes.

**Отрицательные последствия:**
- Нужно поддерживать registry error codes/message keys.
- Изменения в error contract требуют versioning.

**Меры снижения рисков:**
- Версионировать error schema.
- Запретить неописанные public error codes в contract tests.
