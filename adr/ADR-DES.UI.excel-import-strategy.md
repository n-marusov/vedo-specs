# ADR-DES.UI.excel-import-strategy — Стратегия импорта Excel→OWL

**Статус:** ПРЕДЛОЖЕНО
**Дата:** 2026-07-15

## Контекст

VEDO Hub внедряет импорт из Excel→OWL (F14.4) — функцию, позволяющую пользователям загружать данные из Excel-таблиц и автоматически преобразовывать их в OWL-онтологию.

**Проблемы импорта Excel:**

1. **Ошибки в данных:** Пользователи загружают файлы с неверными типами, дубликатами, отсутствующими обязательными полями (аналогично Salesforce data import failures).
2. **Большие файлы:** Импорт больших файлов может занять много времени и вызвать timeout.
3. **Неверный маппинг:** Пользователи не знают, какие колонки соответствуют каким полям онтологии.
4. **Дубликаты:** Как обрабатывать сущности, которые уже существуют в онтологии.
5. **Безопасность:** Excel-файлы могут содержать вредоносные макросы или вирусы.
6. **Обратная связь:** Пользователь должен понимать, какие строки были импортированы, а какие — нет.

**Целевые принципы:**

1. **Качество данных:** Импорт блокируется при > 5% ошибок.
2. **Производительность:** Поддержка до 10,000 строк / 5 МБ.
3. **Прозрачность:** Предпросмотр, отчёт об ошибках, прогресс-бар.
4. **Контроль:** Пользователь выбирает стратегию обработки дубликатов.
5. **Безопасность:** Сканирование на вирусы, экранирование данных.
6. **Асинхронность:** Большие файлы обрабатываются в фоне.

### 3. Обработка ошибок и отчётность

**Структура отчёта об ошибках:**

```sql
CREATE TABLE import_errors (
    id UUID PRIMARY KEY,
    import_id UUID NOT NULL,
    row_number INTEGER NOT NULL,
    column_name VARCHAR(100),
    cell_value TEXT,
    error_type VARCHAR(50) NOT NULL, -- invalid_type, duplicate, missing_required, invalid_iri, invalid_range, invalid_date
    error_message TEXT NOT NULL,
    suggestion TEXT,
    created_at TIMESTAMP
);

CREATE TABLE import_history (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    ontology_id UUID NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_size INT NOT NULL, -- in bytes
    total_rows INT NOT NULL,
    imported_rows INT NOT NULL,
    error_rows INT NOT NULL,
    skipped_rows INT NOT NULL,
    status VARCHAR(20) NOT NULL, -- pending, processing, completed, failed, blocked
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    error_report_url VARCHAR(500),
    corrected_file_url VARCHAR(500),
    duplicate_strategy VARCHAR(20), -- skip, overwrite, error
    created_at TIMESTAMP
);
```

**Коды ошибок:**

| Тип ошибки | Код | Описание | Suggestion |
|------------|-----|----------|------------|
| `invalid_type` | E001 | «Ожидался тип {expected}, получено '{actual}'» | «Замените на {expected}» |
| `duplicate` | E002 | «Сущность '{value}' уже существует» | «Используйте уникальное имя» |
| `missing_required` | E003 | «Отсутствует обязательное поле '{field}'» | «Добавьте значение в колонку '{field}'» |
| `invalid_iri` | E004 | «Некорректный IRI: '{value}'» | «Используйте латиницу или URL-кодирование» |
| `invalid_range` | E005 | «Значение вне допустимого диапазона» | «Используйте значение от {min} до {max}» |
| `invalid_date` | E006 | «Некорректный формат даты: '{value}'» | «Используйте формат ГГГГ-ММ-ДД» |
| `parent_not_found` | E007 | «Родительский класс '{value}' не найден» | «Создайте родительский класс или исправьте имя» |
| `invalid_sheet` | E008 | «Лист '{sheet}' не найден» | «Убедитесь, что файл содержит лист с данными» |

### 4. Поддерживаемые форматы

| Формат | Расширение | Парсер | Примечание |
|--------|-----------|--------|------------|
| Excel (Open XML) | `.xlsx` | Apache POI / OpenXML | Основной формат |
| Excel (Macro-enabled) | `.xlsm` | Apache POI (macros ignored) | Макросы не выполняются |
| CSV (UTF-8) | `.csv` | CSV parser (auto-delimiter) | Поддержка `,` и `;` разделителей |

**Не поддерживаемые форматы:**
- `.xls` (Excel 97-2003) — отклоняется с предложением конвертировать
- Файлы с паролем — отклоняются
- Файлы с внешними ссылками — предупреждение

### 5. Производительность и масштабирование

**Пороговые значения:**

| Параметр | Значение | Действие |
|----------|----------|----------|
| **Строки** | ≤ 1,000 | Синхронный импорт |
| **Строки** | 1,001 - 10,000 | Асинхронный импорт (очередь) |
| **Строки** | > 10,000 | Блокировка (превышен лимит) |
| **Размер** | ≤ 5 МБ | Принимается |
| **Размер** | > 5 МБ | Блокировка (превышен лимит) |

**Асинхронная обработка:**

1. Запрос помещается в RabbitMQ queue
2. Worker обрабатывает файл (валидация, импорт)
3. Прогресс сохраняется в PostgreSQL (обновляется каждые 100 строк)
4. При завершении — email уведомление
5. Пользователь может отслеживать статус через API

**Конфигурация:**

```yaml
excel_import:
  max_rows: 10000
  max_size_mb: 5
  error_threshold_percent: 5.0
  async_threshold_rows: 1000
  supported_formats: ['.xlsx', '.xlsm', '.csv']
  chunk_size: 100  # строк для batch-обработки
  progress_update_interval: 100  # строк
  virus_scan_enabled: true
  audit_enabled: true
```

### 6. Безопасность

**Меры безопасности:**

1. **Вирусы:** Файлы сканируются через ClamAV (или аналогичный антивирус).
2. **Макросы:** Макросы в `.xlsm` не выполняются (парсинг только данных).
3. **Инъекции:** Все данные экранируются перед записью в базу (OWASP SQL Injection).
4. **Размер:** Лимиты предотвращают DoS-атаки.
5. **Аутентификация:** Только аутентифицированные пользователи могут импортировать.
6. **Аудит:** Все импорты логируются с указанием пользователя, файла, результатов.
7. **XSS:** Данные из Excel экранируются перед отображением в UI.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Импорт сразу всех строк без предварительной валидации | Риск частичного импорта с ошибками — пользователь не видит проблемы |
| Автоматическое исправление ошибок | Риск неверных исправлений — система не может знать намерения пользователя |
| Только синхронный импорт | Проблемы с timeout при больших файлах (> 1,000 строк) |
| Игнорировать дубликаты без уведомления | Потеря прозрачности — пользователь должен знать о пропущенных сущностях |
| Не показывать предпросмотр | Риск неверного маппинга — пользователь не видит, как колонки интерпретируются |

## Последствия

**Положительные последствия:**

1. **Качество данных:** Блокировка при > 5% ошибок предотвращает частичный импорт с проблемами.
2. **Прозрачность:** Предпросмотр маппинга, детальный отчёт об ошибках, прогресс-бар.
3. **Контроль:** Пользователь выбирает стратегию обработки дубликатов.
4. **Производительность:** Асинхронный импорт для больших файлов (> 1,000 строк).
5. **Безопасность:** Антивирусное сканирование, экранирование данных, аудит.
6. **Масштабируемость:** Очередь сообщений (RabbitMQ) для асинхронной обработки.

**Отрицательные последствия:**

1. **Сложность:** Дополнительный компонент (Import Pipeline) требует разработки и поддержки.
2. **Задержка:** Асинхронный импорт требует ожидания завершения (email-уведомление).
3. **Зависимости:** Зависимость от антивируса, S3/MinIO, RabbitMQ.
4. **Стоимость:** Хранение временных файлов, обработка очереди сообщений.

**Меры снижения рисков:**

1. **Асинхронный импорт:** Для > 1,000 строк — пользователь может продолжать работу, не дожидаясь завершения.
2. **Прогресс-бар:** Пользователь видит статус импорта в реальном времени через API polling.
3. **Graceful degradation:** При недоступности антивируса — предупреждение администратору, но импорт возможен.
4. **Документация:** Подробное руководство по импорту, шаблоны с примерами заполнения.

**Риски:**

1. **Большие файлы:** Пользователь может попытаться загрузить файл > 10,000 строк.
   - **Смягчение:** Лимит с чётким сообщением, конфигурируемый для Enterprise-тенантов.
2. **Некорректный маппинг:** Система может неверно определить соответствие колонок полям онтологии.
   - **Смягчение:** Предпросмотр с ручной корректировкой маппинга.
3. **Производительность:** Валидация 10,000 строк может занять время.
   - **Смягчение:** Асинхронная обработка, chunk-based валидация по 100 строк.
4. **Повторный импорт:** Пользователь может случайно импортировать данные повторно.
   - **Смягчение:** Стратегия обработки дубликатов (Skip/Overwrite/Error), аудит всех импортов.
