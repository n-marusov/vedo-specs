# ADR-DES.UI.incident-communication-sla-strategy

**Дата:** 2026-05-17  
**Статус:** Принято

## Контекст

При частичных деградациях пользователи теряют доверие, если команда не дает быстрые и регулярные статус-обновления. Требуется единый SLA коммуникации инцидентов.

## Требование-источник

- [incident-communication-sla.md](requirements/REQ-NFR.UI.incident-communication-sla.md)

## Решение

Утвердить обязательный incident communication SLA: первый апдейт <= 10 минут, далее обновления каждые 15/30 минут для P0/P1, и публикация RCA в фиксированные сроки.

## Рассмотренные альтернативы

- Коммуникация только через support tickets — отклонено (низкая скорость и охват).
- Коммуникация без SLA — отклонено (неизмеримость и непредсказуемость).

## Последствия

- **Плюсы:** прозрачность для клиентов, снижение churn и повторных тикетов.
- **Минусы:** дополнительная нагрузка на incident commander.
- **Смягчение:** шаблоны сообщений и автоматизация публикации на status page.
