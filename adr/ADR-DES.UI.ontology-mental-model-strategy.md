# ADR-DES.UI.ontology-mental-model-strategy

**Дата:** 2026-05-10  
**Статус:** Принято

## Контекст

Новички и бизнес-пользователи могут путать классы, свойства, индивиды, domain/range и наследование. Для VEDO Core это не просто косметика: неверная ментальная модель приводит к ошибкам моделирования знаний.

## Требование-источник
- [ontology-mental-model.md](requirements/REQ-USR.UI.ontology-mental-model.md)

## Решение

Ввести Ontology UI Type System — единый слой presentation metadata для онтологических типов и связей.

Единый presentation registry гарантирует одинаковую визуальную семантику (иконки, цвета, подписи, allowed actions) во всех UI-представлениях — дереве, графе, карточках, результатах поиска и diff — и снижает порог входа для неэкспертов через progressive disclosure терминов OWL/RDF без потери точности для инженеров знаний.

Registry описывает каждый entity kind (Class, ObjectProperty, Individual, Constraint и т.д.) с icon, color token, label, short help и relation semantics; все компоненты потребляют один registry вместо локальных визуальных правил.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Визуальные правила внутри каждого компонента | Быстро приводит к расхождению дерева, графа и diff |
| Использовать только OWL/RDF термины | Слишком высокий порог входа для неэкспертов |
| Скрыть технические термины полностью | Инженерам знаний нужна точность и проверяемая семантика |

## Последствия

**Положительные последствия:**
- Одинаковая визуальная семантика во всех UI-представлениях.
- Компоненты не дублируют знания о типах ontology entities.
- Можно добавлять новые типы/отношения через registry.

**Отрицательные последствия:**
- Registry становится общей зависимостью клиентской части.
- Требуется governance для изменения color/icon/action semantics.

**Меры снижения рисков:**
- Хранить registry рядом с design tokens и покрывать snapshot/contract tests.
- Изменения registry проводить через ADR/design review при влиянии на семантику.
