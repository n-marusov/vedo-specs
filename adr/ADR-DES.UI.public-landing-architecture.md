# ADR-DES.UI.public-landing-architecture — Архитектура публичного лендинга VEDO Hub

**Дата:** 2026-08-01
**Статус:** Предложено

## Контекст

VEDO Hub — новый продукт в новой категории («социальный хаб онтологий»). В отличие от GitHub и GitLab, где категория «хостинг кода» или «DevOps-платформа» уже устоялась, VEDO должен сначала **объяснить посетителю, что такое онтология и зачем она нужна**, а затем конвертировать его в пользователя.

Текущая ситуация:
- Продуктовый фронтенд (Vue 3, Apollo, Keycloak) требует авторизации: корневой URL `/` редиректит на `/dashboard/home` → `/login`
- Единственная публичная страница — `/public/:id` (`requiresAuth: false`) — показывает дерево классов и счётчики, но граф-область — пустой плейсхолдер
- Сервис `public-browse-api` (Rust, axum + gRPC) существует, но используется минимально
- Сервис `publish-browse-ui` (Vue 3, nginx) существует, но практически пуст — содержит только точку входа без бизнес-логики
- VEDO Demos (5 проектов: Организация, Продукт, Процесс, Глоссарий, Событие) создаются как seed data в M5 (F13.1 Forks)

Согласно vision.md §2.5 (L1027), «public browse UI» явно исключён из MVP. Однако ROADMAP M5 включает задачу «Public landing page + demo showcase» как executive decision: минимальный лендинг (hero, витрина демо, кликабельный граф) должен войти в MVP, несмотря на формальное ограничение vision. Полноценный Public Browse 1.0 (поиск, DOI, visibility model) остаётся в M11.

Требуется архитектурное решение: **где и как развернуть публичный лендинг**, чтобы он (a) не тянул тяжёлый стек продукта, (b) был независим от доступности Keycloak/основных сервисов, (c) переиспользовал существующую инфраструктуру (`public-browse-api`, `publish-browse-ui`).

## Требование-источник

- `specs/requirements/REQ-USR.UI.public-landing.md` — полные требования к лендингу (R1–R8)
- `specs/vision.md` §1.5 «Положение о концепции», §2.5 «MVP scope»

- `.ai-factory/RESEARCH.md` — анализ GitHub/GitLab лендингов (сессия 2026-08-01)

## Решение

Публичный лендинг VEDO Hub развёртывается в существующем сервисе **`publish-browse-ui`** как отдельное лёгкое Vue 3 приложение за nginx, изолированное от основного `frontend`. Данные для демо-онтологий поступают через `public-browse-api` (Rust, gRPC к `ontology-service`, без Keycloak).

### Архитектурная диаграмма

```
                        +-----------------------------------------+
  Неавторизованный       |  publish-browse-ui (nginx, порт X)      |
  посетитель             |                                         |
       |                 |  /                -> Лендинг (hero,      |
       v                 |                     карточки демо,      |
  GET /                  |                     ролевые секции)     |
                         |  /public/{slug}   -> Просмотрщик        |
                         |                     (Vue Flow-граф)     |
                         |                                         |
                         +--------------+--------------------------+
                                        | HTTP (без auth)
                                        v
                         +-----------------------------------------+
                         |  public-browse-api (Rust, axum+gRPC)    |
                         |  GET /api/v1/public/projects            |
                         |  GET /api/v1/public/projects/{slug}     |
                         |  GraphQL (nodes + edges for Vue Flow)    |
                                        | gRPC
                                        v
                         +-----------------------------------------+
                         |  ontology-service (Rust, Neo4j)         |
                         |  Project + Ontology data for            |
                         |  visibility=public projects             |
                         +-----------------------------------------+

  - - - - граница авторизации - - - -

                         +-----------------------------------------+
  Авторизованный          |  frontend (Vue 3, Apollo, Keycloak)    |
  пользователь            |  /dashboard/home, /project/:id/...     |
       |                  |                                         |
       v                  |                                         |
  Keycloak OAuth          +-----------------------------------------+
  (JWT, RBAC)
```

### Ключевые решения

1. **Лендинг — внутри `publish-browse-ui`, не внутри `frontend`.**

   - `publish-browse-ui` — отдельный Docker-контейнер (nginx + Vue 3), уже существующий, лёгкий (нет Apollo, Keycloak)
   - Основной `frontend` не меняется: `/` → по-прежнему редирект на `/dashboard/home` (для авторизованных)
   - Публичная и приватная зоны изолированы — падение Keycloak не ломает лендинг

2. **Два режима в `publish-browse-ui`: статический лендинг + динамический просмотрщик.**

   - `/` — полностью статический HTML/CSS/минимальный JS (≤ 50 KB, ≤ 10 запросов)
   - `/public/{slug}` — динамическая страница с Vue Flow (ленивая загрузка)
   - Graceful degradation: hero, CTA, карточки демо — без JS; граф — с JS

3. **Данные демо-онтологий — через `public-browse-api` (без Keycloak).**

   - `public-browse-api` получает эндпоинты:
     - `GET /api/v1/public/projects` — список проектов с `visibility=public`
     - `GET /api/v1/public/projects/{slug}` — метаданные (classCount, propertyCount, individualCount)
     - `GraphQL endpoint for graph data (nodes + edges for Vue Flow)`
   - БЕЗ JWT-аутентификации — это read-only публичный доступ
   - `public-browse-api` → gRPC → `ontology-service` (внутренний вызов, Neo4j)

4. **Граф (Vue Flow) — переиспользование из `OntologyWorkspace`, адаптированное под read-only.**

   - Компонент `GraphVisualization` из `ui-kit.lib.pen` (Organism/GraphVisualization)
   - Vue Flow — уже в стеке, лицензия MIT, используется в `OntologyWorkspace`
   - Адаптация: только чтение, тёмная тема, публичный API данных

5. **Дизайн — сначала Pencil, потом код (Design-first по RULES.md).**

   - Новый файл `design/pages/landing.pen`
   - Импортирует `ui-kit.lib.pen` (алиас `B:`)
   - Содержит фреймы: `landingHero`, `landingDemoCards`, `landingRoles`, `landingTrust`, `landingFooter`
   - Размер страницы: 1920×1080 px (FullHD — стандарт всех страниц в `design/pages/`)

6. **Граница между M5 (лендинг) и M11 (Public Browse 1.0).**

   | Возможность | M5 (сейчас) | M11 (1.0) |
   |------------|-------------|-----------|
   | Hero + CTA | ✅ | ✅ |
   | Карточки VEDO Demos (5 проектов) | ✅ (статика) | ✅ (динамика: поиск, фильтрация) |
   | Просмотрщик графа (Vue Flow) | ✅ (read-only, ≤ 200 узлов) | ✅ (полный, без ограничений) |
   | Публичный поиск по онтологиям | ❌ | ✅ |
   | DOI-метаданные | ❌ | ✅ |
   | Visibility model (public/internal/private) | ❌ (только public) | ✅ |
   | Каталог всех публичных онтологий | ❌ | ✅ |
   | Регистрация / OAuth | ✅ (CTA → Keycloak) | ✅ |

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| **A: Лендинг внутри основного `frontend` (как GitHub)** | Тянет Apollo, Keycloak, весь стек — медленно (противоречит бюджету R5: ≤ 200 KB). Падение Keycloak ломает лендинг. |
| **B: Отдельный статический сайт (как `about.gitlab.com`)** | Два домена, двойной фаннел, разделение бренда. VEDO на ранней стадии — один продукт, одно сообщество. Плюс лишний сервис для поддержки. |
| **C: Лендинг = `index.html` в nginx без Vue** | Только статика — нельзя показать живой граф. «Wow-момент» (P5) теряется. Vue Flow нужен для демо-графа. |
| **D: Лендинг через `public-browse-api` как SSR (server-side rendering)** | Избыточно для MVP. Nuxt/SSR — дополнительная зависимость. `publish-browse-ui` с nginx + SPA — достаточно. |

## Последствия

**Положительные:**

- **Изоляция:** лендинг не зависит от доступности Keycloak или основного frontend
- **Производительность:** лёгкий nginx-фронт без Apollo/Keycloak — ≤ 200 KB, ≤ 10 запросов, Lighthouse ≥ 90
- **Переиспользование:** `publish-browse-ui` уже существует (не новый сервис); Vue Flow — из того же стека; `public-browse-api` получает чёткую роль
- **Готовность к M11:** `publish-browse-ui` становится полноценным Public Browse UI в 1.0; лендинг — его естественная точка входа
- **Design-first:** `landing.pen` в Pencil до кода — соответствует ADR-IMPL.PROCESS.ui-design-pencil-adoption
- **Снижение порога входа:** не-эксперт (P4) видит живой граф до регистрации — ключевой «wow-момент»

**Отрицательные:**

- **Два фронта:** `publish-browse-ui` и `frontend` — нужно поддерживать оба. Но `publish-browse-ui` уже существует и будет расти в M11
- **Два маршрута `/`**: корень `publish-browse-ui` = лендинг; корень `frontend` = редирект на dashboard. Но эти сервисы на разных портах/хостах — коллизии нет
- **Vue Flow в публичной зоне:** требует данных из `ontology-service` через `public-browse-api`, а не напрямую. Добавляет эндпоинты в `public-browse-api`

**Меры снижения рисков:**

- Эндпоинты `public-browse-api` для графа (`/graph`) кешируются (Redis, TTL: 60 сек) — снижение нагрузки на Neo4j
- Vue Flow загружается лениво — не аффектит бюджет лендинга
- При падении `public-browse-api` — лендинг (статика) продолжает работать; `/public/{slug}` показывает graceful error
