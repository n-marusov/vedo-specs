# ADR-DES.UI.version-context-visibility-strategy

**Дата:** 2026-05-10  
**Статус:** Принято

## Контекст

VEDO Core имеет Git-подобное версионирование: сохранение объекта, коммит, ветка и экспорт являются разными действиями. Пользовательская ошибка `работаю не в той ветке/версии` или непонимание разницы между save/commit/export могут привести к потере времени и неверным ожиданиям.

## Требование-источник
- [versioning.md](requirements/REQ-FUN.DATA.versioning.md)

## Решение

Ввести клиентской части Version Context Provider как обязательный контекст приложения и связать его с read model Versioning Service.

Единый провайдер гарантирует, что все экраны редактирования видят один ontology_id, branch_id, commit_id и dirty_state, исключая рассинхронизацию и работу не в том контексте, а разделение save/commit/export как разных command paths делает Git-подобную модель прозрачной для пользователя без смешения понятий.

Version Context Provider снабжает все экраны контекстом из Versioning Service; header и action bar потребляют этот контекст; router state включает онтологию и ветку для deep link и восстановления сессии.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| Хранить branch/commit локально в каждом компоненте | Риск рассинхронизации и работы не в том контексте |
| Скрыть version context в advanced panel | Контекст версии становится необязательным и незаметным |
| Объединить save и commit | Ломает Git-подобную модель и затрудняет review/history |

## Последствия

**Положительные последствия:**
- Единый provider исключает дублирование version state.
- Компоненты редактирования получают стабильный API контекста.
- Команды save/commit/export можно тестировать независимо.

**Отрицательные последствия:**
- Нужно поддерживать синхронизацию provider с router, cache и Versioning Service.
- Появляется shared dependency для большинства экранов клиентской части.

**Меры снижения рисков:**
- Держать provider тонким: только identity/context/dirty state, без бизнес-логики diff.
- Проверять context transitions через contract/e2e tests.
