# ADR-IMPL.STACK.api-gateway-go-strategy

**Дата:** 2026-07-14
**Статус:** PROPOSED

## Контекст

API Gateway — единственная внешняя точка входа в VEDO Core, через которую проходят все клиентские запросы. Выполняет функции reverse proxy, middleware (CORS, rate limiting, auth forwarding), маршрутизации gRPC/REST/GraphQL трафика и агрегации ответов.

Требования:
- Высокая конкуррентность соединений (сотни одновременных запросов)
- Минимальная задержка на проксирование (не более единиц миллисекунд на hop)
- Простота добавления новых маршрутов и middleware
- Надёжная обработка большого числа параллельных соединений без роста потребления памяти

## Требование-источник

- [backend-service-stack.md](requirements/REQ-CON.STACK.backend-service-stack.md)

## Решение

Реализовать API Gateway на Go.

Go обеспечивает высокую пропускную способность и предсказуемое потребление памяти для I/O-bound proxy/middleware благодаря лёгким горутинам (один поток на десятки тысяч соединений) и эффективному runtime для сетевых операций. Встроенная стандартная библиотека (`net/http`) и成熟的 middleware-экосистема (Gin, Chi, CORS middleware) позволяют быстро собирать production-ready gateway.

Использовать Gin в качестве HTTP-фреймворка для маршрутизации и middleware; GraphQL-запросы проксировать на соответствующие backend-сервисы без дополнительной обработки на уровне gateway.

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|--------------|--------------------|
| **Rust** | Избыточная сложность и время разработки для сценария proxy/middleware; Rust даёт преимущества в CPU-bound задачах, но gateway — чистый I/O с простой логикой маршрутизации |
| **Node.js** | Подходит для I/O, но горутины Go дают более предсказуемую модель конкуррентности и отсутствие event loop starvation под высокой нагрузкой |
| **Java/Spring Cloud Gateway** | Богатая экосистема, но значительно выше потребление памяти и время холодного старта; избыточно для задач VEDO Core |

## Последствия

**Положительные последствия:**
- Высокая пропускная способность при минимальных накладных расходах
- Лёгкое горизонтальное масштабирование (stateless)
- Быстрая разработка middleware за счёт богатой экосистемы Go
- Простота тестирования и отладки

**Отрицательные последствия:**
- Go не имеет встроенной поддержки async/await — для некоторых сценариев проксирования может потребоваться ручное управление горутинами

**Меры снижения рисков:**
- Использовать проверенные middleware-библиотеки (Gin, rate limiting от `golang.org/x/time/rate`)
- Покрыть gateway нагрузочными тестами для выявления узких мест
- Ввести timeout и circuit breaker для upstream-сервисов
