# ADR-IMPL.SUP.ticket-operations-channels

**Дата:** 2026-05-24  
**Статус:** ПРИНЯТО

## Контекст

В контуре тикетов VEDO Core были пересекающиеся формулировки про "support console" в GUI и операторские действия поддержки. Это приводило к риску дублирования админского интерфейса в VEDO GUI при наличии уже принятого CLI-контура (`vedo-cli`) и внутреннего рабочего контура компании в GitLab.

## Требование-источник

- `human/artifacts/requirements/REQ-FUN.INTEGRATION.ticket-management.md`
- `human/artifacts/requirements/REQ-FUN.INFRA.vedo-cli-specification.md`
- `ADR-IMPL.UI.volt-vs-primevue-vs-vuetify`

## Решение

1. В v1.0 операторские действия по тикетам выполняются через `vedo-cli`.
2. Админский интерфейс поддержки в VEDO GUI не реализуется (no duplicate admin GUI).
3. GitLab Issues остаётся внутренним контуром компании для доработок и исправлений; ссылки/IID GitLab не показываются конечному пользователю.
4. В пользовательском VEDO GUI отображается только проекция статуса тикета: `получен`, `в работе`, `отклонён`, `решён`.
5. Интеграция VEDO ↔ GitLab по вебхукам/двусторонней синхронизации остаётся future backlog (integration-ready, без включения в v1.0).

## Рассмотренные альтернативы

**1. Полноценная support-console в VEDO GUI**
- Отклонено: дублирует операторский контур, увеличивает стоимость реализации и сопровождения, повышает риск рассинхронизации с CLI.

**2. Только GitLab GUI без CLI**
- Отклонено: не покрывает обязательные guardrail и audit-процедуры `vedo-cli` для эксплуатационных ролей (L1/L2/L3, DevOps/SRE).

## Последствия

**Положительные последствия:**
- Один операторский канал в продукте (`vedo-cli`) без дублирования админского GUI.
- Чёткая граница между пользовательским UX и внутренним контуром поддержки.
- Ниже риск утечки внутренних данных (GitLab links/IID) в пользовательский интерфейс.

**Отрицательные последствия:**
- Поддержка должна работать через CLI, что требует дисциплины runbook и обучения.
- Для внутреннего GitLab-контура остаётся организационная связка (процессы/регламенты), не реализованная как продуктовая интеграция в v1.0.
