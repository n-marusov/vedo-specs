# ADR-IMPL.UI.volt-vs-primevue-vs-vuetify

**Дата:** 2026-05-22  
**Статус:** ПРИНЯТО

## Контекст

Для фронтенда VEDO Core принят стек Vue 3 + Composition API + TypeScript + Apollo Client (`ADR-IMPL.STACK.frontend-vue-strategy`). Необходимо выбрать библиотеку UI-компонентов для реализации интерфейса редактирования онтологий. Ключевые требования: соответствие WCAG 2.1 AA (`ADR-DES.UI.wcag-accessibility-strategy`), гибкая кастомизация под корпоративный стиль (`ADR-DES.UI.design-system-customization-strategy`), производительность и низкий порог входа.

## Требование-источник

- `ADR-IMPL.STACK.frontend-vue-strategy`
- `ADR-DES.UI.wcag-accessibility-strategy`
- `ADR-DES.UI.design-system-customization-strategy`
- `human/artifacts/context.md`

## Решение

Выбрать **Volt** — официальную надстройку над PrimeVue с подходом "source-available" и стилизацией через Tailwind CSS.

Граница решения для тикетного контура:
- Volt применяется для пользовательского VEDO GUI (форма обратной связи, список собственных тикетов, статусная проекция).
- Административный интерфейс поддержки в VEDO GUI не реализуется; операторские действия выполняются через `vedo-cli`.
- GitLab Issues используется во внутреннем контуре компании для задач доработки/исправлений и не экспонируется конечным пользователям VEDO GUI.

**Ключевые характеристики:**
- Компоненты добавляются в проект как `.vue`-файлы в `src/volt/`, а не как пакет из `node_modules`.
- Стилизация через Tailwind CSS: компоненты — обёртки над `unstyled`-версией PrimeVue, стили задаются через пропс `pt` и Tailwind-классы.
- Соответствие WCAG 2.1 AA.
- Набор из ~30 ключевых компонентов.
- Установка через `npx volt-vue add [component]`.

**Обоснование:**
- Подход "source-available" даёт команде полный контроль над кодом компонентов (нет "чёрного ящика" в `node_modules`).
- Tailwind CSS идеально интегрируется со стратегией кастомизации UI через CSS-переменные (`customization-variables.md`).
- Полное соответствие принятой accessibility-стратегии (WCAG 2.1 AA).

## Рассмотренные альтернативы

**1. Чистый PrimeVue**
- Предлагает 90+ готовых компонентов.
- Система темизации на базе дизайн-токенов сложнее для кастомизации под экосистему Tailwind.
- Компоненты остаются "чёрным ящиком" в `node_modules`.

**2. Naive UI**
- Хорошая TypeScript-поддержка и нативная интеграция с Vue 3 Composition API.
- Меньше контроля над стилизацией (нет source-available подхода).
- Компонентная база не следует WCAG 2.1 AA так же строго, как PrimeVue/Volt.

**3. Vuetify**
- Следует спецификации Material Design, что делает его фреймворк-специфичным.
- Сильно ограничивает возможности кастомизации под корпоративный стиль.

## Последствия

**Положительные последствия:**
- Полный контроль над кодом компонентов внутри `src/volt`.
- Нативная поддержка Tailwind CSS и интеграция с дизайн-токенами.
- Соблюдение Accessibility (WCAG 2.1 AA).
- Возможность добавлять только необходимые компоненты.

**Отрицательные последствия:**
- Команда берёт на себя поддержку кода компонентов внутри `src/volt`.
- Необходимость периодического обновления компонентов из репозитория PrimeVue через `npx volt-vue add`.
- Потенциальные конфликты с ESLint на сгенерированных файлах.

**Меры снижения рисков:**
- Настроить игнорирование `src/volt` для ESLint.
- Создать скрипт для обновления компонентов с проверкой обратной совместимости.
- Документировать процесс обновления и добавления новых компонентов.
