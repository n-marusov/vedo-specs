## Назначение

Зафиксировать жёсткие ограничения, накладываемые On-premise развёртыванием VEDO на AI-функции.

## Ограничения

1. **Внешние LLM-провайдеры недоступны по сети.**

   On-premise развёртывание предполагает сетевую политику, запрещающую исходящий трафик к внешним LLM-провайдерам (OpenAI, Anthropic). VEDO не проверяет доступность внешних провайдеров и не пытается к ним обращаться.

2. **Только локальная LLM.**

   Все AI-функции (NL→OWL, NL-запросы, AI-подсказки) используют исключительно локальную LLM, развёрнутую клиентом внутри периметра. Конфигурация — через переменные окружения (см. `REQ-DEPLOY.AI.on-premise-local-llm`).

3. **Клиентская ответственность за LLM.**

   Развёртывание, обновление, мониторинг и поддержка локальной LLM — ответственность клиента. VEDO документирует требования к API-совместимости (OpenAI-compatible `/v1/chat/completions`) и рекомендуемые модели, но не управляет жизненным циклом LLM.

4. **Нет opt-in / consent диалогов.**

   Поскольку данные онтологии не покидают периметр клиента, диалоги consent для внешних LLM не отображаются. Пользователь не видит предупреждений о передаче данных.

5. **AI-функции недоступны без настроенной LLM.**

   Если `VEDO_LLM_LOCAL_ENDPOINT` не сконфигурирован, все AI-функции недоступны. Система возвращает `LLM_LOCAL_NOT_CONFIGURED`. Администраторские настройки разрешения внешних LLM скрыты.

## Критерии приёмки

1. В on-premise нет возможности использовать внешние LLM-провайдеры.
2. При попытке обратиться к внешнему провайдеру — ошибка конфигурации или сети.
3. Документация Admin Guide включает раздел по развёртыванию локальной LLM.
4. Без настроенной локальной LLM AI-функции возвращают `LLM_LOCAL_NOT_CONFIGURED`.
5. Consent-диалоги не отображаются в on-premise.
