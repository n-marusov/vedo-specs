## Назначение

Определить способ упаковки и развёртывания сервисов VEDO Core.

## Требование

Все сервисы VEDO Core должны быть контейнеризированы. Контейнеризация обеспечивает:
- Единый способ развёртывания на всех этапах (разработка, тестирование, production)
- Изоляцию сервисов
- Воспроизводимость окружения
- Согласованные версии runtime-зависимостей

Для локальной разработки и тестирования требуется поддержка оркестрации нескольких контейнеров (docker-compose или аналогичный инструмент).

## Проверка сборки Docker-образов

### Индивидуальная проверка после реализации каждого сервиса или заглушки

После завершения реализации каждого сервиса или заглушки (включая, но не ограничиваясь: auth-service, api-gateway, ontology-service, versioning-service, metrics-service, antora-docs, frontend) должна производиться обязательная проверка успешной сборки его Docker-образа.

- Проверка выполняется командой `docker build` с использованием Dockerfile сервиса.
- Сборка считается успешной, если образ собирается без ошибок и exit-код равен 0.
- Результат проверки фиксируется в протоколе валидации.

### Окончательная проверка сборки и развёртывания

После реализации всех сервисов и заглушек текущей вехи должна производиться окончательная проверка сборки всех образов и локального развёртывания через docker-compose:

1. `docker compose build --parallel` — сборка всех образов, определённых в docker-compose.yml.
2. `docker compose up -d` — запуск стека.
3. Health check каждого сервиса — все сервисы должны ответить HTTP 200 на endpoint здоровья в течение таймаута (120 секунд).
4. `docker compose down` — остановка стека.

Окончательная проверка является интеграционным тестом и фиксируется в test-specs соответствующей вехи.

## Расположение конфигурации сборки и развёртывания

Настройки сборки Docker-образов (Dockerfile, .dockerignore) и развёртывания docker-compose (docker-compose.yml, сопутствующие файлы) должны храниться в папке `./deploy` на всех вехах и этапах проекта, начиная с инициализации.

- `deploy/docker-compose.yml` — основной файл оркестрации.
- `deploy/docker-compose.observability.yml` — расширение для стека наблюдаемости.
- `deploy/helm/` — Helm-чарты для Kubernetes-развёртывания.
- Dockerfile каждого сервиса находится в его директории в `llm/src/`, путь к нему указывается в `context` и `dockerfile` полях docker-compose.yml.

Это обеспечивает единую точку входа для локальной разработки, CI/CD и аудита конфигурации развёртывания.
