## SaaS (мультитенант) — P0 MVP

### Архитектура

- Одна инсталляция в облаке (AWS, Azure, Yandex Cloud)
- Мультитенантность через изоляцию на уровне `ontology_id` и `user_id`
- Keycloak для управления пользователями (общий на всех тенантов)
- Neo4j, PostgreSQL, Redis — общие кластеры с логическим разделением

### Изоляция данных

| Ресурс | Способ изоляции |
|--------|----------------|
| TBox | Namespace + префикс: `tenant_123/Person` |
| ABox | Таблицы с колонкой `tenant_id` |
| Коммиты, ветки | `ontology_id` как внешний ключ |
| Пользователи и роли | Keycloak realm per tenant или группы |

### Ограничения SaaS

- Нет доступа к raw-логам (только через API)
- Нет возможности установить свой SSL-сертификат
- Общий лимит на квоты (диск, соединения)
- Нет on-premise агентов для локальных данных

## On-premise — P2 Enterprise

### Требования к инфраструктуре заказчика

**Минимальные (proof-of-concept):**
- 4 vCPU, 16 GB RAM, 100 GB SSD
- PostgreSQL 15+
- Neo4j 5+ (Enterprise или Community)
- Redis 7.2+
- MinIO или S3-совместимое хранилище

**Production (100 пользователей):**
- 8 vCPU, 32 GB RAM, 500 GB SSD (K8s, 3 узла)
- PostgreSQL кластер (primary + replica)
- Neo4j кластер (3 core + 2 read replica)
- Redis кластер (3 master + 3 replica)
- MinIO кластер (4 узла)

### Поставка VEDO

| Компонент | Поставляется VEDO | Управляется заказчиком |
|-----------|-------------------|------------------------|
| vedo-core образы (Docker) | ✅ | Нет (исполняется) |
| Helm-чарты | ✅ | Нет (применяются) |
| Neo4j, PostgreSQL, Redis | Нет | ✅ Да |
| MinIO / S3 | Нет | ✅ Да |
| Observability stack (OpenTelemetry Collector, Prometheus, Grafana, Loki, Tempo) | ✅ Да | ✅ Эксплуатация и альтернативные backend по выбору заказчика |

### Лицензирование

- Лицензионный ключ, проверяемый через локальный сервис
- Возможна периодическая проверка через интернет (но не обязательно)

## Приватное облако — P3

### Варианты

| Вариант | Описание |
|---------|----------|
| **VEDO Managed** | Заказчик предоставляет bare metal/VMs/k8s, VEDO разворачивает и обслуживает |
| **Co-Managed** | Заказчик обновляет сам, VEDO помогает с апгрейдами |
| **BYOC** | Заказчик запускает SaaS-код в своём облаке, лицензия центральная |

## География развёртывания и резидентность данных

VEDO Core использует стратегию один код, разные регионы. География развёртывания задаётся конфигурацией и требованиями заказчика, а не отдельной веткой продукта.

| Регион | Статус | Основные требования | Рекомендуемые провайдеры |
|--------|--------|---------------------|--------------------------|
| Россия | MVP | Данные и ПДн на территории РФ, 152-ФЗ, ФСТЭК для госзаказчиков | Yandex Cloud, VK Cloud, Selectel |
| ЕС | P2 | GDPR, хранение ПДн в ЕС, DPA, data portability | AWS Frankfurt, Azure Germany, Google Cloud Frankfurt |
| США | P2 | Cloud Act awareness, HIPAA при медицинских данных, SOC 2 Type II для enterprise | AWS us-east-1, Google Cloud us-central1 |
| Другие страны | По запросу | Legal review и локальная адаптация | AWS, Azure или локальный провайдер |

ПДн пользователей и логи не синхронизируются между регионами. Обезличенные TBox модели могут синхронизироваться по согласованию.

Подробная политика зафиксирована в `human/artifacts/requirements/REQ-CON.INFRA.deployment-geography.md`.

## Развёртывание в изолированном контуре

VEDO Core поддерживает работу в on-premise air-gapped environment без доступа в интернет.

| Аспект | Решение |
|--------|---------|
| Лицензирование | MIT, online license server не требуется |
| Runtime | Сервисы не должны требовать outbound internet access |
| Installation | Images загружаются в локальный registry: Harbor, Nexus или аналог |
| Helm | Charts устанавливаются из локальной директории или локального mirror |
| Telemetry | Внешняя telemetry и version checks отключаются через offline mode |
| Alerts | PagerDuty/Slack недоступны; используется SMTP внутри контура |
| Backup | Local storage или in-perimeter MinIO/S3-compatible storage |

Подробная политика зафиксирована в `human/artifacts/requirements/REQ-CON.INFRA.air-gapped-deployment.md`.

## Sustainability & Energy Efficiency

Экологические требования не являются блокирующими для MVP, но учитываются как enterprise differentiator и подготовка к зелёным критериям в корпоративных и государственных закупках.

| Метрика | Цель |
|---------|--------|
| Energy per Request | < 0.5 J/request |
| Carbon per User per Month | < 100 g CO2e |
| Idle energy / peak energy | < 30% |
| Average CPU utilization | > 40% |

Для enterprise deployments VEDO может включать Kepler/Scaphandre metrics, Grafana dashboards и monthly SCI/carbon footprint reports.

Подробная политика зафиксирована в `human/artifacts/requirements/REQ-NFR.INFRA.sustainability-energy-efficiency.md`.
