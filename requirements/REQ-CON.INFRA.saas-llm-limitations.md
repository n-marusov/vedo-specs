## Назначение

Зафиксировать жёсткие ограничения, накладываемые SaaS-развёртыванием VEDO на AI-функции.

## Ограничения

1. **Локальная LLM не предоставляется в SaaS.**

   VEDO в SaaS-развёртывании **не разворачивает** и **не управляет** локальными LLM-моделями. Все AI-функции используют только внешних LLM-провайдеров (OpenAI, Anthropic и другие, сконфигурированные в tenant).

2. **Внешние LLM для Internal/Private по умолчанию заблокированы.**

   Для онтологий с уровнем видимости Internal или Private в SaaS внешние LLM-провайдеры **заблокированы по умолчанию**. Администратор может сознательно разрешить (см. `REQ-FUN.UI.external-llm-override`).

3. **Нет гарантии изоляции данных внешнего провайдера.**

   VEDO не контролирует, как внешний LLM-провайдер обрабатывает переданные данные. Политика использования данных определяется соглашением между VEDO и провайдером, но VEDO не может гарантировать, что провайдер не использует данные для обучения моделей. Это явно доводится до пользователя в диалоге consent.

4. **Доступность внешних провайдеров не гарантируется.**

   VEDO не гарантирует SLA на доступность внешних LLM-провайдеров. При недоступности провайдера AI-функции возвращают ошибку `LLM_PROVIDER_UNAVAILABLE`.

## Критерии приёмки

1. В SaaS нет возможности подключить локальную LLM (конфигурация `local.enabled=false` по умолчанию).
2. При попытке использовать локальную LLM в SaaS — ошибка конфигурации.
3. Документация явно разделяет SaaS и on-premise возможности.
4. Для Internal/Private без административного разрешения AI-функции возвращают `LLM_BLOCKED_BY_POLICY`.
