## Назначение

Определить, как выбирать языки реализации для каждого микросервиса VEDO Core в зависимости от профиля нагрузки.

## Требование

Для каждого микросервиса VEDO Core выбрать язык реализации, оптимально соответствующий его профилю нагрузки:

- **CPU-интенсивные сервисы** (Ontology Service — graph CRUD, OWL/RDF операции до 1M триплетов; Versioning Service — diff/merge, коммиты, ветки): требуют максимальной производительности, zero-cost abstractions, предсказуемой latency без GC-пауз.
- **I/O-bound сервисы** (Auth Service — high-rate HTTP, JWT, OAuth): требуют лёгкой модели конкурентности, эффективной обработки множества соединений.
- **Analytics/aggregation сервисы** (Metrics Service — сбор метрик, агрегация, аналитика): latency не критичен, важна скорость разработки и богатая экосистема для data processing.

## Обоснование

Разные профили нагрузки требуют разных языковых экосистем. Использование одного языка для всех сервисов приводит к неоптимальной производительности или избыточной сложности.
