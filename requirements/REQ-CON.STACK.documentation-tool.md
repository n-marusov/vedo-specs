## Назначение

Определить инструмент для генерации и управления документацией VEDO Core.

## Требование

VEDO Core требует несколько классов документации: пользовательские инструкции, административные и on-premise runbooks, руководства по развёртыванию в изолированном контуре, API-документацию, архитектурные справочники, ADR, release notes и LTS-документацию для корпоративных клиентов.

Инструмент документации должен обеспечивать:
- **Отдельный сайт для каждого типа документации** — каждый класс собирается как самостоятельный статический сайт и запускается в отдельном сервисе docker-compose. Это необходимо для:
  - **Разграничения доступа**: пользовательский сайт доступен без аутентификации, административные и операционные runbooks требуют входа, API-документация доступна по роли Developer. Единый сайт не позволяет гибко применять разные политики доступа к разным разделам.
  - **Эргономики пользователей**: администратору не нужно пролистывать пользовательские инструкции, а разработчику — операционные runbooks. Раздельные сайты сокращают время поиска и уменьшают когнитивную нагрузку.
- Версионирование документации по релизам
- Cross-references между модулями и между сайтами
- Сборку в CI
- Offline-поставку для air-gapped environments
- Поддержку AsciiDoc или аналогичного формата для больших технических документов

## Реализация — Antora

Выбранный инструмент: **Antora**. Исходные файлы документации хранятся в `docs/antora/` и организованы в четыре компонента по аудиториям:
- `user-guide/` — конечные пользователи
- `developer-guide/` — разработчики и архитекторы
- `admin-guide/` — DevOps и администраторы
- `integrator-guide/` — разработчики-интеграторы

Каждый компонент собирается в **отдельный статический сайт** через собственный Antora playbook (`playbook-user.yml`, `playbook-dev.yml`, `playbook-admin.yml`, `playbook-integrator.yml`). Каждый сайт запускается как **отдельный сервис** в docker-compose со своим health endpoint. Это обеспечивает:
- Изолированное разграничение доступа: nginx/api-gateway направляет запросы к нужному сайту, применяя разные политики аутентификации.
- Независимое масштабирование и обновление каждого сайта без влияния на остальные.
- Адресацию по отдельным URL: `/docs/user/`, `/docs/admin/`, `/docs/dev/`, `/docs/integrator/`.

Подробная инструкция по обновлению документации при изменении артефактов — в `docs/antora/update.md`.

## Связь с артефактами

При изменении артефактов проекта (`human/artifacts/`, `human/contracts/` и др.) документация обновляется автоматически по инструкции в `docs/antora/update.md`.
