# Аудит LLM-вызовов

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-DATA.AI.llm-audit |
| **Уровень** | NFR |
| **Атрибут качества** | Supportability |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.1 матрицы качества M2 |
| **Связанные REQ** | `REQ-DATA.AI.llm-policy` |

---

## Назначение

Обеспечить полный аудит всех LLM-вызовов для compliance, расследования инцидентов и мониторинга использования.

## Требование

Каждый LLM-вызов (NL→OWL, NL-режим запросов, AI-подсказки) создаёт audit-запись со следующими полями:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор записи |
| `user_id` | UUID | Кто инициировал вызов |
| `ontology_id` | UUID | Идентификатор онтологии |
| `visibility_level` | ENUM | `public` / `internal` / `private` |
| `deployment_type` | ENUM | `saas` / `on-premise` |
| `provider` | TEXT | Использованный LLM-провайдер |
| `action` | ENUM | `nl_to_owl` / `nl_query` / `suggestion` |
| `timestamp` | TIMESTAMPTZ | Время вызова |
| `trace_id` | TEXT | OpenTelemetry trace_id для корреляции |
| `status` | ENUM | `success` / `blocked_by_policy` / `error` / `consent_denied` |
| `reason` | TEXT | Причина блокировки (если `blocked_by_policy`) |
| `admin_override` | BOOLEAN | Было ли использовано административное разрешение |
| `input_tokens` | INTEGER | Количество токенов на входе |
| `output_tokens` | INTEGER | Количество токенов на выходе |
| `duration_ms` | INTEGER | Длительность LLM-вызова в миллисекундах |
| `consent_id` | UUID | Ссылка на запись согласия пользователя (если применимо) |

**Запрещено логировать:**

- Полный текст NL-запроса (только хеш `query_hash`).
- Структуру онтологии (классы, свойства).
- Ответ LLM (только хеш `response_hash`).

**Срок хранения:**

Audit-записи хранятся минимум 90 дней. Для SaaS — срок определяется тарифным планом tenant (минимум 90 дней, до 365 дней для Enterprise).

**Доступ к логам:**

- Администратор tenant имеет доступ к логам своего tenant.
- Пользователь имеет доступ к логам своих действий.
- Администратор VEDO имеет доступ ко всем логам (для SaaS — с ограничением по внутренней политике).

## Критерии приёмки

1. Каждый LLM-вызов создаёт audit-запись.
2. Все обязательные поля заполнены.
3. Audit-логи не содержат конфиденциальных данных онтологии.
4. Поиск по `user_id`, `ontology_id`, `trace_id`, `visibility_level`, `deployment_type` работает.
5. Блокировки по политике логируются с указанием причины.
6. Доступ к логам разграничен по ролям.
7. Срок хранения соблюдается.
