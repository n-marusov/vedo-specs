## Назначение

Определить порядок подключения и требования к локальной LLM для on-premise развёртывания VEDO.

## Требование

**Модель ответственности:**

Клиент самостоятельно разворачивает локальную LLM внутри своего сетевого периметра и указывает URL эндпоинта в конфигурации VEDO. Обновление модели LLM — ответственность клиента, вне рамок VEDO.

**Поддерживаемые модели (документированы для совместимости):**

- Llama 3.x (70B или эквивалент по качеству)
- Qwen 2.5 (72B или эквивалент)
- Mistral Large (или эквивалент)

Минимальные требования к модели: поддержка OpenAI-compatible API (`/v1/chat/completions`), функциональность tool-calling для MCP-инструментов.

**Конфигурация (переменные окружения):**

```bash
VEDO_LLM_LOCAL_ENDPOINT=http://local-llm.internal:8080/v1
VEDO_LLM_LOCAL_MODEL=llama3-70b
VEDO_LLM_LOCAL_API_KEY=  # опционально
```

**Поведение при отсутствии конфигурации:**

Если `VEDO_LLM_LOCAL_ENDPOINT` не задан в on-premise развёртывании, все AI-функции (NL→OWL, NL-запросы, AI-подсказки) недоступны. Система возвращает ошибку `LLM_LOCAL_NOT_CONFIGURED` с сообщением: «AI-функции недоступны: не настроена локальная LLM. Обратитесь к администратору.»

**Сетевые ограничения:**

Предполагается, что сетевая политика on-premise запрещает исходящий трафик к внешним LLM-провайдерам. VEDO не проверяет доступность внешних провайдеров в on-premise.

## Критерии приёмки

1. Документация по развёртыванию локальной LLM включена в Admin Guide.
2. Конфигурация LLM осуществляется через переменные окружения.
3. При отсутствии конфигурации AI-функции возвращают понятную ошибку.
4. Ведётся changelog поддерживаемых моделей (какие версии протестированы).
5. При обновлении VEDO — release notes включают информацию о совместимости с версиями LLM.
