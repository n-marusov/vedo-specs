## Назначение

Определить порядок поддержки CYPHER как второго языка запросов к графу знаний VEDO Core, наравне с SPARQL 1.1.

## Требование

VEDO Core должен предоставлять CYPHER как нативный язык запросов к графу знаний (Neo4j) в трёх режимах:

- **Визуальный конструктор:** пользователь выбирает метку узла, тип связи, целевой узел и фильтры; система генерирует MATCH/RETURN запрос.
- **Текстовый редактор:** подсветка синтаксиса, автодополнение меток узлов, типов связей и свойств текущей онтологии, синтаксическая валидация без выполнения.
- **NL-режим (кнопка «Микрофон»):** пользователь вводит запрос на естественном языке; VEDO отправляет его LLM-провайдеру (с явным opt-in), получает сгенерированный CYPHER и подставляет в текстовый редактор для выполнения.

Endpoint `/api/v1/cypher` реализуется по тому же шаблону, что и `/api/v1/sparql`:

- Read-only (только MATCH/RETURN)
- Аутентификация и авторизация
- Обязательный LIMIT
- Timeout выполнения
- Rate limiting (раздельные метрики по endpoint'ам)
- Анализ query complexity
- Аудит запросов

Результаты CYPHER-запросов отображаются в едином формате с SPARQL-запросами: таблица (для RETURN) или граф (для MATCH-path) с экспортом в CSV, JSON, Turtle.

Introspection онтологии расширяется для поддержки меток узлов и типов связей (для CYPHER) наравне с классами и свойствами RDF.

Библиотека запросов должна поддерживать поле `query_type` для различия языков (SPARQL/CYPHER).
