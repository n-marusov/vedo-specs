## Подход

gRPC API сохраняет совместимость по правилам Protocol Buffers.

## Правила изменения protobuf

| Правило | Разрешено в минорной версии | Разрешено в мажорной версии |
|---------|----------------------------|----------------------------|
| Добавить новое поле с новым field number | Да | Да |
| Удалить поле | Нет | Да, только если пометить `reserved` |
| Изменить тип поля | Нет | Нет, даже в мажорной версии; нужно создавать новое поле |
| Переименовать поле | Да, с сохранением field number | Да, с сохранением field number |

## Совместимое изменение

```protobuf
message Class {
  string id = 1;
  string label = 2;
  string comment = 3;
}
```

## Несовместимое изменение

Удаление поля без резервирования номера ломает клиентов v1:

```protobuf
message Class {
  string id = 1;
}
```

## Правильное удаление поля

```protobuf
message Class {
  string id = 1;
  reserved 2;
  reserved "label";
  string display_name = 3;
}
```
