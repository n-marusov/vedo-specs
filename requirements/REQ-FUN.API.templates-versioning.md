## Назначение

Определить правила семантического версионирования шаблонов.

## Требование

Версионирование шаблонов следует semver (MAJOR.MINOR.PATCH):

| Уровень | Изменение | Пример |
|---------|-----------|--------|
| **MAJOR** (1.x.x) | Несовместимые изменения структуры. Удаление классов/свойств, изменение IRI, изменение иерархии | Удалён класс `Department`, переименован `Employee` → `Worker` |
| **MINOR** (x.1.x) | Добавление новых классов/свойств (обратная совместимость). Новые аксиомы, аннотации | Добавлен класс `Contractor`, свойство `hasSkill` |
| **PATCH** (x.x.1) | Исправление ошибок (label, comment, документация). Без изменения структуры | Исправлена опечатка в `rdfs:label`, обновлён README |

**Поведение при обновлении шаблона:**
- **PATCH/MINOR:** Существующие онтологии, созданные из шаблона, не затрагиваются. Пользователь видит уведомление о новой версии и может обновиться.
- **MAJOR:** Существующие онтологии продолжают работать. Пользователь видит уведомление, но автоматическое обновление не предлагается.

## Критерии приёмки

1. Версия шаблона соответствует semver (MAJOR.MINOR.PATCH).
2. MAJOR инкрементируется при несовместимых изменениях (удаление/переименование классов).
3. MINOR инкрементируется при добавлении классов/свойств (обратная совместимость).
4. PATCH инкрементируется при исправлении документации/аннотаций.
5. Пользователь видит changelog при выборе шаблона.
