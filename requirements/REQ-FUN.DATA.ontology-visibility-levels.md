| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-FUN.DATA.ontology-visibility-levels |
| **Уровень** | FUN |
| **Атрибут качества** | Functionality |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.1 матрицы качества M2 |
| **Связанные ADR** | `ADR-DES.SECURITY.gitlab-like-organization-model` |

---

## Назначение

Определить уровни видимости онтологий, влияющие на политику использования LLM для AI-функций (NL→OWL, NL-запросы, AI-подсказки связей).

## Требование

При создании онтологии пользователь обязан выбрать один из трёх уровней видимости (аналогично модели видимости проектов GitLab):

| Уровень | Определение | Кто имеет доступ |
|---------|-------------|-------------------|
| **Public** | Публичная онтология | Все пользователи без авторизации |
| **Internal** | Внутренняя онтология | Все аутентифицированные пользователи VEDO |
| **Private** | Приватная онтология | Только владелец и члены команды |

Уровень видимости сохраняется в метаданных онтологии (`visibility TEXT CHECK (visibility IN ('public', 'internal', 'private'))`) и определяет политику использования LLM (см. `REQ-FUN.API.llm-policy`).

При выборе уровня видимости система отображает описание последствий для AI-функций:

- **Public:** «AI-функции доступны. В SaaS данные онтологии будут передаваться внешнему LLM-провайдеру.»
- **Internal:** «AI-функции доступны. В SaaS внешние LLM-провайдеры по умолчанию заблокированы — администратор может разрешить.»
- **Private:** «AI-функции доступны. В SaaS внешние LLM-провайдеры по умолчанию заблокированы — администратор может разрешить.»

## Критерии приёмки

1. При создании онтологии отображается выбор уровня: Public / Internal / Private.
2. При выборе уровня отображается описание последствий для AI-функций.
3. Система сохраняет классификацию в метаданных онтологии.
4. Изменение уровня онтологии после создания требует подтверждения и логируется в audit.
5. Уровни видимости согласованы с моделью доступа из `ADR-DES.SECURITY.gitlab-like-organization-model`.
