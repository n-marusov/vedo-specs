# Уровни видимости Project (и его Ontology) для AI-функций

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-FUN.DATA.ontology-visibility-levels |
| **Уровень** | FUN |
| **Атрибут качества** | Functionality |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.1 матрицы качества M2 |
| **Связанные ADR** | `ADR-DES.SECURITY.gitlab-like-organization-model`, `ADR-DES.API.organization-rest-endpoints` |

---

## Назначение

Определить уровни видимости **Project**, которые применяются к содержимому paired Ontology через 1:1-связь и влияют на политику использования LLM для AI-функций (NL→OWL, NL-запросы, AI-подсказки связей).

## Требование

При создании Project (и его paired Ontology) пользователь обязан выбрать один из трёх уровней видимости (аналогично модели видимости проектов GitLab). Visibility хранится на Project; Ontology наследует её через 1:1-связь.

| Уровень | Определение | Кто имеет доступ |
|---------|-------------|-------------------|
| **Public** | Публичный Project (и его Ontology) | Все пользователи без авторизации |
| **Internal** | Внутренний Project (и его Ontology) | Все аутентифицированные пользователи VEDO |
| **Private** | Приватный Project (и его Ontology) | Только владелец и члены команды |

Уровень видимости сохраняется в метаданных Project — на строке `scopes` с `type='project'` (`visibility TEXT CHECK (visibility IN ('public', 'internal', 'private'))`), не на отдельной строке онтологии — и определяет политику использования LLM (см. `REQ-FUN.API.llm-policy`). Политика применяется к содержимому Ontology через 1:1-связь.

При выборе уровня видимости система отображает описание последствий для AI-функций:

- **Public:** «AI-функции доступны. В SaaS данные онтологии будут передаваться внешнему LLM-провайдеру.»
- **Internal:** «AI-функции доступны. В SaaS внешние LLM-провайдеры по умолчанию заблокированы — администратор может разрешить.»
- **Private:** «AI-функции доступны. В SaaS внешние LLM-провайдеры по умолчанию заблокированы — администратор может разрешить.»

## Критерии приёмки

1. При создании Project (и его paired Ontology) отображается выбор уровня: Public / Internal / Private.
2. При выборе уровня отображается описание последствий для AI-функций.
3. Система сохраняет классификацию в метаданных Project (строка `scopes` с `type='project'`); Ontology наследует видимость через 1:1-связь.
4. Изменение уровня видимости Project после создания требует подтверждения и логируется в audit.
5. Уровни видимости согласованы с моделью доступа из `ADR-DES.SECURITY.gitlab-like-organization-model` и REST-контрактом из `ADR-DES.API.organization-rest-endpoints`.
