## Назначение

Фиксирует требования к проверке версии и checksum артефактов на production-узлах, защите от частичного выката, управлению stale feature flags и dead code. Закрывает ячейки `1.1` и `5.1`.

Пробел: риск частичного выката (Knight Capital 2013 — 1 из 8 серверов с устаревшим кодом), stale flags и dead code.

## Проверка версии и checksum на узлах

Система развёртывания должна проверять версию и checksum артефакта на 100% production-узлов перед переключением трафика.

### Критерий приёмки

- Каждый узел сообщает digest артефакта до переключения трафика.
- Версия и checksum сверяются с эталонными из CI/CD pipeline.
- Релиз блокируется, если хотя бы один узел сообщает отличающуюся версию, отсутствующий артефакт или непрошедший smoke test.

### Метод проверки

- Deployment integration test.
- Immutable deployment evidence.

## Защита от частичного выката

Переключение трафика на новую версию происходит только после подтверждения идентичности артефакта на всех узлах.

### Поведение

1. CI/CD пайплайн разворачивает артефакт на всех целевых узлах (rolling update или parallel deploy).
2. Каждый узел выполняет checksum-верификацию после развёртывания.
3. Пайплайн собирает результаты со всех узлов.
4. Если все checksums совпадают — переключение трафика разрешено.
5. Если хотя бы один checksum не совпадает — релиз блокируется, выкат откатывается автоматически.

### Критерий приёмки

- Нулевая толерантность к расхождению версий на узлах.
- Время от обнаружения расхождения до автоматического отката — ≤ 5 минут.
- Уведомление ответственной команды при блокировке релиза.

## Stale feature flags и dead code

Feature flags старше установленного срока должны иметь owner, expiry date и automated cleanup issue.

### Требования

| Характеристика | Требование |
|----------------|------------|
| Owner | Каждый feature flag имеет назначенного владельца |
| Expiry date | Каждый feature flag имеет срок действия (max 90 дней для временных flags) |
| Automated cleanup | CI gate проверяет флаги с истёкшим сроком; создаёт issue на удаление |
| Dead code detection | Код, скрытый за feature flag с истёкшим сроком, помечается как dead code |

### Критерий приёмки

- CI пайплайн блокирует merge request, если feature flag просрочен и не имеет active owner.
- Dead code составляет не более 5% от общего объёма кодовой базы (метрика измеряется ежеквартально).

## Immutable deployment evidence

Каждый production deployment фиксируется автоматически CI/CD пайплайном без возможности ручного пропуска.

Состав evidence и требования к хранению описаны в `ci-cd-procedures.md`.

## CI/CD gates

| Gate | Проверка | Блокирует |
|------|----------|-----------|
| G-1 | Checksum verification на 100% узлов | Да — переключение трафика |
| G-2 | Smoke test на каждом узле | Да — переключение трафика |
| G-3 | Stale feature flags audit | Да — merge request |
| G-4 | Dead code ratio ≤ 5% | Да — квартальный релиз |

## Drill-сценарии

| ID | Сценарий | Ожидаемый результат |
|----|----------|---------------------|
| DI-1 | Partial rollout: 1 узел с отличающейся версией | Релиз заблокирован, автоматический откат ≤ 5 мин |
| DI-2 | Stale feature flag без owner | Merge request заблокирован, создан cleanup issue |
| DI-3 | Dead code превышает 5% | Квартальный релиз заблокирован до рефакторинга |
| DI-4 | Smoke test failed на одном узле | Релиз заблокирован, откат до предыдущей версии |

## Бизнес-правила

- Checksum-верификация на 100% узлов обязательна перед каждым переключением трафика.
- Расхождение версий на любом узле блокирует релиз и инициирует автоматический откат.
- Feature flags имеют срок действия не более 90 дней; owner назначается при создании.
- CI/CD gate для stale flags запускается при каждом merge request в main.
- Dead code ratio измеряется ежеквартально; превышение 5% блокирует квартальный релиз.
- Deployment evidence (версия, checksum, узлы, результат smoke test) фиксируется автоматически для каждого релиза.
- Ручной пропуск gates или post-factum evidence запрещён.
