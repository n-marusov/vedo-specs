## Назначение

Определить требования к обеспечению консистентности данных при межсервисных операциях в микросервисной архитектуре VEDO Core.

## Требование

VEDO Core — микросервисная архитектура с 6+ сервисами и раздельными БД (Neo4j, PostgreSQL, Redis, RabbitMQ). Некоторые логические операции требуют согласованных изменений в двух или более независимых хранилищах.

Требуется механизм распределённой транзакции для операций, где распределённая консистентность критична:
- Rollback (откат коммита) — затрагивает Versioning Service и Ontology Service
- Import + Auto-Commit — затрагивает Ontology Service и Versioning Service

Для остальных потоков (publish snapshot, access control) допустима согласованность в конечном счёте (eventual consistency) без координации.

Механизм должен:
- Не блокировать ресурсы (в отличие от 2PC)
- Обеспечивать идемпотентность шагов
- Иметь детерминированный поток с единой точкой мониторинга
- Поддерживать компенсирующие транзакции для отката при сбоях
