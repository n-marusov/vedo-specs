## Назначение

Определить способ декомпозиции VEDO Core на сервисы с учётом доменных границ, профиля нагрузки и требований к масштабированию.

## Требование

Архитектура VEDO Core должна быть декомпозирована по доменному принципу на независимые сервисы, каждый из которых отвечает за отдельную зону ответственности:

- **Graph Operations** — хранение и запросы графов до 1M триплетов
- **Version Control** — Git-подобное версионирование (коммиты, ветки, diff, merge)

Декомпозиция должна обеспечивать:
- Независимое масштабирование сервисов
- Изоляцию отказов между доменами
- Возможность использования оптимального языка/стека для каждой зоны ответственности
- Domain-driven ownership

## Обоснование

Монолитная архитектура страдает от проблем производительности при масштабировании, единая кодовая база создаёт merge-конфликты, а общая БД — связанность между доменами.
