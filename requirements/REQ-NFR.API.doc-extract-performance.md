## Назначение

Определить требования к производительности извлечения онтологии из документов.

## Требование

Система должна удовлетворять следующим показателям производительности:

| Параметр | Значение | Примечание |
|----------|----------|------------|
| **Максимальный размер файла** | 20 MB | Для файлов больше 20 MB — асинхронный режим (20+ MB → async task) |
| **Максимальное количество страниц (PDF/DOCX)** | 200 страниц | Для документов >200 стр. — чанкинг + multi-step LLM |
| **Максимальное количество классов в sequence** | 500 | Лимит на одну загрузку |
| **Максимальное количество шагов в sequence** | 2000 | Ограничение gRPC message size |
| **Латентность LLM (p95)** | < 30 секунд | Для документа до 50 стр. |
| **Латентность парсинга (p95)** | < 5 секунд | Для PDF/DOCX до 100 стр. |
| **Латентность gRPC ApplySequence (p95)** | < 3 секунд | Для sequence до 500 шагов |
| **Preview latency (p95)** | < 2 секунд | Время от подтверждения до отображения preview |
| **Async threshold** | > 20 MB или > 200 стр. | Переключение на асинхронный режим с уведомлением |

## Критерии приёмки

1. Документ до 20 MB и 200 стр. обрабатывается синхронно (пользователь ждёт результат).
2. Документ больше 20 MB или 200 стр. — асинхронный режим с прогрессом и уведомлением.
3. Sequence из 500 шагов применяется через ApplySequence за < 3 секунд (p95).
4. При превышении лимита классов/шагов — сообщение пользователю с предложением разбить документ.
