## Обзор

VEDO Core использует многоформатную политику резервного копирования. Один универсальный формат не подходит, потому что разные данные требуют разного баланса между скоростью восстановления, размером, переносимостью и инспектируемостью.

## Политика форматов

| Компонент | Формат резервной копии | Сжатие | Инспектируемость | Основная цель |
|-----------|---------------|--------|------------------|---------------|
| TBox | Канонический Turtle (`.ttl`) | `gzip` | Да | Переносимость, аудит, Git-diff |
| ABox full | Neo4j binary dump (`.dump`) | `zstd` | Нет | Быстрое восстановление |
| ABox incremental | WAL / transaction logs | Опционально на уровне ФС | Нет | Восстановление на момент времени |
| Version Store | `pg_dump -Fc` + PostgreSQL WAL | `gzip` для dumps | Частично | Надёжное восстановление PostgreSQL |
| LFS-объекты | Сырые файлы в object storage | По политике storage | Нет | Прямая замена / versioning |
| Аудиторские выгрузки | JSON-L / structured export | `gzip` | Да | Проверка и расследования, не primary restore |

## Административный интерфейс

`vedo-cli` является обязательным административным интерфейсом для операций backup/restore в VEDO Core. Он должен создавать full snapshots, собирать incremental/WAL артефакты, возвращать backup ID и выполнять `backup verify` как обязательный шаг успешного backup.

Прямое production-выполнение `neo4j-admin`, `pg_dump`, S3/MinIO clients или custom scripts допустимо только как внутренняя реализация `vedo-cli` либо как согласованный break-glass процесс с audit log.

## TBox

TBox backup хранится как canonical Turtle. Каноническая сериализация обязательна, чтобы обеспечить стабильный diff, предсказуемые коммиты и совместимость с внешними RDF/OWL-инструментами.

Основные сценарии использования:

- восстановление схемы онтологии;
- аудит изменений схемы;
- интеграция с Git workflow;
- переносимость в Protégé, OWL API и другие RDF-инструменты.

## ABox

ABox backup делится на два слоя:

- полный Neo4j dump для быстрого восстановления после аварии;
- WAL / incremental logs для point-in-time recovery в пределах retention window.

Полный dump является primary restore artifact. WAL без полного dump не считается достаточным backup.

## Version Store

Version Store хранится через `pg_dump` в custom format (`-Fc`) и PostgreSQL WAL. Custom format нужен для выборочного восстановления таблиц, например коммитов, веток или метаданных конкретной онтологии.

## LFS-объекты

LFS-объекты хранятся как сырые объекты в S3/MinIO-compatible storage. Backup опирается на синхронизацию buckets и object versioning. Дополнительная упаковка бинарных файлов не требуется.

## Аудиторские выгрузки

Аудиторские события могут дополнительно выгружаться в JSON-L или другой structured text format для инспекции регулятором или командой безопасности. Эти выгрузки не заменяют primary backup format и не используются как основной механизм восстановления.

## Не входит в цели

- Canonical Turtle не используется как единственный backup для ABox.
- WAL не используется без регулярных full snapshots.
- JSON-L audit export не является резервной копией для аварийного восстановления.
