## Цель

После тестовой и production migration нужно подтвердить, что данные не потеряны и не повреждены.

## Проверки после миграции

- Количество классов: `MATCH (c:Class) RETURN count(c)` должно совпадать с production до миграции.
- Количество свойств: `MATCH (p:Property) RETURN count(p)` должно совпадать.
- Количество индивидов: `MATCH (i:Individual) RETURN count(i)` должно совпадать.
- История коммитов: `SELECT COUNT(*) FROM commits` должно совпадать.
- Выборочная сверка: 10 случайных классов не имеют различий по SPARQL-запросам.

Для быстрой автоматической проверки Neo4j используется сравнение хэша всех узлов:

```cypher
MATCH (n)
RETURN apoc.util.md5(apoc.text.join(COLLECT(n.id), ',')) AS hash
```

## Пост-миграционная проверка

- Синтетические проверки: выполнение набора SPARQL-запросов сразу после миграции.
- Сравнение с бэкапом: выборочная сверка 100 случайных объектов в течение 24 часов.
- Мониторинг ошибок: проверка логов и метрик Prometheus первые 48 часов.
- План отката: если обнаружены критические проблемы, откат на v1 в течение 1 часа.
