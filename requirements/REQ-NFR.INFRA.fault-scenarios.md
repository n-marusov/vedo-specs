## Матрица отказов сервисов

| Сервис | Полный отказ | Режим деградации | Read-only режим | Восстановление |
|--------|-------------|---------------|----------------|----------------|
| **Ontology Service** | Интерфейс недоступен | Ошибки при сохранении, просмотр работает | ✅ (просмотр TBox/ABox) | Авто restart, 1 мин |
| **Versioning Service** | Коммиты недоступны | Ошибки при фиксации | ✅ (просмотр без изменений) | Авто restart, 1 мин |
| **Neo4j (Triple Store)** | Критический — данные недоступны | — | — | RTO: 1 час |
| **PostgreSQL (Version Store)** | Частичный — история недоступна | Новые коммиты не создаются | ✅ | RTO: 2 часа |
| **Redis** | Кэш недоступен | Запросы идут в БД напрямую | ✅ | RTO: 30 мин |

## Критерии режима деградации

### Приемлемый режим деградации (система работает)

| Состояние | Описание | Когда применяется |
|-----------|----------|-------------------|
| **Read-only** | Пользователи видят данные, не могут редактировать | Отказ Ontology Service или конфликт репликации |
| **Без коммитов** | Редактирование работает, создание коммитов недоступно | Отказ Versioning Service или PostgreSQL |
| **Без кэша** | Медленнее, но всё работает | Отказ Redis |

### Неприемлемый режим деградации (система должна отключиться)

| Состояние | Причина |
|-----------|---------|
| **Нет Triple Store** | Невозможно прочитать онтологию — нет смысла в интерфейсе |
| **Нет авторизации** | Безопасность данных под угрозой |
| **Полная потеря данных** | Данные повреждены или недоступны |

## Политика circuit breaker

```yaml
circuit_breaker:
  versioning_service:
    failure_threshold: 3
    timeout: 60s
    degraded_mode: "no_commits"
    
  ontology_service:
    failure_threshold: 3
    timeout: 30s
    degraded_mode: "read_only"
```

## Коды ошибок для пользователя

| Код | Сообщение | Действие пользователя |
|-----|-----------|----------------------|
| `SVC_VERSION_OFFLINE` | «Создание коммитов недоступно. Изменения сохраняются локально.» | Сохранить локально, создать коммит позже |
| `SVC_READONLY` | «Редактирование недоступно. Система работает в режиме чтения.» | Дождаться восстановления |
| `SVC_CRITICAL` | «Система временно недоступна. Мы работаем над восстановлением.» | Обратиться в поддержку |

## Split-brain и read-only переход

### Механизм обнаружения split-brain

Система использует heartbeat + fencing token + проверку `neo4j.dbms.cluster.role` каждые 5 секунд.

| Условие | Действие | Max время перехода |
|---------|----------|-------------------|
| Расхождение контрольных сумм TBox между репликами Neo4j | Немедленный read-only | 30 сек |
| Потеря связи с PostgreSQL primary | Read-only для Version Store-операций | 30 сек |
| `neo4j.dbms.cluster.role` не подтверждён 2+ проверки подряд | Полный read-only | 30 сек |

### Параметры

| Параметр | Значение |
|----------|----------|
| Макс. время перехода в read-only с момента обнаружения | 30 секунд |
| RPO для подтверждённых изменений | 0 (zero) — изменения не считаются подтверждёнными, пока не записаны в оба хранилища с quorum |
| Индикация | Read-only режим логируется как P0 алерт |

### Независимый observability dashboard (read-only)

При отказе основного приложения следующие компоненты observability остаются доступными через независимый канал управления:

| Компонент | Доступность | RTO доступа |
|-----------|-------------|-------------|
| Prometheus (метрики) | Полная (отдельный кластер/namespace) | 0 |
| Loki (логи) | Полная | 0 |
| Tempo (трейсы) | Полная | 0 |
| Статус кластера Neo4j (через `neo4j-admin`) | Чтение | 2 минуты |
| `vedo-cli diagnose` | Полная | 1 минута |
| API Gateway `/health` | Отдельный endpoint вне основного роутера | 0 |

Observability стек работает на отдельном кластере/namespace с изолированными ресурсами, не зависящем от API Gateway. Grafana использует отдельную БД (SQLite или PostgreSQL).

## Процедуры восстановления

### Ontology Service (Rust)

1. **Обнаружение:** Health check каждые 5 секунд
2. **Деградация:** После 3 ошибок → read-only mode
3. **Восстановление:** Автоматический restart пода, проверка health check
4. **RTO:** 1 минута (Kubernetes restart)

### Versioning Service (Rust)

1. **Обнаружение:** gRPC timeout при попытке commit
2. **Деградация:** Создание коммитов недоступно
3. **Восстановление:** Автоматический restart
4. **UX:** Изменения накапливаются локально, коммит позже

---

## Сбои межсервисного взаимодействия

| Сценарий | Поведение |
|----------|-----------|
| **gRPC timeout** | Circuit breaker срабатывает, degraded mode |
| **Redis unavailable** | Fallback на primary data store (Neo4j/PostgreSQL) |
| **Message queue down (RabbitMQ)** | Синхронная обработка без событий, повтор позже |
| **API Gateway unreachable** | Возврат HTTP 503 с retry-after header |
