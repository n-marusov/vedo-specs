## Назначение

Обеспечить отказоустойчивость компонента LLM Router (API Gateway), чтобы он не становился единой точкой отказа для всех AI-функций.

## Требование

Компонент LLM Router должен быть спроектирован с учётом отказоустойчивости и горизонтального масштабирования.

**Архитектурные требования:**

1. **Горизонтальное масштабирование:** LLM Router должен поддерживать запуск ≥ 2 реплик. При падении одной реплики запросы автоматически перенаправляются на оставшиеся через load balancer.
2. **Stateless:** Роутер не хранит состояние между запросами (кроме кэша visibility онтологий). Любая реплика может обработать любой запрос.
3. **Kubernetes probes:**
   - `readinessProbe`: HTTP GET `/health/ready` — проверяет доступность зависимостей (Ontology Service, LLM-адаптеры).
   - `livenessProbe`: HTTP GET `/health/live` — проверяет, что процесс жив.
4. **Graceful shutdown:** При получении SIGTERM роутер завершает текущие запросы (grace period 30 секунд) и перестаёт принимать новые.
5. **Кэширование visibility:** Уровень видимости онтологий кэшируется локально в памяти каждой реплики (TTL 60 сек) для снижения зависимости от Ontology Service. При недоступности Ontology Service используется последнее известное значение из кэша (stale-while-revalidate).
6. **Timeout для LLM-вызовов:** Каждый запрос к LLM-провайдеру имеет timeout 30 секунд. При превышении — запрос отменяется, провайдер помечается для health check downgrade.
7. **Circuit breaker на провайдера:** При достижении failure_threshold (3 последовательных ошибки) провайдер временно исключается из ротации без ожидания health check интервала.

## Критерии приёмки

1. Роутер развёрнут с ≥ 2 реплик в production (≥ 1 в staging).
2. Kubernetes readiness/liveness probes настроены и проверены.
3. При падении одной реплики запросы автоматически перенаправляются на оставшиеся (проверено chaos-тестами).
4. При недоступности Ontology Service роутер использует кэшированные данные (stale-while-revalidate), а не возвращает ошибку.
5. При timeout запроса к LLM-провайдеру роутер возвращает ошибку `LLM_PROVIDER_TIMEOUT`, но продолжает принимать другие запросы.
6. Мониторинг доступности роутера: `up{job="llm-router"}` метрика в Prometheus.
7. Circuit breaker изолирует недоступного провайдера в течение 60 секунд после срабатывания, затем half-open проверка.
