| **ID** | REQ-NFR.INTEGRATION.automatic-failover |

| **Приоритет** | P0 |

## Назначение

Определить механизм автоматического переключения (failover) между LLM-провайдерами при отказе основного провайдера.

## Требование

Система должна автоматически переключаться на резервного LLM-провайдера при отказе основного. Переключение происходит без ручного вмешательства.

**Механизм failover:**

1. **Health check:** Система периодически проверяет доступность каждого провайдера (см. `REQ-NFR.OPS.provider-health-checks`).
2. **Детекция отказа:** При 3 последовательных неудачных health check'ах (с интервалом 30 секунд) провайдер помечается как `unavailable`.
3. **Автоматическое переключение:** Все новые запросы направляются на следующего доступного провайдера согласно конфигурации приоритетов.
4. **Приоритет провайдеров:** Конфигурируется администратором (например: OpenAI > Anthropic > Local). См. `REQ-FUN.INFRA.provider-priority-config`.
5. **Восстановление:** При 2 последовательных успешных health check'ах провайдер помечается как `healthy`, и система возвращается на него как на основной (если его приоритет выше).

**Scope failover:**

- Применяется для Public онтологий (внешние LLM разрешены по умолчанию).
- Применяется для Internal/Private онтологий, если администратор разрешил внешние LLM (см. `REQ-NFR.INTEGRATION.failover-internal-private`).
- НЕ применяется в on-premise (только локальная LLM).

## Критерии приёмки

1. При отказе основного провайдера запросы автоматически направляются на резервного — без ручного вмешательства.
2. Время переключения (от третьего неудачного health check до маршрутизации на резервного) ≤ 2 минут.
3. Администратор может настроить приоритет провайдеров через конфигурацию (`llm.providers.<name>.priority`).
4. При восстановлении провайдера система возвращается на него автоматически (после 2 успешных health check'ов).
5. Каждое переключение логируется в audit (см. `REQ-NFR.DATA.failover-audit`).
