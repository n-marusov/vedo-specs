# Failover для Internal/Private онтологий с разрешёнными внешними LLM

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.INTEGRATION.failover-internal-private |
| **Уровень** | NFR |
| **Атрибут качества** | Reliability |
| **Приоритет** | P1 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.3 матрицы качества M2 |
| **Связанные REQ** | `REQ-FUN.UI.external-llm-override`, `REQ-NFR.INTEGRATION.automatic-failover` |

---

## Назначение

Определить применение политики failover для Internal/Private онтологий, где администратор явно разрешил использование внешних LLM-провайдеров.

## Требование

Для Internal/Private онтологий в SaaS, где администратор включил настройку «Разрешить использование внешних LLM-провайдеров» (см. `REQ-FUN.UI.external-llm-override`), применяется та же политика автоматического failover, что и для Public онтологий.

**Поведение в зависимости от конфигурации:**

| Уровень | Внешние разрешены? | Failover применяется? | Комментарий |
|---------|-------------------|----------------------|-------------|
| Public | Да (по умолчанию) | ✅ Да | Стандартный failover |
| Internal | Да (админ разрешил) | ✅ Да | Та же политика, что и для Public |
| Internal | Нет (по умолчанию) | ❌ Нет | Запросы блокируются политикой — failover не нужен |
| Private | Да (админ разрешил) | ✅ Да | Та же политика, что и для Public |
| Private | Нет (по умолчанию) | ❌ Нет | Запросы блокируются политикой — failover не нужен |
| Любой (on-premise) | N/A | ❌ Нет | Только локальная LLM, один провайдер |

**При отказе всех провайдеров:**

- Для Internal/Private с разрешёнными внешними: graceful degradation (как для Public).
- Для Internal/Private без разрешения: запросы блокируются политикой (как и в штатном режиме).

## Критерии приёмки

1. Настройка failover наследуется от административного разрешения внешних LLM — отдельной настройки не требуется.
2. Для Internal/Private с разрешёнными внешними — failover работает идентично Public онтологиям.
3. Для Internal/Private без разрешения — failover не применяется (запросы блокируются с `LLM_BLOCKED_BY_POLICY`).
4. В on-premise failover не применяется ни при каких условиях.
5. Audit-лог фиксирует флаг `admin_override=true` для запросов, прошедших через failover для Internal/Private онтологий.
