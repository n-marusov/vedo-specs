# Максимально допустимый простой NL-функций при отказе провайдера

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.INTEGRATION.max-downtime |
| **Уровень** | NFR |
| **Атрибут качества** | Reliability |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.3 матрицы качества M2 |
| **Связанные ADR** | `ADR-DES.INFRA.fault-tolerance-strategy` |

---

## Назначение

Определить максимально допустимое время простоя NL-функций (NL→OWL, NL-режим запросов, AI-подсказки) при отказе основного LLM-провайдера.

## Требование

При отказе основного LLM-провайдера NL-функции должны быть восстановлены в течение заданного времени через автоматический failover на резервного провайдера.

**Метрика:** Время от момента детекции отказа до момента, когда NL-функции снова доступны (через failover или восстановление провайдера).

**Пороговое значение:** **≤ 5 минут** (RTO для NL-функций).

**Метод верификации:**

1. Автоматические тесты в CI/CD (chaos engineering), симулирующие отказ провайдера.
2. Мониторинг в production: время между алертом `provider_unavailable` и восстановлением доступности NL-функций.
3. Периодические drills (учения по отказоустойчивости) не реже 1 раза в квартал.

## Критерии приёмки

1. При отказе основного провайдера система автоматически переключается на резервного (failover).
2. Время переключения (детекция + failover) ≤ 5 минут от момента первого неудачного health check.
3. При отказе всех провайдеров — NL-функции переходят в режим graceful degradation с понятным сообщением пользователю (см. `REQ-USR.UI.graceful-degradation`).
4. Алерт отправляется в систему уведомлений (PagerDuty/Opsgenie) при каждом failover.
5. RTO метрика мониторится в Prometheus и отображается на дашборде SLO.
