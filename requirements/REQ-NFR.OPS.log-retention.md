## Назначение

Фиксирует ответ на вопрос M3.3: какие сроки хранения применяются к логам, трейсам и метрикам VEDO Core, как они различаются по типу телеметрии и какие переопределения заказчика допустимы.

VEDO Core использует многоуровневую стратегию хранения: разные сроки для разных типов логов и телеметрии, потому что audit logs, application logs, HTTP access logs, traces и metrics имеют разную ценность, объём, стоимость хранения и compliance-требования.

## Политика хранения по умолчанию

| Тип телеметрии | Активное хранение | Хранение в cold archive | Ориентировочный объём | Нормативная база / назначение |
|----------------|------------------|------------------------|-----------------------|-------------------------------|
| Аудиторские логи (Audit logs) | 1 год | 3 года по умолчанию; 5 лет для `152-ФЗ / Regulatory Enterprise`; до 7 лет как customer override | 10 GB/мес на 1000 пользователей | 152-ФЗ, ПДн, корпоративные политики |
| Логи приложений (Application logs) | 30 дней | 90 дней опционально | 50 GB/мес, зависит от нагрузки | Отладка, инциденты |
| Логи доступа (HTTP / API Gateway) | 14 дней | 30 дней | 100 GB/мес на 1 млн запросов | Безопасность, расследования |
| Трейсы (Traces) | 7 дней | 14 дней по требованию | 200 GB/мес при 1000 запросов/сек | Отладка производительности |
| Метрики (Metrics) | 30 дней raw | 1 год агрегированные | 1 GB/мес для сэмплированных метрик | Тренды, ёмкостное планирование |

## Обоснование

### Аудиторские логи

Хранение: 1 год active + 3 года cold archive по умолчанию.

Причины:

- 1 год active — стандартный срок для расследования инцидентов и оперативного поиска.
- 1 год active поддерживает требования ISO 27001 и SOC 2.
- 3 года cold archive являются разумным стандартом по умолчанию для коммерческих клиентов, ISO 27001, SOC 2, GDPR и общих корпоративных политик.

Для профиля `152-ФЗ / Regulatory Enterprise` 5 лет audit cold archive обязательны. Для остальных клиентов 5 лет не включаются автоматически и оформляются как customer override с capacity planning. Максимальный поддерживаемый override без отдельного архитектурного решения — 7 лет.

### Логи приложений

Хранение: 30 дней active + 90 дней archive опционально.

Причины:

- Большой объём: десятки GB в месяц.
- Большинство инцидентов расследуется в течение 2-4 недель.
- Хранение дольше 30 дней дорого и обычно не нужно для оперативной отладки.

### Логи доступа HTTP / API Gateway

Хранение: 14 дней active + 30 дней cold archive.

Причины:

- Типичный период анализа безопасности — 2 недели.
- Эти логи нужны для расследований безопасности и анализа access patterns, но не для отладки бизнес-логики.
- Это один из самых объёмных потоков из-за миллионов запросов в день.

### Трейсы

Хранение: 7 дней active, без архива по умолчанию.

Причины:

- Трейсы имеют огромный объём при интенсивном использовании.
- Их ценность быстро падает: они нужны для недавних проблем производительности.
- Дольше 7 дней по умолчанию экономически нецелесообразно.

14 дней хранения для traces допускается по требованию заказчика.

### Метрики

Хранение: 30 дней raw + 1 год aggregated.

Причины:

- 30 дней raw metrics покрывают алерты, расследования и краткосрочное ёмкостное планирование.
- 1 год агрегированных метрик нужен для трендов и capacity planning.

## Требования к реализации

### Loki

Loki хранит application logs по умолчанию 30 дней active.

```yaml
limits_config:
  retention_period: 720h
  max_query_lookback: 720h

compactor:
  retention_enabled: true
  retention_delete_delay: 2h
  retention_delete_worker_count: 150
```

Audit logs должны маршрутизироваться в отдельный tenant или отдельный Loki deployment с retention 1 год active.

```yaml
processors:
  routing:
    attribute_source: resource
    from_attribute: log.type
    default_exporters:
      - loki/default
    table:
      - value: "audit"
        exporters:
          - loki/audit

exporters:
  loki/default:
    endpoint: http://loki:3100/loki/api/v1/push
    tenant_id: "vedo"
    labels:
      source: "vedo-app"
  loki/audit:
    endpoint: http://loki-audit:3100/loki/api/v1/push
    tenant_id: "audit"
    labels:
      source: "vedo-audit"
```

### Prometheus

Prometheus хранит raw metrics 30 дней. Для долгосрочного хранения агрегированных метрик используется remote write в Thanos, Victoria Metrics или эквивалентное хранилище.

```yaml
global:
  evaluation_interval: 30s
  scrape_interval: 30s

storage:
  tsdb:
    retention_time: 30d
    retention_size: 50GB

remote_write:
  - url: http://thanos-receive:19291/api/v1/receive
    queue_config:
      capacity: 10000
```

### Tempo

Tempo хранит traces 7 дней по умолчанию.

```yaml
storage:
  trace:
    backend: s3
    s3:
      bucket: vedo-traces
      endpoint: s3.amazonaws.com
      region: us-east-1
    block:
      ttl: 168h
    wal:
      ttl: 24h
```

## Базовая оценка стоимости

Оценка для 1000 пользователей и 1 млн запросов в день:

| Тип телеметрии | Объём | Стоимость активного хранения | Стоимость cold archive |
|----------------|-------|------------------|------------------------|
| Audit | 10 GB/мес | $5 NVMe | $2 HDD |
| Application | 50 GB/мес | $25 NVMe | $10 HDD |
| HTTP access | 100 GB/мес | $50 NVMe | $20 HDD |
| Traces | 200 GB/мес | $100 NVMe | Не архивируются по умолчанию |
| Metrics | 1 GB/мес | $0.5 NVMe | $0.1 S3 aggregated |
| Итого | 361 GB/мес | $180.5 | $32.1 |

Для on-premise заказчик оплачивает ёмкость хранилища самостоятельно; HDD значительно дешевле NVMe для cold archive.

## Переопределения заказчика

| Требование заказчика | Активное хранение | Архивное хранение | Действие |
|----------------------|------------------|-------------------|----------|
| Стандарт по умолчанию | По default retention policy | По default retention policy | Принимается |
| Увеличенный срок хранения, например 90 дней для всех логов | 90 дней для всех логов | 1 год | Нужны дополнительные диски и бюджет |
| Минимальный срок хранения для экономии | 7 дней для всех логов | 14 дней | Снижается возможность расследования инцидентов |
| `152-ФЗ / Regulatory Enterprise` | 1 год audit | 5 лет audit, обязательно | Требуется отдельный cold archive, например S3 Glacier или customer-managed equivalent |
| Customer override | По договору | До 7 лет | Требуется capacity planning, подтверждение инфраструктуры или SaaS change request |

## Формулировка для заказчика

VEDO Core по умолчанию хранит:

- Аудиторские логи — 1 год active + 3 года cold archive.
- Логи приложений — 30 дней active + 90 дней archive.
- Логи доступа HTTP — 14 дней active + 30 дней archive.
- Трейсы — 7 дней.
- Метрики — 30 дней raw + 1 год aggregated.

Срок хранения можно изменить через конфигурацию Loki, Prometheus и Tempo в on-premise версии. Увеличение срока хранения влияет на требования к дисковому пространству и бюджет.

Для профиля `152-ФЗ / Regulatory Enterprise` требуется отдельный tenant с retention 1 год active и выгрузкой в cold archive, например S3 Glacier или customer-managed equivalent, на 5 лет. Для остальных заказчиков 5 лет доступны только как customer override.

## Бизнес-правила

- Audit logs нельзя хранить в общем tenant с application logs, если для audit требуется больший retention или отдельный compliance archive.
- Audit cold archive по умолчанию хранится 3 года.
- Audit cold archive 5 лет обязателен только для профиля `152-ФЗ / Regulatory Enterprise`.
- Customer override audit cold archive до 7 лет допустим только с capacity planning и явным подтверждением стоимости/инфраструктуры.
- Application logs по умолчанию хранятся 30 дней active.
- HTTP/API Gateway access logs по умолчанию хранятся 14 дней active.
- Traces по умолчанию хранятся 7 дней и не архивируются, если заказчик явно не требует 14 дней.
- Raw metrics по умолчанию хранятся 30 дней; aggregated metrics хранятся 1 год.
- Увеличенный retention требует явного capacity planning по диску и бюджету.
- Минимальный retention допустим только как customer override с пониманием, что возможности расследования инцидентов ухудшаются.
