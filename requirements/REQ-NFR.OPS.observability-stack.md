## Назначение

Фиксирует ответ на вопрос M3.1: какой стек observability обязателен для VEDO Core и какие альтернативы допустимы.

## Обязательный стек по умолчанию

Для VEDO Core обязательным к поставке является следующий стек:

| Компонент | Назначение | Обязательность | Причина |
|-----------|------------|----------------|---------|
| Prometheus | Сбор и хранение метрик | Да | Стандарт де-факто, интеграция с Kubernetes, активное сообщество |
| Grafana | Визуализация метрик, логов, трейсов и дашборды | Да | Единая панель для всех метрик, поддержка Prometheus, Loki, Tempo |
| OpenTelemetry | Сбор трейсов, метрик и логов | Да | Стандарт W3C, vendor-neutral, унификация инструментария |
| Grafana Loki | Хранение и поиск логов | Да | Интегрируется с Grafana, дешёвое хранение, поддержка мета-меток |
| Grafana Tempo | Хранение трейсов | Да | Работает с OpenTelemetry, масштабируется, совместим с Jaeger |

## Аргументация

- Prometheus + Grafana — зрелые, документированные, де-факто стандарт для Kubernetes.
- OpenTelemetry — единый стандарт; не нужно поддерживать несколько агентов.
- Loki — легковесная альтернатива Elasticsearch: меньше ресурсов и проще эксплуатация.
- Tempo — объектное хранилище для трейсов: дешёво и масштабируемо.

## Альтернативы

Альтернативы поддерживаются опционально, но не заменяют поставку по умолчанию.

| Альтернатива | Какие компоненты заменяет | Уровень поддержки | Примечание |
|--------------|---------------------------|-------------------|------------|
| Victoria Metrics | Prometheus | Полная через remote write | Для крупных инсталляций больше 1000 узлов |
| Elastic Stack / ELK | Loki + Tempo | Частичная | Требует адаптации exporters; документация предоставляется |
| Jaeger | Tempo | Полная, OpenTelemetry-compatible | Может использоваться вместо Tempo |
| Datadog | Весь стек | Через OpenTelemetry exporter | Требует лицензии заказчика |
| New Relic | Весь стек | Через OpenTelemetry exporter | Требует лицензии заказчика |
| Self-managed ELK | Loki + Tempo | Не входит в базовую поддержку | Заказчик сам настраивает и сопровождает |

## Граница ответственности

Поддержка альтернативных стеков не входит в базовую поставку VEDO Core. Это услуга за отдельную плату или зона ответственности заказчика для on-premise deployment.

Если заказчик использует корпоративный стандарт observability, например Datadog, New Relic или Elastic Stack, телеметрия должна перенаправляться через OpenTelemetry exporters без изменения кода сервисов.

VEDO предоставляет шаблоны Grafana dashboards. Kibana dashboards для ELK не входят в поставку по умолчанию.

## Минимальные требования для on-premise

Если заказчик не хочет использовать стек по умолчанию, он должен самостоятельно обеспечить эквивалентные возможности:

| Функция | Требование |
|---------|------------|
| Метрики производительности | `vedo_*` метрики в Prometheus-compatible формате или экспорт в совместимый backend |
| Трассировка | OpenTelemetry-compatible backend: Tempo, Jaeger, Datadog APM, New Relic |
| Логи | Хранение и поиск логов с эквивалентом Loki API или собственной интеграцией заказчика |
| Дашборды | Единый overview dashboard, содержащий панели health, latency, error rate, saturation, logs и traces |

## Сроки хранения по умолчанию

### SaaS (VEDO managed)

| Тип данных | Retention | Примечание |
|------------|-----------|------------|
| Аудиторские логи | 1 год active + 3 года cold archive | WORM-бакет для комплаенса |
| Логи приложений | 30 дней active + 90 дней archive | Loki |
| Логи HTTP / API Gateway | 14 дней active + 30 дней cold archive | Loki |
| Трейсы (Tempo) | 7 дней active | Быстро теряют ценность |
| Метрики (Prometheus) | 30 дней raw + 1 год aggregated | Downsampled после 30 дней |

### On-premise (минимальные требования)

| Компонент | Retention | Примечание |
|-----------|-----------|------------|
| Prometheus (raw) | 15 дней | Для отладки инцидентов |
| Prometheus (агрегированные) | 90 дней | Для трендов и capacity planning |
| Loki (активные) | 14 дней | Логи приложений |
| Loki (архив) | 30 дней | Если место позволяет |
| Tempo (трейсы) | 3 дня | Минимально для диагностики |
| Аудиторские логи | 1 год active + 3 года cold archive | По умолчанию (см. Audit Cold Archive Profiles) |

Подробная политика зафиксирована в `log-retention.md`.

## Audit Cold Archive Profiles

5-летний audit cold archive не включается для всех enterprise/on-premise заказчиков по умолчанию.

| Профиль | Audit cold archive | Основание |
|---------|--------------------|-----------|
| Default | 3 года | ISO 27001, SOC 2, GDPR и общие корпоративные политики |
| `152-ФЗ / Regulatory Enterprise` | 5 лет, обязательно | Российская юрисдикция, операторы ПДн, отраслевые регуляторы |
| Customer override | До 7 лет, опционально | Политика клиента, договор и capacity planning |

Для SaaS увеличение сверх default является change request с коммерческими условиями и capacity planning. Для on-premise заказчик может переопределить срок, но конфигурация должна пройти проверку ёмкости хранилища и явно подтвердить дополнительную стоимость.

## Рекомендация

Для SaaS и стандартного on-premise deployment использовать стек по умолчанию:

- Метрики: Prometheus.
- Логи: Grafana Loki.
- Трейсы: Grafana Tempo.
- Визуализация: Grafana.
- Коллектор: OpenTelemetry Collector.

Для Enterprise on-premise deployment большого масштаба может использоваться Victoria Metrics вместо Prometheus.

## Диагностика через `vedo-cli`

`vedo-cli diagnose` является обязательной административной точкой входа для диагностики инцидентов. Команда `vedo-cli diagnose trace --id <trace_id>` должна:

- получать trace из Tempo;
- находить ошибочный span и связанные span attributes;
- получать связанные логи из Loki по `trace_id`/`span_id`;
- получать метрики Prometheus за интервал инцидента;
- показывать локализацию проблемы и рекомендации инженеру поддержки;
- опционально использовать LLM для генерации рекомендаций, если это разрешено политикой окружения.

Целевая метрика Time-to-Diagnose: P0 ≤ 10 минут, P1 ≤ 30 минут.

## Infrastructure Requirements for Observability

### Prometheus (метрики)

| Параметр | SaaS (VEDO managed) | On-premise (минимально) | Примечание |
|----------|--------------------|------------------------|------------|
| **Retention (raw)** | 30 дней | 15 дней | Для отладки инцидентов |
| **Retention (агрегированные)** | 1 год (downsampled) | 90 дней | Для трендов и capacity planning |
| **Дисковое пространство** | 50 GB (на старте), 200 GB (рост) | 50 GB | Рассчитывается: ~1 GB на 1 млн активных серий |
| **CPU** | 4 vCPU | 2 vCPU | Нагрузка от запросов и алертов |
| **RAM** | 8 GB | 4 GB | Кэш индексов и WAL |

### Loki (логи)

| Параметр | SaaS (VEDO managed) | On-premise (минимально) | Примечание |
|----------|--------------------|------------------------|------------|
| **Retention (активные)** | 30 дней | 14 дней | Логи приложений и API Gateway |
| **Retention (архив)** | 90 дней (cold storage) | 30 дней (если место позволяет) | Для комплаенса (audit logs — отдельно) |
| **Дисковое пространство** | 100 GB (на старте), 500 GB (рост) | 100 GB | Сжатие 1:5 (raw logs → stored) |
| **CPU** | 4 vCPU | 2 vCPU | Индексация и запросы |
| **RAM** | 8 GB | 4 GB | Индексы в памяти |

### Tempo (трейсы)

| Параметр | SaaS (VEDO managed) | On-premise (минимально) | Примечание |
|----------|--------------------|------------------------|------------|
| **Retention** | 7 дней | 3 дня | Трейсы быстро теряют ценность |
| **Дисковое пространство** | 50 GB | 20 GB | Зависит от нагрузки (sampling rate) |
| **CPU** | 2 vCPU | 1 vCPU | |
| **RAM** | 4 GB | 2 GB | |

### Grafana (дашборды)

| Параметр | SaaS | On-premise | Примечание |
|----------|------|------------|------------|
| **CPU** | 1 vCPU | 0.5 vCPU | Небольшая нагрузка |
| **RAM** | 2 GB | 1 GB | |
| **Диск** | 10 GB | 10 GB | Для плагинов и кэша |

### Capacity planning (пример для SaaS)

| Компонент | CPU (total) | RAM (total) | Диск (total) |
|-----------|-------------|-------------|--------------|
| Prometheus | 4 vCPU | 8 GB | 200 GB |
| Loki | 4 vCPU | 8 GB | 500 GB |
| Tempo | 2 vCPU | 4 GB | 50 GB |
| Grafana | 1 vCPU | 2 GB | 10 GB |
| **Итого** | **11 vCPU** | **22 GB** | **760 GB** |

### Рекомендации по хранению (on-premise)

- **Диски:** SSD обязательны для Loki (индексы) и Prometheus (WAL).
- **Резервное копирование:** Логи и метрики не бэкапятся (восстанавливаются из приложений).
- **Архивация:** Для audit logs — отдельный WORM-бакет (не в Loki).

### Мониторинг самого observability стека

| Проверка | Порог | Действие |
|----------|-------|----------|
| Loki ingestion rate | > 90% capacity | Увеличение retention или диска |
| Prometheus disk usage | > 80% | Ротация блоков, увеличение диска |
| Tempo trace loss | > 1% | Увеличение лимитов |
