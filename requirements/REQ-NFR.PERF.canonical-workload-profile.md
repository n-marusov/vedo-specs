## Контекст

Для корректного планирования ресурсов, тестирования производительности и составления SLA необходимо зафиксировать единую единицу масштаба.

VEDO Core не может полагаться только на один параметр, например количество классов, потому что реальная нагрузка зависит от нескольких факторов. Вместо этого используется канонический профиль нагрузки, который описывает типовую онтологию и типовой сценарий использования.

---

## Решение

Единой единицей масштаба для VEDO Core является канонический профиль нагрузки.

**Базовый профиль:** 1M аксиом, 100K индивидов, 50K классов, 5 параллельных редакторов (работающих в разных ветках), 10 API запросов в секунду.

---

## Канонический профиль

### Основные параметры

| Параметр | Значение | Пояснение |
|----------|----------|-----------|
| Axioms (аксиомы) | 1 000 000 | Базовый размер онтологии (TBox + RBox) |
| Triples (триплеты) | ~4 000 000 | 1 аксиома примерно равна 4 триплетам после разворачивания |
| Classes (классы) | 50 000 | Включая подклассы и перечисления |
| ObjectProperties | 10 000 | Свойства, связывающие классы |
| DatatypeProperties | 5 000 | Атрибуты с XSD-типами |
| Individuals (индивиды) | 100 000 | Экземпляры классов |

## Требования к ресурсам для базового профиля

Профиль: 1M аксиом, 100K индивидов, 5 параллельных редакторов.

| Компонент | CPU requests/limits | Memory requests/limits | Storage | Replicas |
|-----------|---------------------|------------------------|---------|----------|
| Ontology Service | 2 / 4 | 2 Gi / 4 Gi | — | 3 |
| Versioning Service | 2 / 4 | 2 Gi / 4 Gi | 100 GB | 2 |
| Хранилище графа (активная ветка) | 4 / 8 | 8 Gi / 16 Gi | 50 GB | 3 (кластер) |
| Хранилище дельт версий | 2 / 4 | 4 Gi / 8 Gi | 100 GB | primary + replica |
| API Gateway | 1 / 2 | 1 Gi / 2 Gi | — | 2 |
| Auth Service | 0.5 / 1 | 0.5 Gi / 1 Gi | — | 2 |
| Metrics Service | 0.5 / 1 | 0.5 Gi / 1 Gi | — | 1 |

**Примечание:** В модели чисто Git-подобного версионирования Collaboration Service отсутствует. Ресурсы, ранее выделявшиеся под него, перераспределены между Versioning Service (обработка дельт, слияний, семантического diff) и API Gateway (WebSocket для уведомлений о комментариях, если используется).

**Итого на кластер (не на инстанс):**

| Ресурс | Минимально | Рекомендуемо |
|--------|------------|--------------|
| CPU | 16 vCPU | 32 vCPU |
| RAM | 40 GB | 80 GB |
| Storage | 200 GB | 400 GB |

## Формулы масштабирования

| Сценарий | Влияние на ресурсы |
|----------|---------------------|
| Каждые дополнительные 10 000 классов | Увеличение CPU Ontology Service на 0.5 core, RAM на 1 GB (метаданные, индексы) |
| Каждые дополнительные 50 000 индивидов | Увеличение RAM хранилища графа на 4 GB (примерно 80 MB на 1000 индивидов для типовых данных, может быть выше для сильно связанных графов) |
| Каждый дополнительный параллельный редактор | Увеличение CPU Versioning Service на 0.2 core, RAM на 0.3 GB (обработка дельт, операций слияния) |
| Увеличение частоты коммитов в 2 раза | Увеличение Storage хранилища дельт в 2 раза |

## Surge-профиль (всплеск трафика)

Система должна выдерживать следующие коэффициенты всплеска трафика относительно p95 обычного трафика (канонический профиль) в течение 5-минутного скользящего окна:

| Тип операции | Коэф. всплеска | Max p99 latency | Max error rate (5xx) |
|--------------|----------------|-----------------|---------------------|
| GraphQL навигация (read) | 10× | 2 сек | 0.1% |
| SPARQL аналитика | 5× | 10 сек | 0.5% |
| REST CRUD (read) | 8× | 1 сек | 0.1% |
| Коммит / write | 3× | 3 сек | 0.5% |
| Слияние веток (merge) | 3× | 5 сек | 1% |
| Создание ветки | 5× | 2 сек | 0.5% |

**Surge-профиль проверяется при нагрузочном тестировании перед каждым production-релизом.** Отказ любого параметра блокирует релиз.

## Единицы масштаба для лицензирования Enterprise

VEDO Core Enterprise использует три модели лицензирования на выбор заказчика.

| Модель | Единица масштаба | Цена (индикативно) | Когда выбирать |
|--------|------------------|--------------------|-----------------|
| По аксиомам (Axioms) | 1M аксиом | $1 000 / месяц | Заказчики с большим TBox (сложная схема) |
| По индивидам (Individuals) | 100K индивидов | $800 / месяц | Заказчики с большим ABox (много данных) |
| По числу редакторов (Concurrent Editors) | 5 редакторов | $1 500 / месяц | Заказчики с широкой командой |

**Минимальная лицензия:** стоимость 1 единицы любого вида (например, 1 000 000 аксиом = $1 000).

**Примечание:** В модели чисто Git-подобного версионирования «редактор» означает пользователя, активно работающего в своей ветке (коммиты, создание веток, создание Merge Request'ов). Пользователи с правами только на чтение не учитываются в лицензии по редакторам.

## Измерение производительности QA

Все тесты производительности должны быть выражены в единицах профиля и в единицах масштаба.

| Тест | Базовый профиль | Увеличение масштаба |
|------|-----------------|---------------------|
| `test_create_class` | 1M аксиом, 50K классов | 2M аксиом (2×) |
| `test_sparql_query` | 100K индивидов | 200K индивидов (2×) |
| `test_merge_branches` | 5 редакторов, 50 коммитов | 10 редакторов, 100 коммитов (2×) |
| `test_commit_delta` | 500 аксиом на коммит | 1000 аксиом на коммит (2×) |

**Критерий PASS/FAIL:** если при 2× масштаба время выполнения увеличивается более чем в 2.5×, тест считается проваленным.

## Объяснение для заказчиков

VEDO Core характеризуется каноническим профилем нагрузки: **1M аксиом, 100K индивидов, 50K классов, 5 параллельных редакторов, 10 API запросов в секунду.** Под этот профиль предоставляются ресурсные рекомендации по CPU, RAM и Storage.

**Как система масштабируется:**

- Увеличение числа классов → увеличивает CPU и RAM Ontology Service.
- Увеличение числа индивидов → увеличивает RAM хранилища графа и дисковое пространство для ABox.
- Увеличение числа редакторов → увеличивает ресурсы Versioning Service (обработка дельт, слияний).

**Параллельная работа:** VEDO Core использует Git-подобную модель — каждый редактор работает в своей ветке. Конфликты разрешаются при слиянии. Это отличается от модели с блокировками, но обеспечивает предсказуемую производительность и масштабируемость.

**Лицензирование Enterprise** может быть выбрано по одному из трёх параметров: количество аксиом, количество индивидов или число редакторов. Каждая дополнительная единица масштаба (1M аксиом / 100K индивидов / 5 редакторов) имеет фиксированную стоимость.
