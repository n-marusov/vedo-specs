## Назначение

Определить тестовые сценарии для проверки отказоустойчивости NL-функций через chaos engineering в CI/CD и pre-production окружениях.

## Требование

CI/CD и staging/pre-production окружения должны включать автоматические тесты отказоустойчивости, симулирующие различные виды отказов LLM-провайдеров.

**Тестовые сценарии:**

| # | Сценарий | Симуляция | Ожидаемое поведение | Проверки |
|---|----------|-----------|---------------------|----------|
| 1 | Отказ основного провайдера | HTTP 500/503 от OpenAI (mock) | Автоматический failover на Anthropic | Запросы успешны, провайдер = Anthropic, audit-лог содержит failover_completed |
| 2 | Timeout провайдера | Запрос не отвечает > 30 сек | Провайдер помечается unavailable, failover | Запросы уходят на резервного, latency ≤ RTO |
| 3 | Rate limit провайдера | HTTP 429 от OpenAI | Провайдер помечается degraded, запросы продолжаются через резервного | Статус = degraded, алерт P2 |
| 4 | Отказ всех провайдеров | Все провайдеры возвращают 500 | Graceful degradation | NL-функции недоступны, алерт P0, остальные функции VEDO работают |
| 5 | Восстановление провайдера | OpenAI восстанавливается после отказа | Автоматический возврат на OpenAI | Провайдер = OpenAI, алерт P3 (recovered) |
| 6 | Деградация производительности | p95 latency > 10 сек | Провайдер помечается degraded, алерт P2 | Запросы продолжаются, latency мониторится |
| 7 | Отказ LLM Router реплики | Убить одну реплику роутера | Запросы перенаправляются на оставшиеся | 0 ошибок, 0 потерянных запросов |

**Окружения:**

- **CI/CD (pull request):** тесты 1-3 (быстрые, ≤ 2 мин).
- **Staging (nightly):** все тесты 1-7.
- **Production:** тесты НЕ выполняются.

**Инструменты:**

- Mock LLM server (имитирует поведение реальных провайдеров с настраиваемыми сценариями отказов).
- Kubernetes chaos mesh или `kubectl delete pod` для теста 7.

## Критерии приёмки

1. Тесты 1-3 выполняются в CI/CD при каждом pull request, затрагивающем LLM Router или адаптеры.
2. Все тесты 1-7 выполняются nightly в staging.
3. Каждый сценарий проверяет:
   - Автоматическое переключение (failover)
   - Graceful degradation (все провайдеры недоступны)
   - Восстановление после отказа
   - Корректное логирование (audit-записи)
   - Алерты (проверка наличия алертов в системе мониторинга)
4. Тесты не выполняются в production.
5. Результаты тестов доступны в CI/CD отчёте и сохраняются минимум 30 дней.
6. При падении chaos-тестов билд в staging блокируется.
