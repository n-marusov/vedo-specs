# Хранение audit-логов в защищённом виде

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.SECURITY.audit-encryption |
| **Уровень** | NFR |
| **Атрибут качества** | Security |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 2.5 матрицы качества M2 |

---

## Назначение

Обеспечить хранение audit-логов MCP в зашифрованном виде и защиту от несанкционированного доступа.

## Требование

**Меры защиты:**

| Мера | Описание |
|------|----------|
| **Шифрование at rest** | AES-256 для всех логов на диске |
| **Шифрование in transit** | TLS 1.3 для всех запросов к API аудита |
| **Доступ по ролям** | RBAC: пользователь / администратор tenant / поддержка / администратор VEDO |
| **Аудит доступа** | Каждое обращение к логам логируется |
| **Immutable storage** | Append-only — логи нельзя изменить или удалить вручную |

## Критерии приёмки

1. Логи шифруются at rest (AES-256).
2. API аудита работает только по HTTPS (TLS 1.3).
3. Доступ к логам ограничен ролями согласно `REQ-USR.UI.audit-access`.
4. Логи append-only (нет API для изменения/удаления).
5. Ключи шифрования управляются через Vault/KMS.
