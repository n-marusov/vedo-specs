| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.SECURITY.audit-masking |
| **Уровень** | NFR |
| **Атрибут качества** | Security |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 2.5 матрицы качества M2 |

---

## Назначение

Обеспечить маскировку sensitive data в audit-логах MCP-инструментов до записи.

## Требование

**Маскируемые данные:**

| Тип данных | Действие | Пример |
|------------|----------|--------|
| API ключи | Замена на `[REDACTED]` | `"api_key": "[REDACTED]"` |
| Пароли | Замена на `[REDACTED]` | `"password": "[REDACTED]"` |
| Токены | Замена на `[REDACTED]` | `"token": "[REDACTED]"` |
| Персональные данные | Замена на `[REDACTED]` | `"email": "[REDACTED]"` |

**Не маскируются:** IRI онтологии (часть контекста запроса).

## Критерии приёмки

1. Все sensitive данные маскируются до записи в лог.
2. Маскировка применяется ко всем источникам (UI, API, CLI).
3. Список маскируемых паттернов конфигурируется.
4. Факт маскировки логируется (что было замаскировано, без раскрытия значения).
5. Маскировка не влияет на производительность (< 1 мс на запись).
