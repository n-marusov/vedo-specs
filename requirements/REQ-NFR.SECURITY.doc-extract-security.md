## Назначение

Определить требования безопасности для сервиса извлечения онтологии из документов.

## Требование

### Загрузка файлов
1. Максимальный размер загружаемого файла: 20 MB (синхронный режим), 100 MB (асинхронный).
2. Проверка MIME-типа на стороне сервера (не полагаться на клиентскую проверку).
3. Сканирование на вирусы перед обработкой (ClamAV или аналогичное решение).
4. Файлы хранятся временно (max 24 часа) в изолированном storage, недоступном извне.
5. После завершения обработки временные файлы удаляются.

### Защита от вредоносного контента
1. PDF: блокировка JavaScript, внешних ссылок, embedded files.
2. DOCX: отключение макросов, проверка на malicious XML.
3. JSON/XML: защита от XXE (XML External Entity) атак, ограничение глубины вложенности (max 10 уровней).
4. CSV: защита от formula injection (=CMD, +DDE, etc.).

### LLM-безопасность
1. На промпт для LLM накладывается system prompt, запрещающий генерацию вредоносного контента.
2. Пользователь не может напрямую управлять промптом без sandbox-режима.
3. Sequence, возвращаемый LLM, валидируется по JSON Schema перед отображением.
4. Аудит всех LLM-запросов (см. REQ-NFR.DATA.llm-audit).

### Аудит
1. Фиксируется: кто загрузил, какой файл (hash), время, размер, статус обработки.
2. Исходный файл может быть прикреплён к коммиту как артефакт (опционально, с согласия пользователя).

## Критерии приёмки

1. Загрузка .exe под видом .pdf отклоняется.
2. Файлы с макросами обрабатываются безопасно (макросы не выполняются).
3. При попытке XXE-атаки через XML — ошибка парсинга.
4. Virus scan блокирует инфицированные файлы.
5. Временные файлы удаляются через 24 часа.
6. Аудит-лог содержит все операции загрузки.
