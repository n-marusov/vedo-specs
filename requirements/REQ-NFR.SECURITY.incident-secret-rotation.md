## Что описывает

Определяет обязательную процедуру массовой ротации секретов после подтвержденного security-инцидента или подозрения на компрометацию.

## Триггеры mandatory rotation

- Подтвержденный доступ злоумышленника к CI/CD или secret manager.
- Утечка токенов/ключей в логах, артефактах, issue tracker или внешних каналах.
- Компрометация workstation пользователя с privileged доступом.

## SLA ротации

| Категория секрета | SLA завершения ротации |
|---|---|
| CI/CD tokens, registry creds, signing keys | <= 4 часа |
| Service-to-service credentials | <= 8 часов |
| External API keys, webhook secrets | <= 24 часа |
| Customer-facing session secrets | <= 24 часа |

## Требования к процессу

- Охват ротации: 100% секретов затронутой категории.
- Старые секреты должны быть отозваны не позднее 15 минут после активации новых.
- После ротации запускается обязательный smoke suite (`auth`, `api`, `background jobs`).
- Все шаги ротации фиксируются в incident timeline с точностью до минуты.

## Проверка эффективности

- Доля инцидентов с неполной ротацией: 0%.
- Доля инцидентов с нарушением SLA по критичным секретам (<= 8 часов): не более 1% в год.
- Ежеквартальный drill по ротации секретов обязателен.

## Бизнес-правила

- Частичная ротация без документированного исключения запрещена.
- Исключение возможно только по письменному одобрению Security Lead и действует не более 24 часов.
- Запрещено повторное использование компрометированного секрета после инцидента.
