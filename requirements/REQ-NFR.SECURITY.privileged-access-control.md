## Что описывает

Фиксирует обязательные требования к привилегированному доступу в production для администраторов, поддержки и дежурных инженеров.

## Модель доступа

- Постоянный standing access к production запрещен.
- Привилегии выдаются только по JIT-модели через PAM workflow.
- Каждый доступ требует ticket ID, бизнес-обоснование, scope и TTL.

## MFA Requirements (дополнение)

### Разрешенные факторы MFA (согласно ADR)

| Фактор | MVP | Enterprise (post-MVP) | CLI support | Примечание |
|---|---|---|---|---|
| TOTP (Google Authenticator, FreeOTP, Microsoft Authenticator) | Разрешен (основной) | Разрешен | Да (ввод 6 цифр) | Достаточен для MVP |

### Процесс MFA в CLI

1. Пользователь (`Support Engineer`, `SRE`, `DBA`) запускает команду `vedo-cli`.
2. CLI запрашивает `username` и `password`.
3. CLI запрашивает TOTP-код:

```text
Enter TOTP code (Google Authenticator):
```

4. Пользователь вводит 6-значный код из приложения-аутентификатора.
5. После успешной проверки CLI получает `access_token` (TTL = 1 час).

## JIT/PAM параметры

| Параметр | Требование |
|---|---|
| Максимальный TTL сессии | <= 60 минут |
| Повторное продление | не более 1 раза, +30 минут |
| Время выдачи доступа | <= 10 минут для P0/P1 |
| Session recording | 100% привилегированных сессий |
| Command audit log | 100% команд с timestamp и actor |

## Break-glass

- Break-glass доступ допускается только при P0 и недоступности штатного PAM контура.
- Двойное одобрение: Security Lead + Incident Commander.
- TTL break-glass доступа: <= 30 минут.
- Пост-инцидентный review: <= 24 часа.

## Бизнес-правила

- Общие (shared) привилегированные учетные записи запрещены.
- Любой доступ без ticket ID автоматически считается нарушением безопасности P1.
- Отсутствие записи сессии для привилегированного доступа считается P0 security incident.
