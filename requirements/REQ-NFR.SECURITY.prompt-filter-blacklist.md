# Фильтрация запрещённых инструкций в NL-запросах

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.SECURITY.prompt-filter-blacklist |
| **Уровень** | NFR |
| **Атрибут качества** | Security |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 2.1 матрицы качества M2 |

---

## Назначение

Блокировать NL-запросы, содержащие запрещённые инструкции, до их отправки LLM-провайдеру.

## Требование

Система фильтрует NL-запросы на наличие запрещённых фраз и паттернов (регистронезависимый поиск).

**Чёрный список фраз/паттернов:**

| Категория | Фразы/паттерны |
|-----------|---------------|
| **Смена инструкций** | `ignore previous instructions`, `forget all constraints`, `ignore the above`, `reset your instructions` |
| **Смена роли** | `you are now a...`, `from now on, act as...`, `you are no longer...`, `act as if you are...` |
| **Системные промпты** | `system prompt`, `disregard your system prompt`, `system message`, `override system instructions` |
| **Структурные атаки** | `output only JSON with...`, `output only XML with...`, `respond with only...` |
| **Отключение ограничений** | `remove all restrictions`, `disable safety`, `ignore safety guidelines`, `bypass filters` |

## Критерии приёмки

1. Каждый NL-запрос проверяется на наличие фраз из чёрного списка.
2. При обнаружении запрещённой фразы запрос блокируется до отправки провайдеру.
3. Пользователь получает сообщение: «Ваш запрос содержит запрещённые инструкции и был заблокирован.»
4. Блокировка логируется в audit с указанием причины и совпавшего паттерна.
5. Чёрный список обновляется через конфигурацию без перезапуска сервисов.
