## Целевой уровень

| Фаза | Уровень | Assistive technologies | Статус |
|------|---------|----------------------|--------|
| MVP | WCAG 2.1 Level AA (5 критических категорий) | NVDA (Windows), VoiceOver (macOS) | Требуется |
| Релиз 1.0 (P1) | WCAG 2.2 Level AA (полный) | + JAWS (Windows), + TalkBack (Android, browser) | Требуется |
| Enterprise (P3) | Полная сертификация (по запросу) | Все вышеперечисленные | Опционально |

### PASS/FAIL критерий (общий)

- **PASS:** Все обязательные сценарии MVP (A1–F2) пройдены с screen reader AND keyboard-only, за время ≤ 3× норматива обычного пользователя, без подсказок, без использования мыши.
- **FAIL:** Хотя бы один обязательный сценарий недоступен или требует подсказки от разработчика.

---

## Обоснование уровня

| Уровень | Охват | Применимость к VEDO Core |
|---------|-------|--------------------------|
| **Level AA (6 категорий)** | 6 критических категорий сценариев | MVP: аутентификация, навигация, редактирование, версионирование, коллаборация, публичный просмотр |
| **Level AA (полный)** | ~70% критериев | Релиз 1.0: все экраны редактора; требование для госзакупок, баланс затрат |
| **Level AAA** | ~100% | Нецелесообразно (требует радикального пересмотра UI) |

**Рекомендация:** Level AA для 6 критических категорий на MVP позволяет участвовать в госзакупках (ФЗ № 419-ФЗ), соответствует Section 508 и European Accessibility Act с первого релиза.

## Исключения для MVP

| Компонент | Проблема | Обоснование | Компенсация |
|-----------|----------|-------------|-------------|
| 3D-граф (Three.js) | Canvas-based, не доступен для скрин ридеров | Природа 3D-визуализации не позволяет обеспечить AA без радикального перепроектирования | Табличный fallback с keyboard-доступом (сценарий B4) |
| Drag-and-drop (ClassTree reorder) | Native D&D недоступен для скрин ридеров | Drag-and-drop не имеет нативной accessibility-поддержки | Button-based интерфейс (Move Up / Move Down / Move to Parent) |
| WebSocket-уведомления (toast) | Мигающие уведомления могут конфликтовать с 2.3.1 (Three Flashes) | Требуется альтернативный паттерн уведомлений | Persistent визуальный индикатор + ARIA live region (`role="status"`, `aria-live="polite"`) |
| SPARQL редактор (Syntax Highlight) | Сложность подсветки синтаксиса для скрин ридеров | Синтаксическая подсветка — визуальная фича без семантического эквивалента | Plain-text textarea с label и error validation |

## Ключевые требования WCAG 2.1 AA

### Воспринимаемость (Perceivable)

| Критерий | Реализация в VEDO |
|----------|-------------------|
| 1.1.1 Нетекстовый контент | Иконки кнопок с `aria-label` |
| 1.4.1 Использование цвета | Ошибки не только красным (иконка + текст) |
| 1.4.3 Контраст | 4.5:1 для текста, 3:1 для крупного |
| 1.4.4 Изменение размера | Поддержка масштабирования до 200% |
| 1.4.10 Рефлоу | 320px без горизонтального скролла |

### Управляемость (Operable)

| Критерий | Реализация в VEDO |
|----------|-------------------|
| 2.1.1 Клавиатура | Все функции через Tab/Enter/Esc |
| 2.4.3 Порядок фокуса | Логичный порядок элементов |
| 2.4.6 Заголовки и метки | `<label>` у всех полей ввода |
| 2.4.7 Видимый фокус | Увеличение при фокусе |

### Понятность (Understandable)

| Критерий | Реализация в VEDO |
|----------|-------------------|
| 3.2.2 При вводе | Нет неожиданных изменений контекста |
| 3.3.1 Идентификация ошибки | Явные сообщения, не только подсветка |
| 3.3.3 Предложения | Похожие классы при ошибке ввода |

### Совместимость (Robust)

| Критерий | Реализация в VEDO |
|----------|-------------------|
| 4.1.2 ARIA | Кастомные компоненты с role, state |
| 4.1.3 Статусные сообщения | `role="status"`, `aria-live="polite"` |

## Сложные компоненты

| Компонент | Проблема | Решение |
|-----------|----------|---------|
| 3D-граф (Three.js) | Canvas недоступен для скрин ридеров | Альтернативный табличный вид |

| Autocomplete | Нестандартный контрол | ARIA: combobox, listbox, aria-expanded |

```yaml
accessibility:
  target_level: "WCAG 2.1 Level AA (5 critical categories)"
  target_mvp: "Level AA (categories A-D, F)"
  exceptions:
    - "3D-граф: табличный fallback"
    - "Drag-and-drop: button-based альтернатива"
    - "SPARQL редактор: plain-text textarea"

    max_time_multiplier: 3
    no_mouse: true
    no_prompts: true

    gov_contract: "За 2 месяца до тендера"
```

## Hardware for Accessibility Testing

Для тестирования с screen reader (NVDA / VoiceOver) рекомендуются:

| Компонент | Минимально | Примечание |
|-----------|------------|------------|
| RAM | 8 GB | Screen reader + браузер + VEDO Core |
| CPU | 2 ядра | VoiceOver требует ресурсов |
| Звуковая карта | Любая | Для синтеза речи |
| Наушники | Рекомендованы | Для тестирования в офисе |

**Примечание:** Аппаратные требования для пользователей screen reader не отличаются от базовых (см. `client-environment-support.md`).

## Инструменты тестирования

### Automated (CI gate)

| Инструмент | Назначение | Порог |
|------------|-----------|-------|
| **axe-core** | Автоматический audit доступности в CI | block critical/serious violations (fail pipeline) |
| **Lighthouse CI** | Performance + accessibility score | Accessibility score ≥ 90 |
| **Playwright keyboard-only тесты** | Сквозная проверка каждого критического сценария (A1–F2) | 100% PASS для всех сценариев |

### Manual (pre-release gate)

| Инструмент | Назначение | Частота |
|------------|-----------|---------|
| **NVDA** (Windows) | Screen reader тестирование критических сценариев | Перед каждым релизом MVP |
| **VoiceOver** (macOS) | Screen reader тестирование критических сценариев | Перед каждым релизом MVP |
| **Keyboard-only** (Tab/Enter/Arrow/Esc) | Проверка навигации без мыши | Перед каждым релизом MVP |

### Что не допускается

- Только automated scan (axe-core, Lighthouse) как единственное доказательство.
- Наложенный accessibility widget как единственное решение.
- Пропуск любого сценария P0 при релизе — блокирует release gate.

## Design System Governance (для spec-driven разработки)

### Единый источник дизайна

Все дизайн-токены содержатся в файле `design/frontend.pen` (Pencil). Этот файл является единственным источником истины для цветов, типографики, отступов и всех визуальных свойств. AI читает `.pen` напрямую при генерации кода.

Переменные в Pencil используют префикс `$B:` и поддерживают темы light/dark:
- `$B:primary`, `$B:background`, `$B:foreground`, `$B:muted-foreground` — основные цвета
- `$B:card`, `$B:popover`, `$B:accent`, `$B:destructive` — семантические цвета
- `$B:success`, `$B:warning`, `$B:info`, `$B:tool`, `$B:agent` — функциональные цвета
- `$B:font-size-base`, `$B:font-size-2xs` — размеры шрифта

Человекочитаемый справочник CSS-переменных: `human/artifacts/ui/customization-variables.md`.

### Процесс изменения токенов

| Шаг | Действие | Ответственный |
|-----|----------|---------------|
| 1 | Изменение цвета/шрифта в Pencil (`design/frontend.pen`) | UX Designer |
| 2 | Создание PR с описанием изменений | UX Designer |
| 3 | Review изменений (UX Lead) | UX Lead |
| 4 | Approval и merge | UX Lead |
| 5 | Синхронизация `customization-variables.md` | DevOps |
| 6 | ИИ использует обновлённый `.pen` при генерации кода | — |

### Использование токенов ИИ

В промптах и спецификациях **не должны хардкодиться цвета или размеры**. Вместо этого используются ссылки на переменные из `design/frontend.pen`:

```yaml
# user-story.yaml (пример)
acceptance_criteria:
  - "Кнопка 'Сохранить' использует `$B:primary` из design/frontend.pen"
  - "Цвет рамки при фокусе — `$B:ring` из design/frontend.pen"
```

### Компонентная библиотека (Storybook)

- Компоненты разрабатываются в изоляции.
- Каждый компонент имеет:
  - Acceptance criteria (текстовое описание)
  - Скриншот-тест (Playwright)
  - Story в Storybook (сгенерированный ИИ)
- Изменение компонента требует обновления acceptance criteria.

### Ответственность

| Роль | Ответственность |
|------|-----------------|
| **UX Lead** | Утверждение изменений design tokens, ревью acceptance criteria |
| **Frontend (spec)** | Написание acceptance criteria для компонентов |
| **AI** | Генерация кода компонента из acceptance criteria |
