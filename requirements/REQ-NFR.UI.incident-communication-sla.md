## Что описывает

Фиксирует измеримые требования к коммуникации инцидентов для внешних и внутренних пользователей VEDO Core.

## Каналы коммуникации

- In-app banner (обязателен для web UI).
- Public status page API.
- Email-рассылка для администраторов tenant.

## SLA публикации

| Событие | Требование |
|---|---|
| Подтвержден P0/P1 инцидент | Первый публичный апдейт <= 10 минут |
| Активный P0 инцидент | Обновления статуса не реже 15 минут |
| Активный P1 инцидент | Обновления статуса не реже 30 минут |
| Закрытие инцидента | Финальный апдейт <= 30 минут после восстановления |
| Публикация RCA | <= 5 рабочих дней для P0, <= 10 рабочих дней для P1 |

## Содержимое сообщения

Каждый апдейт инцидента должен содержать:

- уникальный incident ID;
- затронутые компоненты и пользовательские сценарии;
- текущий статус (`investigating`, `identified`, `monitoring`, `resolved`);
- время следующего planned update.

## UX-требования

- In-app banner должен отображаться для 100% активных сессий затронутых tenant в течение 2 минут после публикации статуса.
- Сообщения должны быть доступны на RU и EN.
- Для P0 сообщение должно содержать рекомендуемое действие пользователя (retry later/read-only flow/contact support).

## Контроль качества коммуникации

- Доля инцидентов P0/P1 с нарушением SLA первого апдейта: не более 2% за квартал.
- Доля инцидентов с неполным обязательным содержимым: не более 1% за квартал.
- Нарушение SLA более 2 кварталов подряд блокирует release sign-off до корректирующих мер.

## Бизнес-правила

- Коммуникация инцидента обязательна даже при частичной деградации.
- Сообщение "investigating" без времени следующего апдейта запрещено.
- Удаление опубликованных incident updates запрещено; допускается только append-only исправление.
