## Категория A — Аутентификация

### Сценарий A1: Вход в систему

**Описание:** Пользователь переходит на страницу логина, выбирает OAuth провайдера, вводит учетные данные и завершает OAuth flow.

**WCAG критерии:** 2.1.1, 2.4.7, 3.3.1, 3.3.2, 1.1.1, 1.3.1

**Keyboard-only ожидание:**
- Шаг 1: Tab до выбора OAuth провайдера (Яндекс, VK, Google, ЕСИА). Все провайдеры достижимы и визуально обозначены фокусом.
- Шаг 2: Enter для выбора провайдера. Открывается форма логина или redirect на внешний OAuth.
- Шаг 3: Tab по полям формы (email/логин, пароль). Логичный порядок: label → input → submit.
- Шаг 4: Ввод данных, Tab до кнопки "Войти", Enter. При ошибке фокус перемещается на первое поле с ошибкой.
- Шаг 5: После успешного входа фокус устанавливается на основной контент (Dashboard).

**Screen reader ожидание (NVDA/VoiceOver):**
- Страница логина: "Вход в систему. Heading level 1."
- Кнопки OAuth: "Войти через Яндекс", "Войти через VK", "Войти через Google", "Войти через ЕСИА" — с role="button".
- Поле email: "Электронная почта: поле ввода".
- Поле пароль: "Пароль: поле ввода, скрытый текст".
- Кнопка "Войти": "Войти, кнопка".
- Ошибка: "Неверный email или пароль", с указанием поля.
- Успех: "Dashboard, heading level 1".

**PASS/FAIL критерий:**
- PASS: Пользователь выполнил вход без мыши, все элементы достижимы и озвучены, ошибки валидации объявлены. Время ≤ 3× норматива.
- FAIL: Невозможно выбрать OAuth провайдера с клавиатуры, поле ввода без label, ошибка не озвучена, время превышено.

**Связанные компоненты:** Login page, OAuth provider selector, form controls, submit button, error messages

---

### Сценарий A2: Восстановление пароля

**Описание:** Пользователь запрашивает восстановление пароля, вводит email, получает подтверждение и устанавливает новый пароль.

**WCAG критерии:** 2.1.1, 3.3.1, 3.3.2, 1.1.1, 2.4.7, 2.4.6

**Keyboard-only ожидание:**
- Шаг 1: Tab до ссылки "Забыли пароль?" на странице логина, Enter.
- Шаг 2: Tab до поля email, ввод адреса, Tab до кнопки "Отправить", Enter.
- Шаг 3: После отправки появляется сообщение "Проверьте почту". Фокус на сообщении.
- Шаг 4: Переход по ссылке из письма — открывается форма сброса пароля.
- Шаг 5: Tab до поля "Новый пароль", ввод. Tab до поля "Подтвердите пароль", ввод. Tab до "Сохранить", Enter.

**Screen reader ожидание (NVDA/VoiceOver):**
- Ссылка: "Забыли пароль? Ссылка."
- Поле: "Email: поле ввода, обязательное."
- Кнопка: "Отправить, кнопка."
- Статус: "Письмо отправлено на указанный адрес", role="status".
- Сброс: "Новый пароль: поле ввода, скрытый текст", "Подтвердите пароль: поле ввода, скрытый текст".
- Ошибка: "Пароль должен содержать минимум 8 символов", озвучено сразу после потери фокуса.

**PASS/FAIL критерий:**
- PASS: Все шаги выполнены с клавиатуры, screen reader объявляет все поля, ошибки и статусы. Время ≤ 3× норматива.
- FAIL: Поле email без label, ссылка "Забыли пароль" не достижима клавиатурой, статус отправки не объявлен.

**Связанные компоненты:** Login page, password reset form, email input, status message

### Сценарий A3: Выход из системы

**Описание:** Пользователь находит кнопку выхода в интерфейсе, подтверждает действие и возвращается на страницу логина.

**WCAG критерии:** 2.1.1, 2.4.3, 2.4.7, 1.3.1, 4.1.2

**Keyboard-only ожидание:**
- Шаг 1: Tab до кнопки "Выйти" в header/sidebar. Кнопка визуально выделена фокусом.
- Шаг 2: Enter для активации. Появляется диалог подтверждения "Вы уверены, что хотите выйти?".
- Шаг 3: Tab до кнопки "Да, выйти" в диалоге. Escape также работает для отмены.
- Шаг 4: Enter для подтверждения. Пользователь возвращается на страницу логина.
- Шаг 5: Фокус после выхода — на форме входа (поле email).

**Screen reader ожидание (NVDA/VoiceOver):**
- Кнопка: "Выйти, кнопка."
- Диалог: "Подтверждение выхода. Вы уверены, что хотите выйти?", role="dialog".
- Кнопки: "Да, выйти, кнопка", "Отмена, кнопка."
- После выхода: "Вход в систему. Heading level 1."

**PASS/FAIL критерий:**
- PASS: Выход выполнен с клавиатуры, диалог подтверждения объявлен screen reader, фокус после выхода на форме логина. Время ≤ 3× норматива.
- FAIL: Кнопка выхода не достижима Tab, диалог подтверждения не объявлен, фокус потерян после выхода.

**Связанные компоненты:** Header/sidebar logout button, confirmation dialog, login page

## Категория B — Навигация по онтологии

### Сценарий B1: Просмотр дерева классов (Tree view)

**Описание:** Пользователь открывает онтологию, видит иерархическое дерево классов, раскрывает узлы, перемещается между ними и открывает карточку выбранного класса.

**WCAG критерии:** 2.1.1, 2.4.3, 2.4.7, 1.3.1, 4.1.2, 4.1.3

**Keyboard-only ожидание:**
- Шаг 1: После загрузки онтологии фокус на первом узле дерева или на панели дерева.
- Шаг 2: Tab для входа в дерево, Arrow Up/Down для перемещения между узлами.
- Шаг 3: Arrow Right для раскрытия узла (expand), Arrow Left для сворачивания (collapse).
- Шаг 4: Enter для выбора класса и открытия его карточки в панели свойств.
- Шаг 5: Возврат Tab/Shift+Tab в дерево для продолжения навигации.

**Screen reader ожидание (NVDA/VoiceOver):**
- Дерево: "Дерево классов. Tree. Свернуто. Ветка 1 из 20."
- Узел: "Класс: Person. Уровень 1. Свернуто. 3 дочерних элемента."
- Раскрытие: "Person развернуто. Дочерние элементы: Employee, Customer, Partner."
- Выбор: "Person. Выбрано. Карточка класса в панели свойств."
- Статус: "Загрузка дерева..." / "Дерево загружено. 20 классов."

**PASS/FAIL критерий:**
- PASS: Пользователь может раскрыть/свернуть узлы, перемещаться между ними и выбрать класс с клавиатуры. Screen reader объявляет иерархию, состояние expand/collapse, имя узла и уровень вложенности. Время ≤ 3× норматива.
- FAIL: Tree nodes не достижимы Arrow keys, expand/collapse не работает с клавиатуры, screen reader не объявляет уровень или состояние узла.

**Связанные компоненты:** ClassTree component, tree view, class card, property panel

---

### Сценарий B2: Поиск класса по названию

**Описание:** Пользователь вводит запрос в поле полнотекстового поиска, просматривает результаты и открывает карточку нужного класса из результатов.

**WCAG критерии:** 2.1.1, 3.3.2, 2.4.3, 4.1.2, 1.3.1, 3.3.1

**Keyboard-only ожидание:**
- Шаг 1: Tab до поля поиска (в header или на панели). Фокус видим.
- Шаг 2: Ввод текста запроса. Через задержку (debounce) появляются результаты в выпадающем списке.
- Шаг 3: Arrow Down для навигации по результатам поиска. Каждый результат подсвечен фокусом.
- Шаг 4: Enter для выбора результата. Открывается карточка класса.
- Шаг 5: Escape для закрытия списка результатов без выбора. Фокус возвращается в поле поиска.

**Screen reader ожидание (NVDA/VoiceOver):**
- Поле: "Поиск классов. Поле ввода. Combo box."
- Результаты: "Найдено 5 результатов. Результат 1: Person класс. Результат 2: Employee класс."
- Выбор: "Employee. Карточка класса открыта."
- Пустой результат: "Ничего не найдено."
- Ошибка: "Поисковый запрос должен содержать минимум 2 символа."

**PASS/FAIL критерий:**
- PASS: Пользователь может ввести запрос, просмотреть результаты, выбрать нужный — всё с клавиатуры. Screen reader объявляет количество и имена результатов, обновление списка при вводе. Время ≤ 3× норматива.
- FAIL: Поле поиска не достижимо Tab, список результатов не объявляется screen reader, невозможно навигировать по результатам Arrow keys, результаты не обновляются динамически.

**Связанные компоненты:** Search input, autocomplete/listbox, search results, class card

### Сценарий B3: Просмотр свойств класса (Property Panel)

**Описание:** Пользователь после выбора класса в дереве просматривает его свойства в панели — DataProperties, ObjectProperties, Individuals — и перемещается между секциями.

**WCAG критерии:** 2.1.1, 2.4.3, 2.4.7, 1.3.1, 4.1.2, 4.1.3

**Keyboard-only ожидание:**
- Шаг 1: После выбора класса в дереве (сценарий B1) фокус автоматически переходит на панель свойств или остаётся в дереве.
- Шаг 2: Tab до панели свойств. Вкладки/секции: "DataProperties", "ObjectProperties", "Individuals".
- Шаг 3: Arrow Left/Right для переключения между вкладками (tablist).
- Шаг 4: Tab для перехода к содержимому выбранной вкладки (tabpanel).
- Шаг 5: Arrow Up/Down для просмотра списка свойств внутри вкладки.
- Шаг 6: Enter для открытия свойства для редактирования (если применимо).

**Screen reader ожидание (NVDA/VoiceOver):**
- Панель: "Свойства класса Person. Tab panel."
- Вкладки: "DataProperties. Вкладка. Выбрана.", "ObjectProperties. Вкладка.", "Individuals. Вкладка."
- Содержимое: "DataProperties: hasName (DataProperty), hasAge (DataProperty)."
- Статус: "Загрузка свойств..." / "3 свойства загружено."

**PASS/FAIL критерий:**
- PASS: Пользователь может переключать вкладки клавиатурой (Arrow Left/Right), просматривать содержимое каждой вкладки. Screen reader объявляет выбранную вкладку, список свойств, имя каждого свойства. Время ≤ 3× норматива.
- FAIL: Вкладки не реализованы как tablist/tabpanel, Arrow keys не работают, screen reader не объявляет активную вкладку или содержимое.

**Связанные компоненты:** Property panel, tablist, tabpanel, property list, class card

### Сценарий B4: Навигация по графу (табличный fallback)

**Описание:** Пользователь переключает представление графа с 3D-визуализации на табличный вид, просматривает связи между сущностями и переходит к связанной сущности.

**WCAG критерии:** 2.1.1, 2.4.3, 1.3.1, 4.1.2, 2.4.7, 1.1.1

**Keyboard-only ожидание:**
- Шаг 1: Tab до переключателя вида (кнопка или ссылка) "Табличный вид" / "3D-граф".
- Шаг 2: Enter для переключения на табличное представление.
- Шаг 3: Arrow Up/Down для навигации по строкам таблицы (role="grid").
- Шаг 4: Arrow Left/Right для навигации по ячейкам строки.
- Шаг 5: Enter на ячейке с ссылкой для перехода к связанной сущности.
- Шаг 6: Shift+Tab для возврата к переключателю вида для обратного переключения.

**Screen reader ожидание (NVDA/VoiceOver):**
- Переключатель: "Переключить на табличный вид. Кнопка."
- Таблица: "Связи класса Person. Grid. 5 строк, 3 колонки."
- Строка: "Строка 1: Связь: hasEmployee, Тип: ObjectProperty, Цель: Employee."
- Ячейка: "Employee — ссылка."
- Переход: "Employee. Карточка класса загружена."

**PASS/FAIL критерий:**
- PASS: Пользователь может переключиться на табличный вид, навигировать по строкам и столбцам, перейти к связанной сущности — всё с клавиатуры. Screen reader объявляет структуру таблицы и содержимое ячеек. Время ≤ 3× норматива.
- FAIL: Табличный вид недоступен, grid не поддерживает Arrow навигацию, ссылки в ячейках не достижимы, screen reader не объявляет структуру таблицы.

**Связанные компоненты:** View toggle (3D/table), data grid/table, entity links, graph visualization

## Категория C — Редактирование

### Сценарий C1: Создание нового класса

**Описание:** Пользователь создает новый класс в онтологии: указывает имя (Label), аннотацию (Comment), выбирает родительский класс и сохраняет.

**WCAG критерии:** 2.1.1, 3.3.1, 3.3.2, 1.3.1, 2.4.7, 4.1.2

**Keyboard-only ожидание:**
- Шаг 1: Tab до кнопки "Создать класс" на панели инструментов или в контекстном меню дерева, Enter.
- Шаг 2: Открывается форма создания. Фокус на первом поле "Label" (обязательное).
- Шаг 3: Ввод названия класса. Tab до "Comment" (опционально), ввод описания.
- Шаг 4: Tab до выбора родительского класса (tree picker или combobox). Arrow для поиска, Enter для выбора.
- Шаг 5: Tab до кнопки "Сохранить", Enter. Форма закрывается, новый класс появляется в дереве.
- Шаг 6: Фокус на новом классе в дереве. Screen reader объявляет "Класс [имя] создан".

**Screen reader ожидание (NVDA/VoiceOver):**
- Форма: "Создание нового класса. Heading level 2. Форма."
- Поле: "Label: поле ввода, обязательное.", "Comment: поле ввода."
- Родитель: "Родительский класс: комбо-бокс. Текущий выбор: Thing."
- Ошибка: "Label обязателен для заполнения." (aria-describedby на поле)
- Статус: "Класс Person создан. Оповещение."

**PASS/FAIL критерий:**
- PASS: Пользователь создал класс с клавиатуры, все поля имеют label, ошибки валидации объявлены, screen reader объявляет успешное создание. Время ≤ 3× норматива.
- FAIL: Поля без label, кнопка "Создать класс" не достижима, ошибки не объявляются screen reader, фокус не перемещается на новый класс.

**Связанные компоненты:** Create class dialog/form, tree picker, form controls, class tree

### Сценарий C2: Редактирование класса (имя, аннотация)

**Описание:** Пользователь выбирает существующий класс, открывает режим редактирования, изменяет Label и/или Comment и сохраняет изменения.

**WCAG критерии:** 2.1.1, 3.3.1, 3.3.2, 2.4.7, 1.3.1, 4.1.3

**Keyboard-only ожидание:**
- Шаг 1: Tab до панели свойств или контекстного меню класса в дереве. Enter на "Редактировать".
- Шаг 2: Форма редактирования открывается с предзаполненными полями. Фокус на поле "Label".
- Шаг 3: Изменение Label и/или Comment. Tab между полями.
- Шаг 4: Tab до кнопки "Сохранить", Enter.
- Шаг 5: Форма закрывается, изменения отражены в дереве и панели свойств. Фокус на названии класса.
- Шаг 6: Escape для отмены редактирования без сохранения.

**Screen reader ожидание (NVDA/VoiceOver):**
- Форма: "Редактирование класса Person. Heading level 2."
- Поле: "Label: поле ввода. Текущее значение: Person."
- Статус: "Изменения сохранены." или "Редактирование отменено."
- Ошибка: "Label не может быть пустым."

**PASS/FAIL критерий:**
- PASS: Пользователь отредактировал класс с клавиатуры, изменения сохранены, screen reader объявляет статус сохранения. Время ≤ 3× норматива.
- FAIL: Невозможно открыть редактирование с клавиатуры, поля без label, статус сохранения не объявлен.

**Связанные компоненты:** Edit class dialog, form controls, property panel, class tree

### Сценарий C3: Создание ObjectProperty

**Описание:** Пользователь создает новое объектное свойство (ObjectProperty): задает имя, выбирает Domain и Range, настраивает характеристики (functional, transitive и т.д.).

**WCAG критерии:** 2.1.1, 3.3.1, 3.3.2, 1.3.1, 2.4.7, 4.1.2

**Keyboard-only ожидание:**
- Шаг 1: Tab до кнопки "Создать свойство" на панели ObjectProperties, Enter.
- Шаг 2: Форма создания открывается. Фокус на поле "Label".
- Шаг 3: Ввод имени свойства. Tab до поля "Domain" (combobox/tree picker), выбор.
- Шаг 4: Tab до поля "Range" (combobox/tree picker), выбор.
- Шаг 5: Tab до чекбоксов характеристик: Functional, Inverse functional, Transitive, Symmetric. Space для отметки.
- Шаг 6: Tab до "Сохранить", Enter. Свойство появляется в списке ObjectProperties.

**Screen reader ожидание (NVDA/VoiceOver):**
- Форма: "Создание ObjectProperty. Heading level 2."
- Поля: "Label: поле ввода, обязательное.", "Domain: комбо-бокс.", "Range: комбо-бокс."
- Чекбоксы: "Functional: флажок, не отмечен.", "Transitive: флажок, не отмечен."
- Статус: "ObjectProperty hasEmployee создан."
- Ошибка: "Domain обязателен для заполнения."

**PASS/FAIL критерий:**
- PASS: Пользователь создал ObjectProperty с клавиатуры, выбрал Domain/Range через combobox, отметил характеристики. Screen reader объявляет все поля, чекбоксы и статус. Время ≤ 3× норматива.
- FAIL: Domain/Range не выбираются с клавиатуры, чекбоксы не отмечены Space, ошибки не объявлены.

**Связанные компоненты:** Create property dialog, combobox, checkboxes, property list

### Сценарий C4: Добавление индивида (экземпляра)

**Описание:** Пользователь создает новый экземпляр (Individual) указанного класса: выбирает тип, заполняет свойства экземпляра и сохраняет.

**WCAG критерии:** 2.1.1, 3.3.1, 3.3.2, 1.3.1, 2.4.7, 4.1.2

### Сценарий D1: Просмотр истории коммитов (дифф)

**Описание:** Пользователь открывает историю коммитов онтологии, просматривает список версий, выбирает две для сравнения и просматривает diff изменений.

- Шаг 4: Tab для переключения между режимами diff (Unified/Split), если применимо.
- Шаг 5: Arrow Up/Down для прокрутки diff-строк. Enter на строке для перехода к сущности (если применимо).

**PASS/FAIL критерий:**

## Категория F — Публичный просмотр

### Сценарий F1: Открытие публичной ссылки

**Описание:** Пользователь (без авторизации) переходит по публичной ссылке на опубликованную онтологию и видит её read-only представление.

- Шаг 4: Все функции доступны без авторизации. Ни одно действие не требует логина.
- Шаг 5: Tab до начала дерева классов для навигации по онтологии.

**Screen reader ожидание (NVDA/VoiceOver):**

- PASS: Пользователь открыл публичную ссылку без авторизации, все элементы доступны с клавиатуры, screen reader объявляет заголовок и навигацию. Время ≤ 3× норматива.

**Связанные компоненты:** Public ontology page, header, skip link, navigation

### Сценарий F2: Навигация по опубликованной онтологии

**Описание:** Пользователь (без авторизации) просматривает опубликованную онтологию: раскрывает дерево классов, выполняет поиск, просматривает карточку класса в read-only режиме.

**Связанные компоненты:** Public class tree, search, class card (read-only), public navigation

## Exceptions for MVP

| Исключение | Причина | WCAG риск | Компенсация | Проверка |
|------------|---------|-----------|-------------|----------|
| 3D-граф (Three.js/WebGL) | Canvas-based 3D-визуализация не доступна для скрин ридеров без радикального перепроектирования | SC 1.1.1, 2.1.1, 4.1.2 | Табличный fallback с полной keyboard-доступностью (сценарий B4) | Табличный вид должен пройти все сценарии B4 |
| Drag-and-drop (ClassTree reorder, PropertyPanel reorder) | Native HTML5 D&D не имеет нативной accessibility-поддержки для скрин ридеров | SC 2.1.1, 4.1.2 | Button-based интерфейс: Move Up, Move Down, Move to Parent — с клавиатурными шорткатами | Все перестановки выполнимы через кнопки с клавиатуры |
| SPARQL редактор (Syntax Highlight) | Подсветка синтаксиса — визуальная фича без семантического эквивалента для скрин ридеров | SC 1.1.1, 2.1.1 | Plain-text textarea с явным label, error validation и keyboard-шорткатами (Ctrl+Enter для выполнения) | SPARQL запрос вводится и выполняется с клавиатуры, ошибки валидации объявляются |

## Automation in CI

```yaml
# .gitlab-ci.yml — accessibility stage

accessibility-audit:
  stage: test
  script:
    # 1. axe-core audit
    - npx axe --exit --show-errors
      --tags wcag2a,wcag2aa,wcag21a,wcag21aa
      --dir ./accessibility-reports/
    # 2. Lighthouse CI accessibility check
    - npx lhci autorun --collect.url="<LOGIN_URL>"
      --collect.url="<DASHBOARD_URL>"
      --collect.url="<ONTOLOGY_WORKSPACE_URL>"
      --assert.preset=lighthouse:recommended
      --assert.accessibility=90
  artifacts:
    paths:
      - accessibility-reports/
    when: always
  only:
    - merge_requests
    - main
    - develop

playwright-keyboard-tests:
  stage: test
  script:
    - npx playwright test --config=playwright.config.ts
      --grep "@keyboard-only"
      --reporter=junit
  artifacts:
    reports:
      junit: test-results/junit.xml
    when: always
  only:
    - merge_requests
    - main
    - develop
```
