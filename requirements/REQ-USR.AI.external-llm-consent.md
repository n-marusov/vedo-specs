## Назначение

Определить порядок предупреждения пользователя и получения согласия при использовании AI-функций, направляющих данные онтологии внешнему LLM-провайдеру.

## Требование

**Когда отображается диалог:**

Диалог предупреждения отображается перед первым в сессии NL-запросом через внешний LLM-провайдер для каждой онтологии в следующих случаях:

- **SaaS, Public:** всегда (внешние LLM разрешены политикой).
- **SaaS, Internal/Private с административным разрешением:** всегда (администратор сознательно разрешил, пользователь должен подтвердить).

Диалог НЕ отображается:

- **SaaS, Internal/Private без административного разрешения:** AI-функции заблокированы, диалог не нужен.
- **On-premise:** используется локальная LLM, данные не покидают периметр.

**Текст диалога (шаблон):**

> **«Отправка данных внешнему LLM-провайдеру»**
>
> Вы используете AI-функцию для онтологии **«[ontology_name]»** (уровень: **[visibility_level]**).
>
> Данные онтологии будут переданы внешнему LLM-провайдеру **«[provider_name]»**. Провайдер может использовать переданные данные для улучшения своих моделей в соответствии со своей политикой конфиденциальности.
>
> [ ] Я понимаю и принимаю риски
>
> [Продолжить]  [Отмена]

**Поведение:**

- Согласие действует на одну сессию (до закрытия вкладки или истечения токена).
- При смене онтологии диалог отображается заново.
- Отказ логируется в audit.

## Критерии приёмки

1. Диалог отображается перед первым вызовом внешнего LLM в сессии для каждой онтологии.
2. Диалог содержит имя онтологии, уровень видимости и название провайдера.
3. Пользователь должен явно подтвердить согласие (checkbox + кнопка).
4. Согласие сохраняется на время сессии (не запрашивается повторно для той же онтологии).
5. Отказ логируется в audit (`user_id, ontology_id, visibility, provider, timestamp, status=denied`).
6. В on-premise диалог не отображается.
