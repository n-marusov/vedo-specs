# Поддержка языков в NL-описании

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-USR.AI.nl-language-support |
| **Уровень** | USR |
| **Атрибут качества** | Usability |
| **Приоритет** | P1 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.2 матрицы качества M2 |

---

## Назначение

Определить поддержку языков при NL→OWL генерации — пользователь должен иметь возможность описывать предметную область на своём языке.

## Требование

NL→OWL генерация должна поддерживать NL-описания на нескольких языках. Пользователь может вводить описание на языке интерфейса или явно указать язык.

**Поддерживаемые языки (MVP):**

| Язык | Статус | Примечание |
|------|--------|------------|
| Русский | ✅ MVP | Основной язык платформы |
| Английский | ✅ MVP | Международная аудитория |

**Post-MVP:**

- Немецкий, французский, испанский, китайский — добавляются по мере локализации платформы.

**Поведение:**

- По умолчанию язык NL-описания определяется из языка интерфейса пользователя.
- Пользователь может явно выбрать язык через выпадающий список в интерфейсе генерации.
- Сгенерированные `rdfs:label` и `rdfs:comment` создаются на языке описания.
- Мультиязычные label не поддерживаются в MVP (пользователь может добавить вручную).

**Добавление нового языка:**

Не требует изменений в коде. Конфигурируется через:
1. Добавление language-specific промпта в конфигурацию tenant.
2. Обновление evaluation suite (добавление тестовых NL-описаний на новом языке с эталонными онтологиями).

## Критерии приёмки

1. Пользователь может выбрать язык описания (русский / английский) через выпадающий список.
2. Генерация корректно работает для русского и английского языков по всем критериям качества (`REQ-FUN.AI.*`).
3. Сгенерированные label и comment создаются на выбранном языке описания.
4. При отсутствии явного указания языка используется язык интерфейса пользователя.
5. Добавление нового языка не требует изменений в коде — только конфигурация промптов и тестов.
