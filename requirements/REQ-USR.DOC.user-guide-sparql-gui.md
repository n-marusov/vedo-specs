## Назначение

Раздел описывает, как пользователь выполняет запросы к графу знаний в VEDO Core через графический интерфейс.

Поддерживаются два языка запросов:

- **SPARQL 1.1** — стандарт W3C для семантических запросов к RDF-графу. Используется для сложных фильтров, агрегаций и обходов графа, которые не покрываются навигационной GraphQL-схемой. Типовая 2D/3D навигация по графу описана отдельно в `human/artifacts/requirements/REQ-USR.DOC.user-guide-graphql-navigation.md`.
- **CYPHER** — язык запросов Neo4j для графовых запросов по меткам узлов и типам связей.

Каждый язык поддерживает три режима:
- визуальный конструктор — для аналитиков и бизнес-пользователей;
- текстовый редактор — для инженеров знаний и опытных пользователей;
- NL-режим (кнопка «Микрофон») — естественный язык → SPARQL или CYPHER через LLM.

## Визуальный конструктор SPARQL

### Что показывает интерфейс

Документация должна включать скриншоты следующих состояний:
- выбор режима "Визуальный конструктор";
- список классов, загруженный через introspection;
- выбор свойства и объекта;
- настройка фильтров;
- предпросмотр сгенерированного SPARQL-запроса;
- результат в таблице и графе.

### Пошаговый сценарий

1. Откройте раздел запросов к графу знаний.
2. Выберите язык "SPARQL".
3. Выберите режим "Визуальный конструктор".
4. Выберите класс субъекта.
5. Выберите свойство.
6. Выберите класс объекта или тип литерала.
7. Добавьте фильтры, если они нужны.
8. Проверьте сгенерированный SPARQL-запрос.
9. Нажмите "Выполнить".
10. Просмотрите результат в таблице или графе.
11. При необходимости экспортируйте результат.

## Текстовый редактор SPARQL

### Что показывает интерфейс

- редактора с подсветкой синтаксиса;

6. Нажмите "Выполнить".
7. Просмотрите результат или сообщение об ошибке.

## NL-режим (кнопка «Микрофон»)

### Что показывает интерфейс

Документация должна включать скриншоты:
- кнопка «Микрофон» в визуальном конструкторе или текстовом редакторе;
- текстовое поле для ввода NL-запроса;
- диалог opt-in с предупреждением о передаче данных LLM-провайдеру;
- индикатор ожидания ответа от LLM;
- сгенерированный SPARQL или CYPHER, подставленный в текстовый редактор.

### Пошаговый сценарий

1. Откройте визуальный конструктор или текстовый редактор SPARQL/CYPHER.
2. Нажмите кнопку «Микрофон».
3. Введите запрос на естественном языке (например, «Найди все классы, у которых есть свойство status со значением active»).
4. Подтвердите opt-in: система предупредит, что запрос и контекст онтологии будут отправлены LLM-провайдеру.
5. Дождитесь генерации запроса.
6. Система подставит сгенерированный SPARQL или CYPHER в текстовый редактор.
7. Проверьте и при необходимости отредактируйте запрос.
8. Нажмите «Выполнить».
9. Просмотрите результат.

### Ошибки NL-режима

- Если вы отклонили opt-in — запрос не будет отправлен.
- Если LLM-провайдер недоступен — система уведомит и предложит повторить позже.
- Если сгенерированный запрос не прошёл синтаксическую валидацию — система уведомит и предложит отредактировать результат вручную.

## MCP-сервер (подключение внешних LLM-клиентов)

VEDO предоставляет MCP-сервер (Model Context Protocol) для внешних LLM-клиентов, таких как Claude Desktop, Cursor и другие AI-ассистенты.

### Что даёт MCP-сервер

LLM-клиент может через MCP:
- Отправлять NL-запросы к графу знаний VEDO.
- Получать структуру онтологии (классы, свойства, метки узлов, типы связей) для контекста.
- Выполнять SPARQL-запросы (SELECT/ASK) без написания кода.
- Выполнять CYPHER-запросы (MATCH/RETURN) без написания кода.

### Как подключиться

Настройте MCP-клиент на endpoint VEDO MCP-сервера. Адрес и параметры подключения указаны в документации администратора.

## Экспорт результатов

Пользователь может экспортировать результаты в форматы:
- CSV;
- JSON;
- Turtle (только для SPARQL SELECT с RDF-compatible bindings).

Инструкция должна показывать:
- где находится кнопка экспорта;
- как выбрать формат;
- как система сообщает об ошибке экспорта;
- чем отличается табличный CSV/JSON от RDF-ориентированного Turtle.

### Семантика Turtle export для SELECT

Turtle export для результатов `SELECT` доступен только для RDF-compatible bindings, то есть для результатов, которые можно представить как валидные RDF-тройки.

Правило:

- `?subject` должен быть IRI или blank node.
- `?predicate` должен быть IRI.
- `?object` должен быть IRI, blank node или типизированный литерал / литерал с языковым тегом.
- Plain literal без datatype или language tag не считается достаточным для Turtle export, если нет явного mapping на RDF-термы.
- Табличные результаты со скалярами, строками без RDF-контекста, числами без datatype или датами вне `xsd:dateTime` нужно экспортировать в CSV или JSON.

Если результат несовместим с Turtle, система возвращает `SPARQL_EXPORT_TURTLE_INCOMPATIBLE` и предлагает CSV/JSON. Когда post-MVP будет включён `CONSTRUCT`, RDF-графы следует получать через `CONSTRUCT`, а не через принудительное преобразование таблицы `SELECT` в Turtle.

Сообщение пользователю:

> Результаты этого SELECT-запроса нельзя экспортировать в Turtle. Используйте CSV или JSON для табличных данных либо CONSTRUCT для RDF-графов, когда CONSTRUCT будет включён.

## Безопасность и ограничения

### SPARQL
- Разрешены только SELECT/ASK.
- INSERT, DELETE, UPDATE и другие модифицирующие формы запрещены.
- SELECT-запрос должен содержать `LIMIT`, кроме согласованных исключений.

### CYPHER
- Разрешён только MATCH с RETURN.
- CREATE, DELETE, SET, MERGE и другие модифицирующие формы запрещены.
- MATCH-запрос должен содержать `LIMIT`, кроме согласованных исключений.

### Общие
- Запрос может быть остановлен по timeout (30 сек по умолчанию).
- Количество результатов ограничено (10 000 по умолчанию).
- Действует rate limiting на пользователя (10 запросов в минуту по умолчанию).
- Слишком сложный запрос блокируется по query complexity.
- Результат может быть ограничен правами доступа пользователя.

### NL-режим
- NL-запросы не отправляются LLM-провайдеру без явного opt-in пользователя.
- Opt-in запрашивается однократно на сессию с возможностью отозвать согласие.
- Все обращения к LLM фиксируются в audit-логе.

### MCP-сервер
- MCP-сервер не требует opt-in — обработка NL-запроса выполняется на стороне VEDO.
- Все запросы через MCP подлежат тем же ограничениям безопасности (read-only, LIMIT, timeout, rate limiting, query complexity, аудит).

Если запрос слишком сложный, User Guide должен рекомендовать:
- добавить более узкие фильтры;
- уменьшить глубину обхода графа;
- заменить широкие `OPTIONAL`/`UNION` / неограниченные property paths;
- добавить или уменьшить `LIMIT`;
- обратиться к инженеру знаний, если запрос нужен как регулярный отчёт.

- Скриншоты появятся после готовности UI-макетов.
- NL-режим: текст предупреждения opt-in и UX-сценарий уточняются на проектном ревью UI.
- MCP-сервер: документация по подключению и набор инструментов MCP уточняются после реализации.
