> Критичные ошибки UX для системы, где знания являются основным активом.

---

## Главный принцип

Любой UX-дефект, который создаёт риск потери данных, скрытого несохранения, незаметного конфликта или работы не в той версии/онтологии, считается минимум Major, а при отсутствии обходного пути — Showstopper.

Главное требование: RPO = 0 для committed ontology changes, RPO ≤ 5 минут для uncommitted draft изменений (localStorage/autosave). Все сценарии потери данных (сбой БД, обрыв соединения, краш браузера, race condition при коллаборации) должны быть перечислены в тест-плане и покрыты автоматизированной проверкой. Всё остальное решаемо правками в UI.

---

## Категории критичности

| Уровень | Обозначение | Влияние на пользователя | Действие при обнаружении |
|---------|-------------|--------------------------|--------------------------|
| Блокирующая (Showstopper) | P0 | Пользователь не может выполнить задачу вообще. Альтернативы нет. | Блокировка релиза |
| Серьёзная (Major) | P1 | Пользователь может выполнить задачу, но очень неудобно: много шагов, постоянные ошибки. | Исправить до следующего релиза или milestone |
| Значительная (Medium) | P2 | Снижает удовлетворённость, но не блокирует работу. | Исправляется в порядке очереди |
| Косметическая (Minor) | P3 | Не влияет на функциональность, только на эстетику. | Может быть отложена |

## Блокирующие ошибки: потеря данных и невозможность базовой работы

| ID | Ошибка | Описание | Проверка |
|----|--------|----------|----------|
| BS-1 | Нет автосохранения черновика | Пользователь заполнил сложную форму, страница обновилась, все данные потеряны. | UI сохраняет состояние формы в localStorage при каждом изменении и восстанавливает при загрузке. |
| BS-2 | "Успешно сохранено", но после перезагрузки данные исчезли | Пользователь получил уведомление об успешном создании класса, перезагрузил страницу, класса нет в дереве. | После ответа "успех" объект должен быть доступен из БД и не исчезать после reload. |
| BS-3 | Конфликт совместного редактирования перезаписывает чужие изменения без предупреждения | Два пользователя редактируют один класс, второй save теряет изменения первого. | WebSocket уведомляет о конфликте, блокировка обязательна, есть диалог: отменить / перезаписать / объединить. |
| BS-4 | Undo / rollback недоступен после опасного действия | Пользователь удалил или переместил класс, массово импортировал данные и не может отменить действие. | Опасные операции имеют undo в пределах сессии или rollback через историю операций. |
| BS-5 | Импорт применился частично, но UI не показывает что создано, пропущено или сломано | Пользователь загрузил файл, система сообщила "Импорт завершён", но часть классов не создана. | Итоговый отчёт показывает успешные элементы и ошибки с перечислением. |
| BS-6 | Ошибка прав доступа выглядит как техническая ошибка | Пользователь видит `Error 403: Forbidden` и думает, что система сломалась. | UI объясняет: "У вас недостаточно прав для удаления класса. Запросите роль Admin у владельца онтологии". |
| BS-7 | Пользователь работает не в той онтологии, ветке или версии | Пользователь думает, что редактирует `main`, но коммитит в `test`. | В шапке есть явный индикатор онтологии, ветки и версии; при коммите в не-main ветку есть предупреждение. |
| BS-8 | Сохранение не работает или работает с ошибкой | Пользователь редактирует класс, нажимает "Сохранить", изменения теряются или редактор молча не сохраняет. | Ошибка явно показана в UI, данные формы не теряются, пользователь может повторить сохранение. |
| BS-9 | Блокировка не снимается при закрытии вкладки | Пользователь закрыл браузер, оставив блокировку на классе; другой пользователь не может редактировать. | WebSocket unlock или TTL блокировки; блокировка не держится бесконечно. |
| BS-10 | Удаление класса без предупреждения | Пользователь случайно удалил класс с индивидами, нет подтверждения и отката. | Подтверждение удаления показывает последствия, каскадные изменения и возможность отката. |
| BS-11 | Ошибка валидации не отображается | Пользователь нажал "Сохранить", но ничего не произошло и непонятно, что исправить. | Ошибка видна в UI, привязана к полю или объекту, содержит действие для исправления. |
| BS-12 | Класс не добавляется в дерево после создания | Система сообщила "Успешно", но созданного класса нет в дереве. | Дерево обновляется без reload, созданный объект находится поиском и после перезагрузки. |
| BS-13 | Импорт валидной онтологии всегда падает | Валидный Turtle-файл из Protege не импортируется. | Валидный файл импортируется или пользователь получает детальный отчёт о неподдерживаемых конструкциях. |
| BS-14 | Экспорт из VEDO нельзя открыть в Protege | Обратная совместимость нарушена, пользователи не могут мигрировать. | Экспортированный Turtle/RDF/XML/OWL открывается в Protege. |

Критерий: если блокирующая ошибка встречается у более чем 5% пользователей, релиз задерживается.

## Серьёзные ошибки: ментальные модели, контекст и предсказуемость

| ID | Ошибка | Описание | Проверка |
|----|--------|----------|----------|
| MJ-1 | Нет понятного diff перед применением изменений | Пользователь делает merge или применяет патч, но не видит, какие классы и свойства изменятся. | Перед merge / импортом / патчем показывается diff: добавлено, удалено, изменено. |
| MJ-2 | Нет preview перед импортом | Пользователь загружает файл и не знает, сколько классов, свойств и индивидов будет добавлено. | Показывается статистика предпросмотра импорта. |
| MJ-3 | Ошибки валидации не привязаны к конкретному полю или узлу графа | Пользователь получает ошибку, но не понимает, к какому объекту она относится. | Поле или узел подсвечены, есть ссылка на объект с ошибкой. |
| MJ-4 | Технические термины без расшифровки | Сообщение "IRI не соответствует шаблону" непонятно пользователю. | UI пишет понятным языком: "Идентификатор (ID) класса должен начинаться с буквы и не содержать пробелов". |
| MJ-5 | Поиск показывает слишком много результатов без ранжирования | Поиск `Person` возвращает много нерелевантных результатов. | Ранжирование: точное совпадение, начинается с, содержит. |
| MJ-6 | UI не объясняет, что изменение сохранено локально, но ещё не закоммичено | Пользователь думает, что изменение попало в историю, хотя коммита не было. | Есть индикатор незакоммиченных изменений и предупреждение при закрытии. |
| MJ-7 | Пользователь не понимает разницу между "сохранить", "закоммитить", "экспортировать" | Пользователь нажимает "Сохранить" и считает, что данные уже в Git-истории. | Тултипы и иерархия действий: сохранить локально, закоммитить в версию, экспортировать в файл. |
| MJ-8 | Label не синхронизируется с ID пользователя понятным образом | Пользователь ввёл "Квадратное уравнение", получил ID с суффиксом и не понимает причину. | Коллизии ID объясняются, пользователь видит итоговый ID до сохранения. |
| MJ-9 | Родитель по умолчанию не `owl:Thing` | Новичок создаёт класс и не замечает, что выбран неправильный родитель. | Для новичкового сценария родитель по умолчанию `owl:Thing`, смена родителя явная. |
| MJ-10 | Правила валидации непонятны | Ошибка техническая и без подсказки по исправлению. | Ошибка содержит человеческое объяснение и пример допустимого значения. |
| MJ-11 | После переключения языка сбрасывается текущий класс | Пользователь теряет место в дереве. | Текущий объект и позиция сохраняются при смене языка. |
| MJ-12 | Drag-and-drop переместил класс без подтверждения | Пользователь случайно изменил иерархию и не заметил. | Опасные изменения иерархии требуют подтверждения или имеют undo. |
| MJ-13 | WebSocket-обновление сбрасывает навигацию | Уведомление или lock update возвращает дерево к корню. | Realtime-события не меняют текущий контекст пользователя. |
| MJ-14 | Непоследовательное поведение клавиш | Enter в одном месте сохраняет, в другом переносит строку без очевидности. | Поведение клавиш описано и стабильно по типам полей. |
| MJ-15 | Контекстное меню не соответствует реальным действиям | Команды выглядят безопасно, но имеют неожиданные последствия. | Контекстные действия соответствуют текущему объекту и показывают последствия. |
| MJ-16 | Разный цвет одного типа объектов в графе и дереве | Класс в дереве зелёный, в графе синий. | Палитра типов объектов единая во всех представлениях. |
| MJ-17 | Пользователь не видит разницы между классом и свойством | Новички путают сущности онтологии и моделируют неправильно. | UI визуально и текстово различает классы, свойства, индивиды. |

| MD-6 | Непонятно, какие поля обязательные | Пользователь узнаёт обязательность поля только после ошибки. | Обязательные поля отмечены визуально до сохранения. |
| MD-7 | Пустые состояния не помогают пользователю | Пустое дерево классов не содержит CTA. | Пустое состояние объясняет ситуацию и предлагает следующее действие. |

## QA-чек-лист перед релизом

- Автосохранение черновика: закрыл вкладку, открыл заново, данные восстановлены.
- Сохранение стабильно: после успешного ответа объект появляется в списке и не исчезает после перезагрузки.
- Блокировки: пользователь A редактирует, пользователь B видит предупреждение; после закрытия вкладки блокировка снимается по TTL.
- Undo / rollback: удаление класса можно отменить; массовый импорт можно откатить.
- Импорт с отчётом: показан список успехов и ошибок, не только счётчик.
- Права доступа: сообщение понятное, не техническое.
- Индикатор ветки/версии: название ветки видно в шапке, при коммите в не-main есть предупреждение.
- Diff перед merge: отображается список изменений.
- Preview импорта: отображается статистика перед импортом.
- Валидация с привязкой к полю: ошибка подсвечивает конкретное поле или объект.
- Сообщения без жаргона: технические термины объяснены человеческим языком.
- Индикатор незакоммиченных изменений: есть звёздочка, бейдж или явный список изменений.
- Пустые состояния: есть кнопка "Создать первый класс".
- Клавиатурная доступность: создание класса, редактирование и сохранение работают без мыши.
- Screen reader: ошибки формы читаются.

Часть пунктов должна быть автоматизирована через Playwright, часть проверяется вручную перед каждым релизом.
