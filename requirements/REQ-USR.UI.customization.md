---

## Принципиальная позиция

Корпоративные стандарты UI зависят от заказчика, и для on-premise могут потребовать адаптации. Для SaaS-мультитенантной версии VEDO Core не поддерживает кастомные темы для каждого арендатора, потому что это слишком дорого в разработке, тестировании и поддержке.

Стратегия разделяется по модели развёртывания.

| Модель развёртывания | Кастомизация UI | Ответственный | Примеры |
|----------------------|-----------------|---------------|---------|
| SaaS (мультитенант) | Нет, кроме светлой/тёмной темы | VEDO | Все клиенты видят одинаковый интерфейс |
| On-premise | Полная кастомизация | Заказчик и его команда разработки | Логотип, цвета, шрифты, расположение элементов |
| Приватное облако (Managed VEDO) | Ограниченная кастомизация через CSS-переменные | VEDO по запросу заказчика | Цветовая схема и логотип, но не кастомные компоненты |

---

## Типовые запросы Enterprise-клиентов

| Компонент UI | Тип кастомизации | Оценка | Пример |
|--------------|------------------|--------|--------|
| Цветовая схема | CSS-переменные: primary, secondary, accent | 8 часов | Заменить `#4CAF50` на брендовый синий `#0050B3` |
| Шрифты | Локальные шрифты через `@font-face` | 4 часа | Использовать корпоративный шрифт, например Roboto или PT Sans |
| Логотип | Замена логотипа VEDO, favicon, логотипа на странице входа | 2 часа | Вместо VEDO — логотип заказчика |
| Страница входа | Возможность скрытия атрибуции VEDO | 2 часа | Убрать `Powered by VEDO` |
| Локализация | Полный перевод интерфейса на язык заказчика | 40+ часов | Полный перевод на казахский или белорусский |
| Брендирование ошибок | Кастомные страницы 404/403 | 4 часа | Страница 404 с корпоративным дизайном |

## Архитектура кастомизации

### CSS-переменные

MVP-подход для темизации: стандартная тема VEDO задаёт CSS-переменные, которые могут быть переопределены в on-premise или managed-окружении.

```css
:root {
  --vedo-primary: #4CAF50;
  --vedo-primary-dark: #388E3C;
  --vedo-primary-light: #81C784;
  --vedo-secondary: #2196F3;
  --vedo-accent: #FF9800;
  --vedo-background: #FFFFFF;
  --vedo-surface: #F5F5F5;
  --vedo-text: #212121;
  --vedo-text-secondary: #757575;
  --vedo-border: #E0E0E0;
  --vedo-error: #F44336;
  --vedo-warning: #FFC107;
  --vedo-success: #4CAF50;
  --vedo-font-family: 'Inter', system-ui, -apple-system, sans-serif;
}
```

Заказчик может создать `theme/custom.css` и переопределить переменные.

### Переопределения заказчика

Для on-premise версии допускается папка `customer-overrides/`, которая не входит в Git-репозиторий VEDO, но подключается при сборке через Vite alias. Если заказчик предоставляет `customer-overrides/theme.css`, файл подключается после стандартной темы.

Кастомные компоненты допускаются для ограниченного набора областей: логотип, favicon, футер, атрибуция, страницы 404/403. Полная замена рабочих редакторов не входит в базовую модель кастомизации.

## Что нельзя кастомизировать

| Компонент | Причина | Компромисс |
|-----------|---------|------------|
| Редактор графа 2D/3D | Слишком сложно, ломается вёрстка и UX-согласованность | Можно менять цвета узлов через CSS-переменные, но нельзя менять алгоритм layout |
| Структура карточек и поля ввода | Зависит от модели данных и бэкенда | Можно переопределить CSS: размеры, отступы, цвета |
| Терминология | Управляется через i18n | Можно перевести на другой язык, но нельзя переименовать `Class` в `Сущность` без изменения кода |
| Кастомизация через админку | Слишком дорого для MVP | Настройка через файлы, env и сборку on-premise |

## Политика брендирования

| Версия | Логотип VEDO | Атрибуция `Powered by VEDO` | Цвета VEDO | Цена / статус |
|--------|--------------|-----------------------------|------------|---------------|
| SaaS (бесплатный тариф) | Виден | Видна | Стандартные | 0 |
| SaaS (Pro / Team) | Можно убрать за доплату | Можно убрать за доплату | Стандартные | +$200/мес |
| On-premise (лицензия) | Можно убрать | Можно убрать | Можно изменить | Фикс |
| SaaS Enterprise (выделенный экземпляр) | Можно убрать | Можно убрать | Можно изменить | Индивидуально |

## Фазы реализации

| Задача | Оценка | Фаза |
|--------|--------|------|
| CSS-переменные для основных цветов | 3 человеко-дня | MVP |
| Поддержка кастомного логотипа через env или файл | 2 человеко-дня | MVP |
| Динамический импорт кастомных компонентов: логотип, футер | 3 человеко-дня | P2 Enterprise |
| Поддержка переопределения переводов i18n | 5 человеко-дней | P2 |
| Документация для заказчика по кастомизации | 3 человеко-дня | P2 |
| Интерфейс выбора темы в админке | 5 человеко-дней | P3 по требованию |

## Решение по версиям

### SaaS MVP

- Только базовая кастомизация: светлая/тёмная тема через CSS-переменные.
- Без поддержки логотипа заказчика в мультитенантном SaaS.
- Все клиенты видят одинаковый интерфейс.

### On-premise P2 / Enterprise

- Полная поддержка кастомизации через CSS-переменные.
- Замена логотипа и favicon через переменные окружения или файлы в `customer-overrides/`.
- Отключение атрибуции по лицензионному ключу.
- Локализация через i18n и файлы переводов.
- Кастомные компоненты только в явно разрешённых слотах.

### Приватное облако P3

- Ограниченная кастомизация: цвета и логотип.
- Без полной замены компонентов.

## Итог E1.3

| Аспект | Решение | Статус | Примечание |
|--------|---------|--------|------------|
| Базовая кастомизация: цвета, шрифты | CSS-переменные, переопределяемые заказчиком | P2 | MVP только светлая/тёмная тема |
| Замена логотипа | Файл/env или динамический импорт из `customer-overrides/` | P2 | Требует пересборки и инструкции |
| Удаление атрибуции | По лицензионному ключу или env-переменной | P2 | В Enterprise-версиях |
| Локализация | i18n + возможность добавления новых языков | P2 | Русский и английский в MVP |
| Кастомные страницы ошибок | Переопределение компонентов 404/403 | P3 | Низкий приоритет |
| Кастомизация через админку | Не поддерживается | Нет | Слишком сложно для MVP |

Главный вывод: MVP не включает корпоративную кастомизацию, кроме светлой/тёмной темы. Полная адаптация под бренд заказчика относится к on-premise версии P2.
