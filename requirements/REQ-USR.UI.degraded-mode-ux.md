## Что описывает

Определяет обязательный деградированный режим для сохранения доступности базовых сценариев при отказах зависимостей.

## Триггеры входа в деградированный режим

Система должна автоматически входить в degraded mode, если выполняется хотя бы одно условие:

- `gateway_5xx_rate > 2%` в течение 2 минут;
- `auth_token_issuance_p99 > 2s` в течение 5 минут;
- недоступность primary data-store > 30 секунд;
- межрегиональная потеря связности > 20% packet loss в течение 1 минуты.

## Обязательное поведение в degraded mode

| Сценарий | Требование |
|---|---|
| Просмотр онтологии | Доступен (read-only), SLO >= 99.9% |
| Аутентификация | Доступна для already-known users, success >= 99.5% |
| Изменение данных | Отклоняется с кодом `503_DEGRADED_WRITE_BLOCKED` |
| Экспорт данных | Доступен только для ранее запущенных задач |

## Ограничения и время восстановления

- Переход в degraded mode: <= 60 секунд с момента срабатывания триггера.
- Выход из degraded mode разрешен только после 10 минут стабильных метрик ниже порогов.
- Максимальная длительность непрерывного degraded mode без executive escalation: 4 часа.

## UX и API семантика

- UI обязан показывать баннер "Read-only degraded mode" с причиной и ETA следующего обновления.
- API write endpoints обязаны возвращать детерминированный код ошибки `503_DEGRADED_WRITE_BLOCKED`.
- Доля write-запросов, отклоненных без корректного кода в degraded mode: 0%.

## Бизнес-правила

- Полное отключение системы без попытки деградации запрещено, кроме сценариев security containment.
- В degraded mode приоритетом является целостность данных над функциональной полнотой.
- Все входы/выходы degraded mode должны фиксироваться в audit trail.
