## Назначение документа

Этот артефакт фиксирует нефункциональные UX-требования, которые формируют у пользователя эмоцию "вау" и привычку возвращаться в VEDO Core. Документ обязателен для Product, UX, Frontend, Backend и QA при планировании, разработке и приёмке.

Целевая эмоция: пользователь рекомендует VEDO коллеге не из-за "набора функций", а из-за ощущения скорости, контроля и удовольствия от работы со сложной онтологией.

## Продуктовый контекст

- Продукт: VEDO Core (B2B-платформа для инженеров знаний, архитекторов, аналитиков).
- Бенчмарк по качеству UX: VS Code, Figma, Notion, Linear, Git.
- Конкурентный фон: Protégé закрывает базовую функциональность, но не даёт эмоциональной привязанности.

## Принципы вайб-эффекта

| Принцип | Смысл для VEDO Core |
|---|---|
| Скорость как базовая эмоция | UI ощущается мгновенным; анимации усиливают, а не тормозят действие |
| Угадывание желаний | Система предлагает следующий шаг: smart defaults, автодополнение, шаблоны |
| Эстетика сложного | Сложные графы/иерархии читаются легко и выглядят визуально качественно |
| Мастерство (клавиатура) | Опытный пользователь может делать ключевые операции без мыши |
| Безопасность и контроль | Пользователь понимает последствия изменений и может откатить ошибку |
| Человеческое лицо | Сообщения и детали интерфейса создают характер и чувство заботы |

## Реестр UX Delight требований

### Категория A: Скорость и отзывчивость (P0)

| ID | Требование | Описание | Измерение |
|---|---|---|---|
| D-01 | Мгновенный отклик UI | Все операции ввода (клик, ввод текста, переключение вкладок) выполняются за `< 100 мс` (p95) | Browser Performance API |
| D-02 | Оптимистичный UI | При create/update/delete UI обновляется сразу; при ошибке выполняется откат | Визуальная проверка + e2e |
| D-03 | Прогресс-бар только при `> 200 мс` | Индикатор долгой операции показывается только после порога 200 мс | UI-метрика события рендера |
| D-04 | Зелёная вспышка при сохранении | Успешно сохранённый элемент подсвечивается зелёным на 200 мс | Визуальная проверка + snapshot |

## Метрики успеха (vibe metrics)

| Метрика | Измерение | Цель | Категория |
|---|---|---|---|
| Time-to-first-action | Юзабилити-тест, 5 пользователей | `< 5 сек` | Скорость |
| DAU/MAU (Stickiness) | Product analytics | `> 40%` | Общая |
| NPS после 10 часов | In-app опрос | `> 40` | Общая |
| Доля пользователей палитры команд | Product analytics | `> 30%` активных | Мастерство |
| Доля пользователей со сниппетами | Product analytics | `> 20%` активных | Мастерство |
| Частота использования Undo | Product analytics | `> 0.5` действия на пользователя в день | Безопасность |
| Вирусный коэффициент (k-factor) | Реферальные приглашения | `> 0.1` | Человеческое лицо |

## Технические ограничения и компромиссы

| Требование | Компромисс | Решение |
|---|---|---|
| D-01 | Часть операций физически дольше 100 мс (например, экспорт 10 000 триплетов) | Для долгих операций показывать индикатор по D-03 |
| D-10 | Анимации могут просаживать UX на очень больших графах | Анимировать только батчи `< 50` узлов; выше порога использовать мгновенное раскрытие |

## Критерии приёмки по категориям

- Скорость: p95 интеракций в UI `< 100 мс`, отсутствие «ложных» спиннеров до 200 мс.
- Угадывание: smart defaults применяются автоматически в 100% базовых сценариев создания сущностей.
- Эстетика сложного: граф читается без визуального шума; миникарта и тепловая карта доступны без падения FPS.
- Мастерство: все ключевые сценарии создания/поиска/навигации выполнимы без мыши.
- Безопасность: удаление без импакта запрещено; откат версии доступен из контекста сущности.
- Человеческое лицо: критические ошибки понятны человеку и дают следующий шаг, а не только код.
- Микро-интеракции: визуальные сигналы состояния консистентны (успех/ошибка/hover/смена версии).

## Примеры реализации

### D-02 Оптимистичный UI

```typescript
const createClass = async (className: string) => {
  const tempId = `temp-${Date.now()}`;
  treeStore.addClass({ id: tempId, name: className, isPending: true });

  try {
    const saved = await api.createClass(className);
    treeStore.replaceClass(tempId, saved);
    showSuccessFlash();
  } catch {
    treeStore.removeClass(tempId);
    showErrorFlash();
    showErrorMessage();
  }
};
```

const snippets = {

### D-19 Предпросмотр удаления

```typescript
const deleteClass = async (classId: string) => {
  const impact = await api.getDeleteImpact(classId);
  const confirmed = await showImpactModal({
    message: `Класс используется:`,
    details: [
      `domain в ${impact.objectProperties.length} свойствах`,
      `ссылки от ${impact.individuals.length} индивидов`,
    ],
  });

  if (confirmed) {
    await api.deleteClass(classId);
  }
};
```
