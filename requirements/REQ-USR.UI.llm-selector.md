# Выбор LLM-провайдера пользователем

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-USR.UI.llm-selector |
| **Уровень** | USR |
| **Атрибут качества** | Usability |
| **Приоритет** | P1 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | Уточнение стейкхолдера по вопросу 1.1 матрицы качества M2 |

---

## Назначение

Предоставить пользователю возможность выбора LLM-провайдера в интерфейсе AI-функций, когда доступно несколько провайдеров.

## Требование

В интерфейсе NL→OWL и NL-режима запросов, если для онтологии разрешены внешние LLM и сконфигурировано более одного провайдера, отображается селектор:

- **Элемент:** выпадающий список или группа radio-кнопок.
- **Метка:** «LLM-провайдер».
- **Значение по умолчанию:** провайдер, установленный в настройках tenant как `default`.
- **Варианты:** список провайдеров из конфигурации tenant (например: `OpenAI GPT-4`, `Anthropic Claude`).

**Правила отображения:**

| Развёртывание | Уровень онтологии | Внешние разрешены? | Селектор |
|---|---|---|---|
| SaaS | Public | Да | Отображается (только внешние) |
| SaaS | Internal/Private | Нет (по умолчанию) | AI-функции заблокированы |
| SaaS | Internal/Private | Да (админ разрешил) | Отображается (только внешние) |
| On-premise | Любой | N/A (только локальная) | Скрыт — используется только локальная LLM |

## Критерии приёмки

1. Селектор отображается, только если доступно > 1 провайдера.
2. Список провайдеров соответствует конфигурации tenant.
3. По умолчанию выбран tenant-default провайдер.
4. При смене провайдера последующие запросы направляются выбранному LLM-адаптеру.
5. В on-premise селектор скрыт.
6. Для заблокированных онтологий селектор скрыт.
