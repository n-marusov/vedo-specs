## Обзор

Публичный лендинг — первая страница, которую видит любой посетитель без авторизации. Он решает три задачи: (1) **объяснить категорию** — что такое «социальный хаб онтологий» и зачем он нужен; (2) **снизить порог входа** — показать живую демо-онтологию с кликабельным графом, сняв страх не-эксперта (P4/P5); (3) **конвертировать посетителя** — в регистрацию (Community) или контакт с отделом продаж (Enterprise).

Лендинг основан на анализе публичных страниц GitHub и GitLab (`.ai-factory/RESEARCH.md`, сессия 2026-08-01), но адаптирован под новую, не устоявшуюся категорию VEDO.

### Описание

**1.1. Контент hero-секции**

Hero-секция содержит **ровно одну строку позиционирования** — из vision.md §1.5:

> **VEDO Hub — GitHub + Hugging Face для онтологий: социальный хаб, API-инфраструктура и LLM-генерация в одном продукте.**

Под positioning statement располагается **подзаголовок из трёх коротких фраз** (каждая ≤ 80 символов), закрывающих ключевые сценарии не-эксперта:

1. *«Создайте онтологию из документа за 1 минуту — без знания OWL»* (G5/P12)
2. *«Работайте командой: ветки, слияния, ревью — как в Git»* (G2/P2)
3. *«Публикуйте с DOI, форкайте, цитируйте»* (G6/P5)

**1.2. Call-to-Action (CTA)**

Hero содержит **ровно два CTA**, расположенных рядом:

| CTA | Текст | Действие | Целевая аудитория |
|-----|-------|----------|-------------------|
| **Primary** | «Создать аккаунт бесплатно» | Переход на `/login` или Keycloak-регистрацию | Community (bottom-up) |
| **Secondary** | «Смотреть демо» | Прокрутка к секции R2 (демо-онтологии) | Не-эксперт, исследователь |

**Правила расположения CTA:** primary слева/сверху, secondary справа/снизу. Primary должен быть визуально доминирующим (цвет, размер). Оба видны без прокрутки на 1920×1080.

**1.3. Фоновый элемент**

Фоновый элемент — **абстрактная визуализация графа онтологии** (статическая или минимально анимированная), не перегружающая восприятие текста. Никаких скриншотов интерфейса в hero (скриншоты устаревают, граф — вечная метафора).

### Критерии приёмки

- [ ] Посетитель без авторизации открывает посадочную страницу → видит positioning statement над сгибом
- [ ] Positioning statement читается за ≤ 10 секунд не-экспертом (юзабилити-тест: 5 респондентов без опыта онтологий)
- [ ] Primary CTA кликабелен, ведёт на регистрацию
- [ ] Secondary CTA кликабелен, ведёт к демо-секции (R2)
- [ ] Hero не требует JS для отображения текста и CTA (graceful degradation)

- Ограничение MVP: отображать до 200 узлов. При превышении — автоматическая фильтрация по centrality или ручной zoom-to-fit
- Тёмная тема — как в `OntologyWorkspace`

## Требование R5: REQ-NFR.UI.public-landing.performance — Производительность лендинга

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-NFR.UI.public-landing.performance |
| **Уровень** | NFR |
| **Атрибут качества** | Performance |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | G1 «< 1 сек на 1M аксиом» (философия производительности VEDO) |
| **Критерии приёмки** | Lighthouse Performance ≥ 90 (desktop); First Contentful Paint ≤ 1.0 сек; Time to Interactive ≤ 1.5 сек (p95) |

### Описание

**5.1. Бюджет загрузки**

Лендинг развёртывается как отдельное лёгкое приложение (`publish-browse-ui`, nginx), **не** внутри основного `frontend` (Apollo, Keycloak, Vue Flow в бандле лендинга недопустимы). Ограничения:

| Метрика | Цель |
|---------|------|
| Общий размер страницы (сжатый) | ≤ 200 KB |
| JS-бандл (сжатый) | ≤ 50 KB (только карточки демо + лёгкая логика) |
| First Contentful Paint | ≤ 1.0 сек (p95, desktop, Fast 3G) |
| Time to Interactive | ≤ 1.5 сек (p95) |
| Lighthouse Performance | ≥ 90 |
| Запросов при первой загрузке | ≤ 10 |

**5.2. Vue Flow для демо-графа**

Vue Flow-компонент (R2) загружается **лениво** (dynamic import) — только при переходе на `/public/{slug}`, не на главном лендинге. JS-бандл Vue Flow (≈ 80 KB) не входит в бюджет лендинга.

**5.3. Без JS**

Лендинг должен отображать hero, CTA и карточки демо-проектов **без JavaScript** (graceful degradation). Граф (Vue Flow) — только с JS.

### Критерии приёмки

- [ ] Lighthouse Performance ≥ 90 (desktop) при запуске через `npx lighthouse`
- [ ] First Contentful Paint ≤ 1.0 сек на Fast 3G (p95)
- [ ] Общий размер страницы ≤ 200 KB (сжатый)
- [ ] JS-бандл лендинга (без Vue Flow) ≤ 50 KB (сжатый)
- [ ] Hero и карточки демо отображаются с отключённым JavaScript

## Требование R7: REQ-FUN.UI.public-landing.deployment — Развёртывание лендинга

| Атрибут | Значение |
|---------|----------|
| **ID** | REQ-FUN.UI.public-landing.deployment |
| **Уровень** | FUN |
| **Атрибут качества** | Functionality |
| **Приоритет** | P0 |
| **Статус** | ЧЕРНОВИК |
| **Источник** | ADR-DES.UI.public-landing-architecture; ROADMAP M5 |
| **Критерии приёмки** | Лендинг развёрнут в `publish-browse-ui`; корневой URL отвечает без авторизации; `docker-compose` health check зелёный |

### Описание

**7.1. Хостинг**

- Лендинг развёртывается в существующем сервисе `publish-browse-ui` (Vue 3, nginx)
- `publish-browse-ui` — отдельный Docker-контейнер, независимый от основного `frontend`
- Nginx обслуживает статику (HTML/CSS/JS) и проксирует API-запросы к `public-browse-api`
- Корневой URL (`/`) возвращает лендинг; `/public/{slug}` — просмотрщик демо-онтологии

**7.2. Интеграция с public-browse-api**

- `publish-browse-ui` → HTTP → `public-browse-api` (Rust, порт из `.env.dev`)
- `public-browse-api` → gRPC → `ontology-service` (за метаданными демо-проектов: classCount, propertyCount, граф)
- БЕЗ Keycloak/JWT — публичный доступ

**7.3. Docker Compose**

- `publish-browse-ui` добавлен в `deploy/docker-compose.yml` (если ещё нет)
- Health check: `curl http://publish-browse-ui:PORT/` → 200
- Зависимость: `public-browse-api` (health check должен пройти до старта `publish-browse-ui`)

### Критерии приёмки

- [ ] `docker compose up` → лендинг доступен на порту `publish-browse-ui`
- [ ] `curl http://localhost:PORT/` → 200, HTML содержит positioning statement (R1)
- [ ] `curl http://localhost:PORT/public/{demo-slug}` → 200, HTML содержит контейнер для Vue Flow
- [ ] Health check `publish-browse-ui` зелёный в `docker compose ps`

- [ ] Путь «лендинг → демо → регистрация»: ≤ 3 клика

## Референсные лендинги (анализ и заимствования)

Анализ проведён в `.ai-factory/RESEARCH.md` (сессия 2026-08-01). Ниже — извлечённые приёмы с указанием, что именно брать и чего избегать для VEDO Hub.

### GitHub (`github.com`)

Страница: продуктовая, один домен с продуктом. Воронка: bottom-up (массовая регистрация).

| Взять | Обоснование для VEDO | Применяется в REQ |
|-------|---------------------|--------------------|
| **Email-поле в hero** — единственное поле, один шаг до регистрации | G5: снижение порога входа. Не-эксперт не должен заполнять форму из 10 полей | R1 (primary CTA) |
| **«Try GitHub Copilot»** — второй CTA для тех, кто не готов к регистрации | Аналог: «Смотреть демо» — снимает страх первого шага, показывает продукт до коммитмента | R1 (secondary CTA) |
| **Экосистемный нарратив** — «from your first line of code to final deployment» | VEDO: «от документа до публикации с DOI» — сквозной сторителлинг жизненного цикла онтологии | R1 (подзаголовок из 3 фраз) |
| **Конкретные метрики безопасности** — «70% MTTR reduction», «8.3M secret leaks stopped» | VEDO: «45 сек → <1 сек», «2 часа → 10 минут» — каждая метрика привязана к сценарию из vision (P1–P13) | R4 (метрики) |

| Избегать | Причина |
|----------|---------|
| **Feature-soup** — Copilot, Actions, Codespaces, Mobile, Marketplace, Security, Projects, Issues, Discussions, Sponsors — новичок не понимает, с чего начать | У VEDO 16 функциональных доменов — соблазн показать всё. Лендинг фокусируется на **ровно 4 pillars** из vision.md §1.5: хаб, LLM-генерация, визуальный SPARQL, API |
| **Размытый hero** — «The future of building happens together» — красиво, но пусто для незнакомого с категорией | VEDO — новая категория. Hero должен быть функциональным: **«GitHub + Hugging Face для онтологий»** — мгновенно якорь к понятным категориям |
| **Скрытый enterprise-фаннел** — нет цен, нет «Contact sales» на лендинге | VEDO использует dual-track CTA как GitLab: primary «Создать аккаунт» (Community) + secondary путь к enterprise (через роль-секцию DevOps или футер) |

### GitLab (`about.gitlab.com`)

Страница: корпоративно-маркетинговая, отдельный домен от продукта. Воронка: top-down (enterprise-лиды).

| Взять | Обоснование для VEDO | Применяется в REQ |
|-------|---------------------|--------------------|
| **Чёткое позиционирование в одну строку** — «intelligent orchestration platform for DevSecOps» | VEDO: «социальный хаб, API-инфраструктура и LLM-генерация в одном продукте» — из vision.md §1.5 | R1 (positioning statement) |
| **Dual-track CTA** — «Try for free» + «Contact sales» | VEDO: «Создать аккаунт бесплатно» (Community) + путь к enterprise через роль-секции и футер | R1 (CTA), R3 (ролевые CTA) |
| **Метрики с контекстом** — «4 hours saved per engineer per week», «82% decrease in cycle time» | VEDO: метрики «Было → Стало» с указанием сценария — **не более 4**, каждая с источником | R4 (метрики) |
| **Open-core заявление** — «one platform for teams of every size», гибкое ценообразование (GitLab Flex) | VEDO: «Публичные онтологии — бесплатно и навсегда. Приватные проекты — по подписке» | R4 (open-core banner) |

| Избегать | Причина |
|----------|---------|
| **Жаргонная стена** — «Duo Agent Platform», «data plane», «guardrails», «SBOM», «air-gapped» — не-эксперт не проходит даже hero | VEDO — новая категория. Термин «онтология» уже барьер. Лендинг объясняет ПРОСТО: «создайте из документа», «схема с классами и связями» |
| **Овервhelm метрик** — 11 разных цифр в карусели без источников снижают доверие | VEDO: ровно 4 метрики, каждая с привязкой к сценарию из vision (P1–P13) |
| **Конкурирующие CTA в hero** — «Try for free» + «Learn more» — посетитель получает выбор вместо действия | VEDO: один primary CTA и один secondary, с явной визуальной иерархией |
| **Индустриальная карусель** (финтех, госсектор, телеком, automotive) — для enterprise-продаж, не для ранней стадии | VEDO: сегментация **по ролям**, не по индустриям — из vision.md §3.1 (5 ролей: аналитик, учёный, онтолог, разработчик, DevOps) |
