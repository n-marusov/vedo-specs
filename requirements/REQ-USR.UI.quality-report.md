## Назначение

Определить формат и содержание отчёта о качестве сгенерированной NL→OWL онтологии, отображаемого пользователю перед сохранением.

## Требование

После генерации NL→OWL система отображает пользователю отчёт о качестве. Отчёт является частью экрана предпросмотра и помогает пользователю принять решение: сохранить онтологию, уточнить описание или перейти к ручному редактированию.

**Содержание отчёта:**

| Метрика | Возможные статусы | Формулировка |
|---------|-------------------|--------------|
| Синтаксическая валидность | ✅ PASS / ❌ FAIL | «OWL синтаксис корректен» / «Обнаружены синтаксические ошибки: [детали]» |
| Циклические зависимости | ✅ PASS / ❌ FAIL | «Иерархия классов не содержит циклов» / «Обнаружены циклы: [список классов]» |
| Корректность иерархии | ✅ PASS / ⚠️ WARN / ❌ FAIL | «[X]% классов имеют корректную иерархию (порог: ≥ 80%)» |
| Корректность свойств | ✅ PASS / ⚠️ WARN / ❌ FAIL | «[Y]% свойств имеют корректный domain/range (порог: ≥ 75%)» |
| Confidence (LLM) | 🟢 Высокая / 🟡 Средняя / 🔴 Низкая | Оценка уверенности модели в результате |

**Визуализация статусов:**

- ✅ PASS — зелёный индикатор.
- ⚠️ WARN — жёлтый индикатор, некритичное предупреждение.
- ❌ FAIL — красный индикатор, критическая ошибка.

**Поведение в зависимости от статуса:**

| Статус | Можно сохранить? | Действие пользователя |
|--------|-----------------|----------------------|
| Все PASS | Да | Сохранить онтологию |
| Есть WARN | Да (с предупреждением) | Сохранить или уточнить |
| Есть FAIL (критический) | Нет | Исправить ошибки или уточнить описание |
| Есть FAIL (некритический) | Да (с предупреждением) | Сохранить с осознанием рисков или уточнить |

## Критерии приёмки

1. Отчёт отображается в экране предпросмотра сгенерированной онтологии.
2. Каждая метрика имеет визуальный статус (зелёный/жёлтый/красный) и текстовое описание.
3. При FAIL по критическим метрикам (синтаксис, циклы) кнопка «Сохранить» заблокирована.
4. При WARN или FAIL пользователь видит конкретные рекомендации: «Попробуйте уточнить описание: укажите, что класс X является подклассом Y».
5. Отчёт о качестве сохраняется в метаданных онтологии (поле `quality_report` в формате JSON) для последующего аудита.
