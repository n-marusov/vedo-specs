## Что это

VEDO Core поддерживает выполнение запросов к графу знаний через графический интерфейс и программные endpoints. Поддерживаются два языка запросов, каждый с тремя режимами ввода:

### SPARQL 1.1
- **Визуальный конструктор** — для аналитиков и бизнес-пользователей.
- **Текстовый редактор SPARQL** — для опытных инженеров.
- **NL-режим (кнопка «Микрофон»)** — естественный язык → SPARQL через LLM.

SPARQL 1.1 — стандарт W3C для RDF, основной язык семантических запросов.

### CYPHER
- **Визуальный конструктор** — для аналитиков и бизнес-пользователей.
- **Текстовый редактор CYPHER** — для опытных инженеров.
- **NL-режим (кнопка «Микрофон»)** — естественный язык → CYPHER через LLM.

CYPHER — язык запросов Neo4j, основной язык для графовых запросов по меткам узлов и типам связей.

### MCP-сервер (внешние LLM-клиенты)
VEDO предоставляет MCP-сервер с инструментами для запросов к графу знаний. LLM-клиент (Claude Desktop, Cursor и др.) через MCP вызывает инструменты VEDO; MCP-сервер принимает NL-запрос, преобразует его в SPARQL или CYPHER и возвращает результат. MCP-сервер не требует opt-in — обработка выполняется на стороне VEDO.

## Функциональные требования

### REQ-FR-SPARQL-GUI-0001 Режимы работы SPARQL GUI

GUI должен поддерживать три режима работы со SPARQL:
- визуальный конструктор;
- текстовый редактор SPARQL;
- NL-режим (кнопка «Микрофон»).

### REQ-FR-SPARQL-GUI-0002 Визуальный конструктор

Пользователь выбирает:
- класс субъекта;
- свойство;
- класс объекта или литерал;
- фильтры.

Система генерирует SPARQL-запрос на основе выбранных элементов текущей онтологии.

### REQ-FR-SPARQL-GUI-0003 Текстовый редактор

Текстовый редактор должен поддерживать:
- подсветку синтаксиса;
- автодополнение префиксов;
- автодополнение классов и свойств из текущей онтологии;
- синтаксическую валидацию запроса без выполнения.

### REQ-FR-SPARQL-GUI-0004 Интроспекция

Клиент должен получать список классов, свойств и их типов через introspection текущей онтологии.

Introspection используется для динамического построения Query Builder, потому что граф и онтология пользователя могут быть произвольными, а статическая GraphQL-схема не покрывает все возможные комбинации.

Wire format для introspection в MVP: REST JSON на публичном API Gateway.

Фронтенд и визуальный конструктор используют REST JSON через API Gateway для быстрой загрузки списков классов, свойств, типов данных и индивидов. Эти endpoints не являются REST API Ontology Service: API Gateway должен преобразовывать их во внутренние gRPC/protobuf вызовы Ontology Service. Основные публичные endpoints:
- `GET /api/v1/ontologies/{id}/schema` - полная TBox-схема в JSON для начальной загрузки UI, кешируется клиентом на 5 минут.
- `GET /api/v1/ontologies/{id}/classes` - список классов с пагинацией.
- `GET /api/v1/ontologies/{id}/properties` - список свойств с пагинацией.
- `GET /api/v1/ontologies/{id}/individuals` - список индивидов для продвинутого конструктора.

SPARQL Service Description остаётся стандартным способом для внешних семантических клиентов. GraphQL не используется как introspection wire format, потому что он смешивает мета-уровень онтологии с frontend-навигацией; GraphQL остаётся для навигации по связям и чтения графовых фрагментов.

### REQ-FR-SPARQL-GUI-0005 Выполнение запроса через endpoint

Публичный REST endpoint API Gateway `/api/v1/sparql` принимает SPARQL-запросы и выполняет только read-only операции SELECT/ASK. API Gateway не проксирует запрос на REST-хендлер Ontology Service; он вызывает внутренний gRPC метод Ontology Service для валидации и выполнения SPARQL.

В MVP разрешены только `SELECT` и `ASK`. `DESCRIBE` и `CONSTRUCT` не выполняются в MVP даже для ролей `editor` и `admin`; endpoint должен отклонять их стабильным кодом `SPARQL_OPERATION_NOT_ALLOWED`. Архитектура авторизации должна при этом закладывать role-gated permissions, чтобы на следующем этапе можно было включить `DESCRIBE`/`CONSTRUCT` конфигурацией ролей и лимитов, без переписывания логики endpoint.

Планируемая post-MVP модель разрешений:

```yaml
sparql_permissions:
  SELECT: [viewer, editor, admin]
  ASK: [viewer, editor, admin]
  DESCRIBE: [editor, admin]
  CONSTRUCT: [editor, admin]
```

Для post-MVP включения `DESCRIBE`/`CONSTRUCT` обязательны отдельные лимиты: максимум 1000 возвращаемых RDF-триплетов, запрет внешних IRI/federation-запросов и timeout не больше 15 секунд.

Endpoint возвращает результаты в форматах:
- JSON;
- CSV;
- Turtle.

### REQ-FR-SPARQL-GUI-0006 Экспорт результатов

Из GUI пользователь может выгрузить результаты выполнения запроса в CSV, JSON или Turtle.

Turtle export для `SELECT` доступен только для RDF-compatible bindings. Система формирует Turtle только когда результат можно представить как валидные RDF-тройки: subject = IRI или blank node, predicate = IRI, object = IRI, blank node, типизированный литерал или литерал с языковым тегом. Plain literals без datatype/language tag и табличные scalar values не экспортируются в Turtle без явного mapping.

Если `SELECT` result содержит mixed/scalar bindings без RDF-структуры, endpoint возвращает `SPARQL_EXPORT_TURTLE_INCOMPATIBLE` и предлагает CSV/JSON. Принудительное преобразование всех bindings в blank-node строки запрещено, потому что создаёт нестандартный Turtle и теряет семантику. Для RDF-графа post-MVP основным способом станет `CONSTRUCT` после включения этой операции по ролям и лимитам.

### REQ-FR-SPARQL-GUI-0007 Библиотека запросов

Пользователь может сохранять часто используемые запросы в библиотеку, загружать их повторно и удалять больше не нужные запросы.

В MVP библиотека сохранённых запросов хранится в PostgreSQL как пользовательские настройки, в таблице `user_saved_sparql_queries`. Отдельное доменное хранилище или `QueryLibraryService` не входит в MVP, потому что CRUD по сохранённому тексту запроса и метаданным достаточно покрывается ACID-транзакциями PostgreSQL и связью с пользователем через FK. В post-MVP таблица расширяется для поддержки CYPHER (поле `query_type TEXT CHECK (query_type IN ('sparql', 'cypher'))`).

```sql
CREATE TABLE user_saved_sparql_queries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    query_type TEXT NOT NULL DEFAULT 'sparql' CHECK (query_type IN ('sparql', 'cypher')),
    query_text TEXT NOT NULL,
    is_public BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now(),
    UNIQUE (user_id, name)
);
```

Запрос принадлежит пользователю и удаляется вместе с аккаунтом. `is_public = true` зарезервирован для post-MVP sharing внутри организации. Если позже появится корпоративная библиотека запросов с тегами, версионированием и ACL, данные можно мигрировать в отдельный `QueryLibraryService` без потери сохранённых запросов.

### REQ-FR-CYPHER-GUI-0001 Режимы работы CYPHER GUI

GUI должен поддерживать три режима работы с CYPHER:
- визуальный конструктор;
- текстовый редактор CYPHER;
- NL-режим (кнопка «Микрофон»).

### REQ-FR-CYPHER-GUI-0002 Визуальный конструктор CYPHER

Пользователь выбирает:
- метку узла;
- тип связи;
- целевой узел или литерал;
- фильтры.

Система генерирует CYPHER-запрос (MATCH/RETURN) на основе выбранных элементов текущей онтологии.

### REQ-FR-CYPHER-GUI-0003 Текстовый редактор CYPHER

Текстовый редактор должен поддерживать:
- подсветку синтаксиса CYPHER;
- автодополнение меток узлов, типов связей и свойств из текущей онтологии;
- синтаксическую валидацию запроса без выполнения.

### REQ-FR-CYPHER-GUI-0004 Выполнение запроса через CYPHER endpoint

Публичный REST endpoint API Gateway `/api/v1/cypher` принимает CYPHER-запросы и выполняет только read-only операции MATCH/RETURN. API Gateway вызывает внутренний gRPC метод Ontology Service для валидации и выполнения CYPHER.

В MVP разрешены только `MATCH` с `RETURN`. `CREATE`, `DELETE`, `SET`, `MERGE` не выполняются в MVP; endpoint должен отклонять их стабильным кодом `CYPHER_OPERATION_NOT_ALLOWED`. Архитектура авторизации должна закладывать role-gated permissions для post-MVP включения write-операций.

Endpoint возвращает результаты в форматах:
- JSON;
- CSV.

### REQ-FR-NL-GUI-0001 NL-режим в Query Builder

В визуальном конструкторе SPARQL и CYPHER присутствует кнопка «Микрофон» для ввода запроса на естественном языке.

При нажатии на кнопку «Микрофон»:
1. Пользователь вводит запрос на естественном языке (NL) в текстовое поле.
2. Система запрашивает явное согласие пользователя (opt-in) на передачу данных LLM-провайдеру с предупреждением о возможной утечке данных онтологии.
3. Если opt-in получен — система отправляет NL-запрос LLM-провайдеру вместе с контекстом (список классов, свойств, меток узлов, типов связей из introspection).
4. LLM-провайдер возвращает сгенерированный SPARQL или CYPHER-запрос.
5. Система подставляет полученный запрос в текстовый редактор для просмотра, редактирования и выполнения пользователем.
6. Факт обращения к внешнему LLM фиксируется в аудит-логе.

### REQ-FR-NL-GUI-0002 Выбор языка запроса в NL-режиме

Если пользователь не указал явно целевой язык, система определяет его автоматически на основе текущего активного конструктора (SPARQL или CYPHER). Пользователь может переключить целевой язык вручную до отправки запроса LLM.

### REQ-FR-MCP-0001 MCP-сервер для запросов к графу знаний

VEDO предоставляет MCP-сервер, реализующий Model Context Protocol. MCP-сервер публикует следующие инструменты:

- `query-sparql` — принимает NL-запрос или готовый SPARQL, преобразует в SPARQL, выполняет SELECT/ASK, возвращает результат.
- `query-cypher` — принимает NL-запрос или готовый CYPHER, преобразует в CYPHER, выполняет MATCH/RETURN, возвращает результат.
- `introspect-ontology` — возвращает схему текущей онтологии (классы, свойства, метки узлов, типы связей) для контекста LLM.

MCP-сервер обрабатывает NL-запрос на стороне VEDO (без отправки данных внешнему LLM-провайдеру), поэтому opt-in пользователя не требуется. Все запросы через MCP подлежат тем же ограничениям безопасности: read-only, LIMIT, timeout, rate limiting, query complexity, аудит.

## Нефункциональные требования (общие для SPARQL и CYPHER)

### REQ-NFR-SEC-0001 Защита от инъекций

Оба endpoint должны использовать параметризованные запросы. Если библиотека или драйвер не поддерживает полноценную параметризацию, значения параметров должны передаваться через строго контролируемый механизм подстановки с экранированием литералов и IRI.

### REQ-NFR-SEC-0002 Принудительный read-only режим

Оба endpoint должны блокировать запросы, изменяющие данные:
- SPARQL: INSERT, DELETE, UPDATE и другие модифицирующие формы. Разрешены только SELECT и ASK.
- CYPHER: CREATE, DELETE, SET, MERGE и другие модифицирующие формы. Разрешён только MATCH с RETURN.

### REQ-NFR-PERF-0001 Тайм-аут выполнения

Предельное время выполнения запроса по умолчанию: 30 секунд, если окружение или контракт не задаёт более строгий лимит.

### REQ-NFR-PERF-0002 Лимит результатов

Максимальное количество записей в ответе по умолчанию: 10 000, если контракт или окружение не задаёт более строгий лимит.

### REQ-NFR-PERF-0003 Обязательный LIMIT

SELECT-запросы (SPARQL) без явного `LIMIT` должны отклоняться, кроме согласованных исключений. MATCH-запросы (CYPHER) без явного `LIMIT` также должны отклоняться.

Визуальные конструкторы добавляют `LIMIT`, если пользователь не указал его явно.

### REQ-NFR-PERF-0004 Ограничение частоты запросов

Endpoint должен ограничивать количество запросов на пользователя. Значение по умолчанию: 10 запросов в минуту, если окружение или контракт не задаёт другой лимит. Rate limiting применяется отдельно к `/api/v1/sparql` и `/api/v1/cypher`.

### REQ-NFR-PERF-0005 Сложность запроса

Перед выполнением система анализирует AST запроса и оценивает ресурсоёмкость. Для SPARQL — по количеству triple patterns, вложенности, типам фильтров, наличию `FILTER NOT EXISTS`. Для CYPHER — по количеству node/relationship patterns, глубине обхода, наличию неограниченных property paths.

Запросы, превышающие порог сложности по умолчанию 1000 баллов, блокируются, если контракт или окружение не задаёт другой порог.

### REQ-NFR-OBS-0001 Логирование и аудит

Все запросы (SPARQL, CYPHER, NL, MCP) должны логироваться с указанием пользователя, времени, текста запроса или redacted summary, количества результатов, времени выполнения и результата security checks.

Секреты, токены и персональные данные не должны попадать в логи.

## Ошибки

### SPARQL
- Пользователь выполняет `INSERT DATA`: система возвращает ошибку, что разрешены только SELECT/ASK.
- Пользователь выполняет `DESCRIBE` или `CONSTRUCT` в MVP: система возвращает `SPARQL_OPERATION_NOT_ALLOWED`.
- Пользователь запрашивает Turtle export для SELECT-результата без RDF-compatible bindings: система возвращает `SPARQL_EXPORT_TURTLE_INCOMPATIBLE` и предлагает CSV/JSON.
- SELECT-запрос без `LIMIT`: система возвращает ошибку обязательного ограничения результатов.
- Запрос превышает query complexity: система не выполняет запрос и объясняет, какие части запроса делают его слишком дорогим.
- Превышен rate limit: система возвращает ошибку лимита запросов и время до повторной попытки.
- Истёк timeout: система прерывает выполнение и возвращает ошибку тайм-аута.

### CYPHER
- Пользователь выполняет `CREATE`, `DELETE`, `SET` или `MERGE`: система возвращает `CYPHER_OPERATION_NOT_ALLOWED`.
- MATCH-запрос без `LIMIT`: система возвращает ошибку обязательного ограничения результатов.
- Запрос превышает query complexity: система не выполняет запрос и объясняет причину.
- Превышен rate limit: система возвращает ошибку лимита запросов и время до повторной попытки.
- Истёк timeout: система прерывает выполнение и возвращает ошибку тайм-аута.

### NL-режим
- Пользователь отклоняет opt-in: NL-запрос не отправляется LLM-провайдеру, система возвращает сообщение о необходимости согласия.
- LLM-провайдер недоступен или возвращает ошибку: система уведомляет пользователя и предлагает повторить позже.
- LLM возвращает запрос, не прошедший синтаксическую валидацию: система уведомляет пользователя и предлагает отредактировать результат вручную.
- LLM возвращает запрос, нарушающий read-only ограничения: система блокирует выполнение и предупреждает пользователя.
- Превышен лимит NL-запросов на пользователя: система возвращает ошибку лимита NL-запросов.

## Открытые вопросы

- Нет открытых вопросов по SPARQL GUI/search.
- CYPHER endpoint: уточнить поддержку `OPTIONAL MATCH` и `WITH` в MVP.
- NL-режим: уточнить, какие LLM-провайдеры поддерживаются в MVP (OpenAI, Anthropic, локальные модели).
- NL-режим: формат контекста онтологии, передаваемого LLM-провайдеру (весь introspection или его часть).
- MCP-сервер: уточнить, какие инструменты публиковать в MVP, и формат их параметров.
