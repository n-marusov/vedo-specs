### UC-browse.search.execute-sparql-query-through-gui: Выполнить SPARQL-запрос через GUI
**Акторы:** Аналитик данных, Инженер знаний  
**Приоритет:** P0 (критичный)  
**Ключевая функция:** F10.1, F10.4, F10.5, F10.6, F10.7 — Полный контур SPARQL-поиска  

**Описание:** Пользователь выполняет семантический SPARQL-поиск по произвольной онтологии через визуальный конструктор или текстовый редактор. Система узнаёт структуру графа через introspection, валидирует запрос, применяет ограничения безопасности и отображает результат в таблице или графе.

**Основной поток (визуальный конструктор):**
1. Пользователь выбирает режим "Визуальный конструктор".
2. Система через introspection загружает список доступных классов текущей онтологии.
3. Пользователь выбирает класс субъекта.
4. Система загружает свойства, применимые к выбранному классу.
5. Пользователь выбирает свойство.
6. Система предлагает возможные значения для объекта: класс или литерал.
7. Пользователь добавляет фильтры, если они нужны.
8. Система генерирует SPARQL-запрос, добавляет `LIMIT`, если он не указан, и проверяет query complexity.
9. Пользователь нажимает "Выполнить".
10. Система отправляет запрос на `/api/v1/sparql`, применяет authentication, authorization, rate limiting и timeout.
11. Система отображает результаты в виде таблицы или графа.
12. Пользователь при необходимости экспортирует результат в CSV, JSON или Turtle.

**Альтернативный поток (текстовый редактор):**
1. Пользователь переключается в режим "Текстовый редактор".
2. Пользователь вводит SPARQL-запрос вручную.
3. Редактор показывает подсветку синтаксиса и автодополнение префиксов, классов и свойств из текущей онтологии.
4. Пользователь нажимает "Валидировать".
5. Система проверяет синтаксис без выполнения запроса.
6. Пользователь нажимает "Выполнить".
7. Система проверяет read-only режим, наличие `LIMIT`, query complexity, rate limit и timeout.
8. Система возвращает результат в выбранном формате.

**Альтернативный поток (ошибка безопасности):**
1. Пользователь пытается выполнить `INSERT DATA`, `DELETE`, `UPDATE` или другой модифицирующий SPARQL-запрос.
2. Система блокирует выполнение.
3. Система возвращает ошибку: разрешены только SELECT/ASK.

**Альтернативные потоки и ошибки:**
- Запрос без `LIMIT` — система отклоняет SELECT-запрос, кроме согласованных исключений.
- Запрос слишком сложный — система блокирует выполнение по query complexity и объясняет причину.
- Превышен rate limit — система возвращает ошибку лимита запросов.
- Истёк timeout — система прерывает выполнение и возвращает ошибку тайм-аута.
- Недостаточно прав — система применяет RBAC и фильтрацию по доступной части онтологии.

**Постусловия:** Пользователь получил результат SPARQL-запроса или явное объяснение, почему запрос не выполнен.
