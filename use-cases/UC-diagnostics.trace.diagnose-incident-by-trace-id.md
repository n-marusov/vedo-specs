### UC-diagnostics.trace.diagnose-incident-by-trace-id: Диагностировать инцидент по `trace_id`
**Актор:** Инженер поддержки  
**Приоритет:** P0 (критичный)  
**Ключевая функция:** F9.5 — Smart diagnostics по trace_id  

**Описание:** Smart diagnostics для сокращения Time-to-Diagnose.
**Основной поток:**
1. Инженер поддержки получает `trace_id` из алерта.
2. Выполняет `vedo-cli diagnose trace --id <trace_id>`.
3. `vedo-cli` загружает trace из Tempo.
4. `vedo-cli` находит ошибочный span, сервис и операцию.
5. `vedo-cli` загружает связанные логи из Loki по `span_id`/`trace_id`.
6. `vedo-cli` загружает метрики из Prometheus за интервал инцидента.
7. `vedo-cli` показывает локализацию проблемы и рекомендации; LLM-анализ включается опционально.
**Альтернативные потоки:**
- А1: Trace не найден — команда показывает retention/backend status и предлагает проверить trace propagation.
- А2: LLM отключён или недоступен — базовая локализация по traces/logs/metrics всё равно выполняется.
**Постусловия:** P0-инцидент локализован за ≤ 10 минут, P1 — за ≤ 30 минут, либо причина невозможности диагностики явно зафиксирована.
