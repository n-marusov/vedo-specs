### UC-git.branches.manage-branch-workflow: Управлять ветками
**Актор:** Инженер знаний  
**Приоритет:** P2 (средний)  
**Ключевая функция:** F3.2, F3.3 — Ветки и слияние  

**Описание:** Создание и слияние веток для параллельной разработки.
**Основной поток:**
1. Пользователь нажимает "Создать ветку"
2. Вводит имя ветки
3. Выбирает базовую ветку (main, dev)
4. Система создаёт ветку в PostgreSQL
5. Пользователь переключается между ветками
**Конфликты (при слиянии):**
1. Пользователь выбирает слияние ветки A в B
2. Система вычисляет diff между base. A, B
3. При конфликтах — показывает UI для разрешения
4. Пользователь выбирает вариант (ours/theirs/manual)
5. Система создаёт merge commit
6. Обновляет целевую ветку
**Альтернативный поток (cherry-pick):**
1. Пользователь выбирает коммит из ветки A
2. Система переносит коммит в текущую ветку
**Постусловия:** Ветка создана/слита
