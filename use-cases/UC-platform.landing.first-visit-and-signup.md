### UC-platform.landing.first-visit-and-signup: Первое знакомство с платформой и регистрация через посадочную страницу
**Акторы:** Неавторизованный посетитель (бизнес-аналитик, учёный, разработчик, инженер знаний, DevOps-инженер)
**Приоритет:** P0 (критичный)
**Ключевая функция:** F0 — Публичный лендинг и витрина демо-онтологий
**Канал:** GUI

**Описание:** Посетитель без учётной записи впервые открывает общедоступную посадочную страницу VEDO Hub, знакомится с платформой через демо-онтологии с наглядным графом связей и завершает регистрацию. От момента открытия страницы до входа в личный кабинет — не более трёх нажатий.

**Основной поток (путь через демо):**
1. Посетитель открывает посадочную страницу — система отображает hero с положением о концепции, витрину демо-проектов и ролевые разделы.
2. Посетитель читает положение о концепции («VEDO Hub — GitHub + Hugging Face для онтологий») — не более 10 секунд.
3. Посетитель нажимает дополнительный призыв к действию «Смотреть демо» — страница прокручивается к витрине VEDO Demos.
4. Посетитель просматривает карточки демо-проектов (Организация, Продукт, Процесс, Учебная программа, Событие) и выбирает наиболее понятный — «Организация».
5. Система открывает страницу просмотра демо-онтологии «Организация» (доступна по идентификатору опубликованного снапшота — UUID) с трёхпанельным просмотрщиком: дерево классов, граф связей (Vue Flow), панель свойств. Авторизация не требуется.
6. Посетитель нажимает на узел «Department» в графе — система подсвечивает связи (`subOrganizationOf`, `hasMember`) и связанные узлы.
7. Посетитель понимает назначение онтологии («это просто схема с классами и связями между ними»).
8. Посетитель возвращается на посадочную страницу, прокручивает к ролевым разделам и видит раздел «Бизнес-аналитик / Не-IT-пользователь».
9. Посетитель нажимает основной призыв к действию «Создать аккаунт бесплатно».
10. Система перенаправляет на страницу входа Keycloak (email + пароль или OAuth-провайдер).
11. Посетитель заполняет регистрационную форму и подтверждает учётную запись.
12. Система выполняет вход и перенаправляет в личный кабинет (`Dashboard`) основного приложения VEDO Hub.
13. Посетитель видит приветственный экран и может начать работу: форкнуть демо-проект (F13.1 Forks), создать новый проект или загрузить документ.

**Основной поток (прямая регистрация без демо):**
1. Посетитель открывает посадочную страницу.
2. Посетитель сразу нажимает основной призыв к действию «Создать аккаунт бесплатно».
3. Система перенаправляет на Keycloak.
4. Посетитель регистрируется и попадает в личный кабинет.

**Альтернативные потоки:**
- А1: Посетитель уже имеет учётную запись — нажимает «Войти» в верхней панели, проходит Keycloak-вход, попадает в личный кабинет (без регистрации).
- А2: Посетитель — учёный/исследователь — переходит по ссылке «Смотреть каталог» из ролевого раздела и просматривает публичные онтологии (в MVP — только VEDO Demos).
- А3: Посетитель — разработчик — переходит по ссылке «API-документация» из ролевого раздела и изучает OpenAPI-спецификацию.
- А4: Посетитель — DevOps-инженер — переходит по ссылке «Документация по развёртыванию» из ролевого раздела.
- А5: Демо-онтология не загрузилась (public-browse-api недоступен) — просмотрщик показывает сообщение «Демо-проект временно недоступен. Пожалуйста, попробуйте позже.» и предлагает вернуться на посадочную страницу или сразу зарегистрироваться.
- А6: Регистрация не удалась (Keycloak недоступен, ошибка сети) — система показывает сообщение об ошибке и предлагает повторить попытку позже.

**Постусловия:**
- Посетитель зарегистрирован в системе VEDO Hub.
- Посетитель аутентифицирован (JWT-токен выпущен).
- Посетитель находится в личном кабинете основного приложения.
- Система зафиксировала источник регистрации: «посадочная страница» (для аналитики воронки).
