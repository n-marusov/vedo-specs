### UC-team.reviews.review-merge-request: Проводить ревью Merge Request
**Актор:** Инженер знаний  
**Приоритет:** P1 (высокий)  
**Ключевая функция:** F3.3 — Слияние (Merge) с ревью-потоком  

**Описание:** Асинхронное ревью изменений через Merge Request между ветками. Совместное редактирование одного узла в реальном времени не поддерживается.
**Основной поток:**
1. Пользователь завершает правки в своей ветке и создаёт Merge Request в целевую ветку.
2. Система строит семантический diff (классы, свойства, индивиды, изменённые атрибуты).
3. Ревьюер открывает Merge Request и проверяет изменения.
4. Ревьюер оставляет замечания или подтверждает изменения.
5. Автор дорабатывает правки и обновляет Merge Request при необходимости.
6. После одобрения система выполняет merge в целевую ветку.
**Альтернативные потоки:**
- А1: Обнаружен конфликт при merge — система помечает MR как конфликтный, автор разрешает конфликт и повторно отправляет на ревью.
- А2: Ревью не пройдено — MR остаётся открытым до внесения исправлений.
**Постусловия:** Изменения либо слиты в целевую ветку после ревью, либо возвращены на доработку.
