# US-org.projects.create: Создание проекта в группе

```gherkin
@US-org.projects.create @UC-org.projects.manage-project-lifecycle @P0 @organization @projects
Feature: US-org.projects.create Создание проекта в группе

  Background:
    Дано пользователь аутентифицирован как "Owner"
    И существует группа "Research Team" с видимостью "Internal"

  Scenario: Owner создаёт приватный проект в выбранной группе
    Когда пользователь переходит на страницу "Projects"
    И нажимает "New project"
    Тогда открывается страница "New project" по адресу "/dashboard/projects/new"
    Когда пользователь выбирает группу "Research Team" из списка доступных групп
    И вводит название проекта "Knowledge Graph"
    И выбирает уровень видимости "Private"
    И нажимает "Create project"
    Тогда создаётся новый проект "Knowledge Graph" в группе "Research Team"
    И проекту присваивается уникальный ontology_id в формате UUID v4
    И пользователь становится Owner созданного проекта
    И отображается Toast-уведомление "Project created successfully"
    И происходит перенаправление в workspace проекта "/project/:id/workspace"
    И проект отображается в списке проектов с человеко-читаемым именем "Knowledge Graph"
    И в списке проектов виден значок видимости Lock (приватная)

  Scenario: Owner выбирает родительскую группу из человеко-читаемого списка
    Когда пользователь переходит на страницу "New project"
    Тогда система загружает список доступных групп
    И отображает группы человеко-читаемыми названиями, не ID
    Когда пользователь выбирает группу "Research Team" из выпадающего списка
    И заполняет название проекта
    И нажимает "Create project"
    Тогда проект создаётся с выбранной родительской группой "Research Team"

  Scenario: Пользователь пытается создать проект с пустым именем
    Когда пользователь находится на странице "New project"
    И выбирает группу из списка
    И оставляет поле названия проекта пустым
    И нажимает "Create project"
    Тогда отображается ошибка валидации "Project name is required"
    И проект не создаётся

  Scenario: Visibility сохраняется и отображается в списке проектов
    Когда пользователь создаёт проект с видимостью "Internal"
    Тогда в строке проекта отображается иконка Shield (внутренняя видимость)
    И при повторном открытии страницы проект имеет видимость "Internal"

  Scenario: После успешного создания показывается Toast и выполняется redirect
    Когда пользователь создаёт проект
    Тогда отображается Toast-уведомление об успехе
    И происходит перенаправление в "/project/:id/workspace"
    И пользователь видит workspace созданного проекта

  Scenario: Backend возвращает ontology_id UUID v4
    Когда пользователь создаёт проект
    Тогда ответ API содержит поле ontology_id в формате UUID v4
    И ontology_id не равен project_id
    И ontology_id парсится валидатором UUID без ошибок

  Scenario: Проект нельзя создать в несуществующей группе
    Когда пользователь переходит на страницу "New project"
    И выбирает несуществующую группу (имитация дефекта)
    Или группа была удалена между загрузкой списка и отправкой формы
    Тогда система возвращает ошибку "Group not found"
    И отображается Toast-уведомление об ошибке
    И проект не создаётся

  Scenario: Проект нельзя сделать более публичным, чем родительская группа
    Дано существует группа "Research Team" с видимостью "Internal"
    Когда пользователь пытается создать проект с видимостью "Public" в группе "Research Team"
    Тогда система отклоняет запрос
    И отображается ошибка "Visibility cannot exceed parent group"
    И проект не создаётся

  Scenario: Пользователь с недостаточными правами не может создать проект в группе
    Дано существует группа "Research Team"
    И пользователь аутентифицирован как "Guest" в группе "Research Team"
    Когда пользователь переходит на страницу "New project"
    И выбирает группу "Research Team"
    И заполняет название проекта
    И нажимает "Create project"
    Тогда система возвращает ошибку "Insufficient role to create project in this group"
    И проект не создаётся
```
