# US-platform.landing.first-visit: Первое знакомство с платформой и регистрация

```gherkin
@US-platform.landing.first-visit @UC-platform.landing.first-visit-and-signup @P0 @landing @onboarding
Feature: US-platform.landing.first-visit Первое знакомство с платформой и регистрация

  Background:
    Given посадочная страница VEDO Hub развёрнута и доступна по адресу "localhost"
    And публичный просмотрщик демо-онтологий работает без авторизации
    And группа "VEDO Demos" содержит пять демо-проектов с visibility=public
    And Keycloak настроен для приёма регистраций (email + пароль, OAuth-провайдеры)

  Scenario: Посетитель регистрируется напрямую через основной призыв к действию
    When посетитель открывает посадочную страницу
    Then страница отображает положение о концепции "VEDO Hub — GitHub + Hugging Face для онтологий"
    And основной призыв к действию "Создать аккаунт бесплатно" виден без прокрутки
    And дополнительный призыв к действию "Смотреть демо" виден без прокрутки
    When посетитель нажимает "Создать аккаунт бесплатно"
    Then посетитель перенаправлен на страницу входа Keycloak
    When посетитель заполняет форму регистрации и подтверждает учётную запись
    Then посетитель аутентифицирован
    And посетитель перенаправлен в личный кабинет Dashboard

  Scenario: Посетитель изучает демо-онтологию перед регистрацией
    When посетитель открывает посадочную страницу
    And посетитель нажимает "Смотреть демо"
    Then страница прокручивается к витрине демо-проектов VEDO Demos
    And посетитель видит карточки пяти демо-проектов
    When посетитель нажимает на карточку демо-проекта "Организация"
    Then открывается страница просмотра демо-онтологии "Организация" (по идентификатору снапшота)
    And дерево классов отображает иерархию: Organization, Department, Employee, Position
    And граф Vue Flow отображает узлы классов и рёбра связей
    And авторизация не запрашивается
    When посетитель нажимает на узел "Department" в графе
    Then система подсвечивает связи "subOrganizationOf" и "hasMember"
    And система подсвечивает узлы, связанные с "Department"
    When посетитель возвращается на посадочную страницу и прокручивает к ролевым разделам
    Then посетитель видит раздел "Бизнес-аналитик / Не-IT-пользователь" первым среди ролей
    When посетитель нажимает "Создать аккаунт бесплатно"
    Then посетитель перенаправлен на Keycloak
    When посетитель регистрируется
    Then посетитель попадает в личный кабинет Dashboard

  Scenario: Посетитель с существующей учётной записью входит через верхнюю панель
    When посетитель открывает посадочную страницу
    And посетитель нажимает "Войти" в верхней панели
    Then посетитель перенаправлен на страницу входа Keycloak
    When посетитель вводит данные существующей учётной записи
    Then посетитель аутентифицирован
    And посетитель перенаправлен в личный кабинет Dashboard

  Scenario: Демо-онтология недоступна — посетитель получает объяснение и альтернативный путь
    Given сервис public-browse-api недоступен
    When посетитель нажимает на карточку демо-проекта
    Then просмотрщик показывает сообщение "Демо-проект временно недоступен. Пожалуйста, попробуйте позже."
    And отображается кнопка "Создать аккаунт" как альтернативный путь

  Scenario: Путь посетителя-учёного через ролевой раздел
    When посетитель открывает посадочную страницу
    And посетитель прокручивает страницу к ролевым разделам
    And посетитель находит раздел "Учёный / Исследователь"
    And посетитель нажимает "Смотреть каталог"
    Then посетитель видит список доступных публичных демо-проектов

  Scenario: Путь посетителя-разработчика через ролевой раздел
    When посетитель открывает посадочную страницу
    And посетитель прокручивает страницу к ролевым разделам
    And посетитель находит раздел "Разработчик / Архитектор"
    And посетитель нажимает "API-документация"
    Then посетитель перенаправлен на страницу OpenAPI-документации
```
